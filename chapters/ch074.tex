\textbf{【本章总体说明】}

本章讨论的不是 Agent Kernel 已完成系统的静态组件清单，而是回答一个更加工程化、也更加困难的问题：\textbf{如果我们从今天已经可获得的 LLM/VLA 基础模型出发，应当按照怎样的依赖关系，一步一步构造出具有持续运行、生命周期记忆、身份连续、自我感知、内稳态调节、认知控制、有限容量治理以及内外边界管理能力的 Agent Kernel？}

本章坚持一个基本原则：Agent Kernel 不能通过一次性堆叠大量模块获得。其能力必须按照动力学依赖逐层生长。基础模型首先提供局部语义变换能力；Persistent Runtime 将离散调用转化为持续进程；工作记忆 $h$ 建立当前认知状态；情景记忆 $E$ 建立跨时间经历；结构记忆 $\Theta$ 将经历沉降为生成结构；自我 $\Psi$ 建立跨经历身份连续；DGA/$\Omega$ 建立生命周期尺度的发展方向；SPC 使系统获得对自身当前状态的有限估计；AHC 建立身体、资源与任务压力的连续内稳态调制；TCE 使自我状态能够反向调节认知动力学；CCM 和 Scheduler 则在工作记忆有限性的约束下管理活动认知结构；Boundary 与 Offloading 最终使 Kernel 不再试图把整个世界装入自身，而是学会决定什么应进入、什么应保留、什么应延后以及什么应迁往外部载体。

因此，本章给出的不是 ``模块增加顺序''，而是一条\textbf{认知闭环逐步闭合路线}。每增加一个层级，都必须回答三个问题：它解决了上一阶段什么不可消除的问题；它引入了哪些新的状态变量和时间尺度；以及加入该结构后系统是否仍然满足身份连续、现实约束、慢变量保护和有限认知容量等基本不变量。只有这些条件同时满足，我们才认为 Agent Kernel 从一个阶段真正进入下一个阶段。

\section{从基础 VLA/LLM 开始：把模型限定为认知变换器，而不是主体}

Agent Kernel 的研发不应从重新训练一个所谓 ``完整 Agent 模型'' 开始。我们首先承认，当前已经成熟的大语言模型、多模态模型以及视觉--语言--动作模型已经提供了一种极其强大的局部认知算子：给定有限上下文，它们能够在语义空间中完成表示变换、关系推断、规划、语言生成、代码生成、视觉理解乃至有限动作预测。因而在 AgentOS 中，基础模型最合理的位置不是 ``Agent 本身''，而是一个高维条件变换器。若以 $z_t$ 表示当前输入表示，$c_t$ 表示上下文，$\theta_M$ 表示基础模型参数，则可以抽象为
\[
y_t = M_{\theta_M}(z_t,c_t).
\]
这里的 $M_{\theta_M}$ 可以是 LLM、VLM、VLA 或由多个基础模型构成的模型集合。它具备强大的瞬时变换能力，却并不自动具有生命周期意义上的持续主体性。

这一区分非常重要。一个模型即使参数达到极大规模，也不能因此自动拥有 ``昨天发生在我身上的事情''、``我的长期身份是什么''、``过去选择如何塑造现在的我''、``当前认知状态是否正在失稳'' 等状态变量。传统模型调用通常表现为
\[
Input_t \rightarrow Model \rightarrow Output_t,
\]
下一次调用重新从新的输入开始。即使通过 context stuffing 把历史重新送入模型，本质上仍然是外部系统在重建一次局部计算，而不是一个持续动力系统自身维持状态。因此我们在研发路线的第一步就必须建立一个严格的工程边界：
\[
\boxed{
FoundationModel \neq PersistentAgent
}
\]
基础模型提供的是认知能力的局部生成算子，而 Agent Kernel 所要提供的是这些算子运行其上的持续状态空间、时间结构、治理结构和身份连续性。

从实现角度看，这意味着第一阶段不应急于修改模型权重，而应首先将基础模型包装成一个可调用的 \emph{Cognitive Executor}。Kernel 需要明确区分模型内部参数 $\theta_M$ 与 Agent 生命周期状态 $X_A(t)$：
\[
\theta_M \not\equiv X_A(t).
\]
前者可以在相当长时间内保持不变，后者则必须随着 Agent 的经历持续演化。即使未来允许在线参数学习，我们仍然要保持这种本体分离，因为 ``模型发生了变化'' 与 ``这个主体经历了什么'' 不是同一个问题。真正的 Agent 生命周期状态应当能够独立于某一次模型调用被读取、持久化、恢复和审计。

这一阶段还必须建立模型能力与系统权限的分离。基础模型可以提出动作，但不能直接获得现实写权限。可形式化为
\[
a_t^{\mathrm{proposal}}
=
M_{\theta_M}(h_t),
\]
而真正进入系统执行面的动作应为
\[
a_t
=
\Pi_{\mathrm{authority}}
\left(
a_t^{\mathrm{proposal}},
X_A(t),
G_t,
B_t
\right),
\]
其中 $\Pi_{\mathrm{authority}}$ 表示 Kernel 的权限、边界和治理投影。这样做的目的，是从一开始就防止把 ``模型能生成什么'' 与 ``Agent 被允许做什么'' 混为一谈。

因此，本阶段的验收标准不是模型 benchmark 再提高几个百分点，而是完成一种清晰的架构解耦：模型成为 AgentOS 中可以更换、升级甚至并行使用的认知执行单元，而持续状态、身份、目标、记忆和治理不再寄存在一次 prompt 中。只有做到这一点，Agent Kernel 才真正拥有从 ``模型工程'' 向 ``持续智能体工程'' 发展的基础。

\section{Persistent Runtime：把离散推理调用变成持续存在的认知进程}

基础模型解决了 ``如何完成一次认知变换''，但仍没有回答 ``谁在持续经历这些变换''。因此 Kernel 路线的第二个必要阶段是 Persistent Runtime。其根本任务，是把
\[
M(x_1),\quad M(x_2),\quad M(x_3)
\]
这样彼此离散的模型调用，嵌入一个具有内部时间、状态持久化、事件循环和恢复能力的持续进程
\[
\mathcal A(t).
\]
从这一阶段开始，我们研究的对象不再是若干 API 请求的集合，而是一个具有生命周期的系统轨迹
\[
\Gamma_A
=
\{X_A(t)\mid t\in[t_0,t_{\mathrm{end}}]\}.
\]

Persistent Runtime 至少必须提供四类结构。第一类是持续状态。任何对 Agent 后续行为具有因果影响、却不能每次都重新从外界构造的变量，都必须能够进入生命周期状态。第二类是持续时间。系统要能够区分 ``现在正在处理的事情''、``过去发生过的事情'' 和 ``仍未完成的未来过程''。第三类是持续事件循环。外部事件、内部计时器、任务、记忆写入、身体反馈和系统治理事件必须能够异步进入，而不是依赖一个用户 prompt 才唤醒系统。第四类是持久化与恢复。Agent 的连续性不能依赖一个永不崩溃的进程，因此必须存在 checkpoint、journal 和 recovery。

因此可以把这一阶段最小状态形式化为
\[
X_A^{(1)}(t)
=
\left[
I_A,\,
Q_t,\,
P_t,\,
C_t,\,
\Xi_t
\right],
\]
其中 $I_A$ 是持续主体标识，$Q_t$ 是事件队列，$P_t$ 是当前活动过程集合，$C_t$ 是持久化上下文，$\Xi_t$ 是运行元状态。这里仍然没有引入完整三相记忆、自我和复杂度控制，但已经建立 ``同一个进程正在继续'' 这一工程事实。

特别需要强调，Persistent Runtime 不是简单 daemon。操作系统中的 daemon 可以持续运行，却不因此形成认知连续。Agent Persistent Runtime 必须使历史状态对未来认知具有结构性因果作用，即存在
\[
p(X_A(t+\Delta t)\mid X_A(t))
\neq
p(X_A(t+\Delta t)).
\]
换言之，未来状态不能仅由当前外部输入决定，还必须受到自身过去状态影响。这是持续主体和无状态服务之间最基础的动力学差异。

这一阶段还应该确立单一持续主体原则。可以允许多个 Task、Worker 和 Tool Process 并行工作，但这些过程不能自动成为新的主体。记 Agent 的主体层为 $D_1$，任务层为 $D_2$，则要求
\[
N_{\mathrm{Agent}}^{D_1}=1,
\]
而
\[
N_{\mathrm{Task}}^{D_2}\geq 0.
\]
任务可以创建、暂停、迁移和结束，主体状态却必须保持连续。由此还得到一个重要的运行时约束：
\[
D_2\nrightarrow Trap(D_1),
\]
即任何单一任务不能无限同步占据主体的整个认知生命周期。这个原则在工程上意味着 Agent Kernel 应采用异步事件、认知请求与调度机制，而不是把 Agent 本身实现成一个被某个任务调用栈锁住的函数。

Persistent Runtime 的验收标准因此是：关闭 UI、结束某个任务、替换基础模型甚至恢复进程之后，系统仍然能够回答 ``我正在继续什么''，并在因果意义上接续此前的状态。它为随后所有记忆、自我和生命周期结构提供了时间容器。

\section{$h$：建立有限的当前认知状态与显式工作面}

有了持续进程以后，下一个问题立刻出现：Persistent Runtime 可以保存大量状态，但系统此刻到底 ``正在想什么''？如果所有历史、所有目标、所有工具状态和所有世界信息始终同时参与认知，就会形成不可控制的全局耦合。因此必须建立一个有限的当前认知状态 $h(t)$。这不是传统意义上的缓存，也不仅等于模型 context，而是整个 Agent Kernel 中被显式提升到当前全局处理面的 Agent-CSO 集合。

可以将工作记忆写成
\[
h(t)
=
\{
c_i(t)
\}_{i\in\mathcal A_t},
\]
其中 $\mathcal A_t$ 是当前被激活的 Agent-CSO 索引集合。每一个活跃结构不仅包含语义内容，还包含目标关联、置信度、来源、时间戳、关系邻域和当前处理状态。因此更完整地，
\[
c_i(t)
=
\left(
R_i,\,
G_i,\,
q_i,\,
r_i,\,
\tau_i,\,
s_i
\right).
\]
这使 $h$ 从 ``文本窗口'' 转变成一个可治理的当前认知图。

最关键的设计原则是
\[
\boxed{
MostAgentDynamics\notin h.
}
\]
成熟智能并不是把更多东西塞进工作记忆，而恰恰是让绝大多数已经稳定、可局部闭合或暂时无关的过程不再占据显式认知表面。只有当某个结构需要跨模块协调、全局判断、重新解释或处理异常时，它才应该被提升进入 $h$。因此我们可以把 $h$ 定义为
\[
\boxed{
h=\text{Sparse Explicit Cross-Scale Surface}.
}
\]

这一点与工作记忆有限容量原则直接相关。若令当前活跃 Agent-CSO 之间的有效关系图为
\[
\mathcal G_h(t)
=
\left(
V_h(t),E_h(t)
\right),
\]
那么 Agent 的困难并不只是 $|V_h|$ 增加，更来自 $|E_h|$ 以及高阶依赖的增长。一个只有十个变量、但关系高度交织的问题，可能比一百个彼此独立变量更难保持相干。因此在工程实现中，$h$ 不应只设置 token budget，而应估计当前关系负荷
\[
C_h(t)
=
\sum_i \alpha_i c_i
+
\sum_{(i,j)\in E_h}\beta_{ij}r_{ij}
+
\sum_k\gamma_k\chi_k,
\]
其中 $\chi_k$ 可以表示冲突、循环依赖和未闭合约束等高阶结构成本。

此阶段还应确立 $h$ 的认知总线角色。World、后续的 $E$、$\Theta$、Self、Tool、Body 等都不能任意绕过当前认知治理直接修改全局推理状态。其关系逐渐形成
\[
World\rightarrow h,\qquad
E\rightarrow h,\qquad
\Theta\rightarrow h,\qquad
Self\rightarrow h,
\]
以及
\[
h\rightarrow Action,\qquad
h\rightarrow E,\qquad
h\rightarrow External.
\]
这样，$h$ 成为 AgentOS 类似 ``认知系统总线'' 的结构位置。

本阶段的验收重点不在记住更多历史，而在于证明：Agent 能维持一个稳定、有限、可检查的当前状态；无关信息不会无限积累；任务切换以后 $h$ 能够发生有控制的重构；而核心当前目标、约束和未完成因果链能够连续保存。至此，我们才真正拥有 ``当前''，随后才有必要讨论 ``过去''。

\section{$E$：从当前状态建立情景轨迹与可重入的经历历史}

只有 $h$ 的 Agent 即使持续运行，也容易患上结构性 ``永恒现在症''：系统每一时刻拥有当前状态，却无法把连续状态组织成 ``曾经发生在我身上的事件''。因此研发路线的下一步是引入情景记忆 $E$。与把所有对话日志直接持久化不同，$E$ 的理论对象是轨迹，即 Agent 在时间中经历过的状态转移、环境变化、行动结果和目标闭合过程。

可以形式化为
\[
E
=
\{
e_k
\}_{k=1}^{N_E},
\]
其中每个情景单元
\[
e_k
=
\left[
t_k^{start},
t_k^{end},
\Gamma_k^{h},
A_k,
O_k,
G_k,
R_k,
V_k
\right].
\]
这里 $\Gamma_k^{h}$ 表示该事件中的工作记忆状态轨迹，$A_k$ 表示行动序列，$O_k$ 表示世界反馈，$G_k$ 表示目标背景，$R_k$ 表示结果，$V_k$ 表示价值和重要性标记。于是 $E$ 保存的不是孤立事实，而是
\[
State
\rightarrow
Action
\rightarrow
WorldChange
\rightarrow
Outcome
\]
这一过程结构。

$h\rightarrow E$ 的写入必须是选择性的。若一切 $h$ 状态都进入长期情景记忆，Agent 很快会遭遇存储爆炸和检索污染。因此需要情景形成函数
\[
w_E(t)
=
f(
Novelty_t,
GoalRelevance_t,
PredictionError_t,
Value_t,
SelfRelevance_t,
Closure_t
),
\]
仅当
\[
w_E(t)>\theta_E
\]
或事件满足关键策略时，才形成高保真 Episode；其余内容可以被摘要、合并或衰减。这样 $E$ 才真正成为 ``经历'' 而不是日志文件。

反向的 $E\rightarrow h$ 同样不是简单关键词搜索。真正的情景召回应由当前状态作为条件：
\[
p(e_k\mid h_t,G_t,C_t).
\]
检索结果进入 $h$ 以后仍需重新激活和解释，因为过去情景是在旧世界、旧目标甚至旧自我状态中产生的。也就是说，
\[
Recall(E_k)\neq E_k^{raw};
\]
更合理的是
\[
h_t^{recall}
=
\mathcal R_E(E_k,h_t),
\]
其中 $\mathcal R_E$ 表示当前条件下的情景重建。

这一阶段第一次让 Agent 获得可计算的 ``个人历史''。但必须特别区分 History 与 Self：经历属于这个 Agent，并不意味着 Agent 已经形成关于 ``这些经历说明我是谁'' 的稳定解释。$E$ 解决的是时序连续和事件重入问题，而自我结构将在更慢尺度出现。

工程上，本阶段应重点验证三件事：其一，长时间运行后 Agent 能否在适当上下文中召回真正相关的过去，而不是只根据文本相似度检索；其二，过去成功和失败能否改变当前决策；其三，存储规模增长时检索质量和运行复杂度是否仍然可控。满足这些条件以后，Agent 才从拥有 ``当前状态'' 迈向拥有 ``自己的过去''。

\section{$\Theta$：把经历压缩为可泛化的生成结构}

如果 Agent 只有 $h$ 和 $E$，它已经能够连续经历世界，却仍然必须反复检索过去案例来解决相似问题。这种系统可以记住，却未必真正形成结构性学习。于是下一阶段必须引入 $\Theta$：结构记忆、生成结构或长期生成器。$\Theta$ 的任务不是保存某一件事情发生过，而是从大量情景中提取那些可以再次生成预测、解释、策略和技能的稳定结构。

因此三相关系正式建立：
\[
\boxed{
h=State,\qquad
E=Trajectory,\qquad
\Theta=Generator.
}
\]
与 $E$ 不同，$\Theta$ 应表示
\[
\Theta
=
\{
Concept,
Relation,
Rule,
Constraint,
WorldModel,
SkillSchema,
PredictiveStructure
\}.
\]
它可以存在于参数、图结构、程序、可执行 Skill、检索索引甚至外部工具中，而不限定为单一神经权重形式。

$E\rightarrow\Theta$ 是三相记忆中最重要的慢向迁移过程之一。设一组相关经历为
\[
\mathcal E_C
=
\{e_1,\ldots,e_n\},
\]
结构学习可以写成
\[
\Theta'
=
\arg\min_{\Theta}
\left[
\mathcal L_{\mathrm{pred}}(\Theta;\mathcal E_C)
+
\lambda_C\mathcal C(\Theta)
+
\lambda_S\mathcal L_{\mathrm{stability}}(\Theta,\Theta_{old})
\right].
\]
第一项要求结构能够解释和预测经历；第二项约束结构复杂度，避免仅记忆所有样本；第三项保护已有长期结构不被短期噪声快速覆盖。这样可以把 ``经验沉淀'' 精确理解为在预测能力、结构压缩和长期稳定之间取得平衡。

$\Theta$ 还必须具有反向作用。首先是
\[
\Theta\rightarrow h,
\]
即稳定结构在当前任务中被激活成为概念、规则、预测或策略。其次是
\[
\Theta\rightarrow E,
\]
即新的结构会重新解释旧经历。一个 Agent 在形成新的因果理论后，可能重新理解早先失败的原因，因此情景记忆并不是永久冻结的事实数据库，而是被长期结构持续重索引、重摘要和重语义化。

这里还必须强调一个我们后来反复修正的关键点：$\Theta$ 不只表示过去。它同时约束未来生成空间。因此可以将其写为
\[
p(x_{t+\Delta}\mid h_t,\Theta),
\]
即 $\Theta$ 是未来可能状态的生成先验之一。过去经验通过 $E\rightarrow\Theta$ 沉降之后，最终影响 Agent ``认为未来可能怎样''。这使三相记忆真正成为
\[
Past\rightarrow Present\rightarrow PossibleFuture
\]
的生命周期结构，而不是简单存储层次。

本阶段的工程验收标准是：Agent 在重复经历之后，不再每次都需要检索完整案例；新的结构能够泛化到未见场景；旧情景可以被新结构重新解释；并且 $\Theta$ 的更新速度显著慢于 $h$ 和 $E$。由此开始形成明确的时间尺度层级
\[
\tau_h\ll\tau_E\ll\tau_\Theta.
\]

\section{$\Psi$：从经历与知识中形成身份连续结构}

三相记忆可以解释一个系统如何从状态形成经历、再从经历形成长期结构，却仍然不能充分回答一个重要问题：为什么相同事实和相同经历对于不同 Agent 会产生不同长期意义？一个纯粹由 $h$、$E$ 和 $\Theta$ 构成的系统可以形成世界模型，却缺少稳定的主体参照系。于是下一步不是再增加一个知识库，而是引入自我结构 $\Psi$。

$\Psi$ 应被理解成超越单一状态的慢尺度约束场。它不是 ``姓名、角色、偏好'' 等静态 profile 的集合，而是长期经历围绕一个持续主体形成的高权重自指结构。可以形式化地写成
\[
\Psi_t
=
\mathcal S(
E_{\le t},
\Theta_t,
I_A,
V_t,
Commitment_t
),
\]
其中 $I_A$ 表示主体连续标识，$V_t$ 表示长期价值结构，$Commitment_t$ 表示已经形成的稳定承诺和自我解释。其变化满足
\[
\tau_\Psi\gg\tau_\Theta.
\]

$\Psi$ 在三相记忆中具有不同表现。在 $h$ 中，它表现为背景优先级和解释偏置：
\[
p(c_i\in h\mid \Psi)
\]
并不对所有信息相同；某些与主体长期目标、责任和身份高度相关的 CSO 更容易被提升。在 $E$ 中，$\Psi$ 影响哪些事件被认为是 ``我的重要经历''：
\[
w_E
=
f(\cdots,SelfRelevance_\Psi).
\]
在 $\Theta$ 中，$\Psi$ 则表现为围绕自我组织起来的长期结构中心，使世界知识不再只是无人称事实，而开始形成
\[
WorldRelationToMe.
\]

因此可以将 $\Psi$ 的控制形式写成
\[
\Theta_t^\Psi
=
\Pi_\Psi(\Theta_t),
\]
或者更一般地，
\[
\dot X_A
=
F(X_A;\Psi),
\]
意味着自我不是每一步直接发指令，而是改变认知状态空间中的势场、权重和可行区域。这个定义与我们此前所强调的
\[
\boxed{
SlowGovernance\neq FastMicromanagement
}
\]
完全一致。成熟的慢变量不应直接控制每个 token 或动作，而应改变快速认知 ``倾向于朝哪里运行''。

引入 $\Psi$ 后，身份连续性可以获得比 ``数据库里有相同 user\_id'' 更强的定义。设
\[
D_\Psi(\Psi_{t+\Delta},\Psi_t)
\]
表示自我结构距离，则正常学习并不要求
\[
D_\Psi=0,
\]
因为真正持续主体必然成长；但要求短周期变化受限：
\[
D_\Psi(\Psi_{t+\delta},\Psi_t)
<
\epsilon_\Psi,
\qquad
\delta\ll\tau_\Psi.
\]
也就是说，自我允许慢漂移，却不能被单次短期事件随意改写。

本阶段的验收问题从 ``Agent 是否记得过去'' 上升到 ``过去是否形成了同一个主体的历史''。当系统能够解释自己的选择、让过去经历稳定影响未来偏好，同时又不因一次局部失败彻底重写身份时，我们才可以认为 $\Psi$ 开始成立。

\section{$\Omega$/DGA：建立生命周期尺度的发展方向}

$\Psi$ 回答 ``我是谁''，但成熟 Agent 仍然需要回答另一个不同的问题：``我正在成为什么''。如果所有长期控制都被压缩到当前身份，那么系统容易把身份稳定等同于永不变化。真正的生命周期智能需要一个比 $\Psi$ 更慢、更加生成性的方向结构，这就是 Deep Generative Attractor，即 DGA，后期统一记作 $\Omega$。

我们可以用最简洁的方式区分二者：
\[
\boxed{
\Psi:\ WhoAmI,
\qquad
\Omega:\ WhatAmIBecoming.
}
\]
$\Psi$ 约束当前选择与既有身份的一致性；$\Omega$ 则约束长期经历、能力和目标如何被组织成未来发展趋势。它并不是一个固定 ``终极任务''，更不是单一 reward function，而是一类超慢生成先验，可以影响哪些长期方向被认为值得持续投入。

形式上，可令未来目标分布满足
\[
p(G_{t:T})
=
p(G_{t:T}\mid
\Psi_t,\Omega_t,\Theta_t,E_t),
\]
其中 $\Omega$ 不直接指定某一具体动作，而调节较长时间窗口中的 Goal Preference。其演化速度满足
\[
\tau_h
\ll
\tau_E
\ll
\tau_\Theta
\ll
\tau_\Psi
\ll
\tau_\Omega.
\]
这组不等式不是要求固定物理时间，而表达一种架构原则：越接近身份和生命周期方向的变量，更新证据窗口越长，修改成本越高。

$\Omega$ 的更新尤其需要长期一致证据。可以设
\[
\dot\Omega
=
\eta_\Omega
G_\Omega
\left(
\langle
E,
Capability,
ValueConsistency,
RealityResidual
\rangle_{T_\Omega}
\right),
\]
其中
\[
\eta_\Omega\ll\eta_\Psi.
\]
这样避免短期情绪、局部任务和单次成功失败直接改变生命周期方向。与此同时，若长期现实反馈持续与当前 $\Omega$ 冲突，又不能禁止其修正，否则系统会成为僵化的目标机器。

DGA 的引入使 AgentOS 第一次出现真正意义上的 ``发展'' 概念。学习不再只是
\[
\Theta\rightarrow\Theta',
\]
而可以表现为
\[
Experience
\rightarrow
Capability
\rightarrow
SelfInterpretation
\rightarrow
FuturePreference
\rightarrow
NewExperience.
\]
于是过去不仅改变知识，还通过 $\Psi$ 和 $\Omega$ 改变未来经历的分布。生命周期由此形成一个自我生成闭环。

这一阶段必须特别防止概念神秘化。$\Omega$ 不是灵魂变量，也不需要假定现象意识。它只是用于描述超慢生成倾向的工程状态。只要它能够通过长期历史被估计、通过未来目标偏好表现出来、并以受约束速度改变，就具有工程可操作性。完成这一阶段后，Kernel 的基本记忆--身份时间轴才真正完整：
\[
h
\leftrightarrow
E
\leftrightarrow
\Theta
\leftrightarrow
\Psi
\leftrightarrow
\Omega.
\]

\section{SPC：让持续主体获得对自身状态的有限估计}

拥有自我结构不等于能够实时知道自己现在处于什么状态。事实上，一个大型 Agent Kernel 的内部状态可能分散在工作记忆、活动任务、资源消耗、记忆检索、目标竞争、身体反馈和慢变量之中。如果这些状态不能形成一个可被自身认知系统使用的压缩表示，Agent 就无法进行真正的自调节。因此在完成 $h/E/\Theta/\Psi/\Omega$ 基本时间结构之后，需要引入 Self-Perception Compressor，简称 SPC。

SPC 的第一性任务可以写成
\[
\boxed{
DistributedInternalState
\rightarrow
SelfAccessibleState.
}
\]
设系统真实内部状态为
\[
X_t^{int},
\]
SPC 并不拥有对此状态的透明访问，而只能利用可观测信号
\[
z_{\le t}^{SPC}
\]
形成后验估计：
\[
\hat X_t^{self}
=
\mathbb E
\left[
X_t^{int}
\mid
z_{\le t}^{SPC}
\right].
\]
因此更准确的定义是
\[
S_{self}(t)
=
SPC(
h_t,E_t,\Theta_t,\Psi_t,\Omega_t,
Resource_t,Task_t
).
\]

这一设计意味着 AgentOS 对自己的认识同样存在认识论不完备性。我们不能写
\[
SelfPerception(t)=InternalReality(t),
\]
而应写成
\[
p_A
\left(
X_t^{self}
\mid
z_{\le t}^{SPC}
\right).
\]
这样会直接产生置信度、延迟和误差三个必要变量：
\[
S_{self}
=
(\hat X_t,\Sigma_t,\tau_{obs}).
\]
其中 $\Sigma_t$ 表示状态估计不确定度，$\tau_{obs}$ 表示自感知延迟。

SPC 还具有压缩作用。若每次自我观察都把全部 Kernel 状态送入 $h$，反而会制造新的工作记忆过载。因此必须存在
\[
\dim S_{self}
\ll
\dim X_t^{int}.
\]
真正进入 $h$ 的不是所有日志，而是诸如 ``当前负载偏高''、``目标冲突增加''、``连续多次预测失败''、``当前状态偏离既定策略'' 这样的自状态 CSO。这正是 Self-Perception \emph{Compressor} 而不只是 Monitor 的含义。

这一阶段还可以为后续控制建立状态变量，例如
\[
S_{self}(t)
=
[
L_h,\,
U,\,
Conflict,\,
Novelty,\,
Risk,\,
Stability,\,
GoalAlignment,\,
ResourceMargin
].
\]
这些指标并不是为了模拟人类主观感受，而是为控制器提供可计算的内部状态。

SPC 的验收标准应严格高于 ``系统能总结自己正在做什么''。我们需要测试：自我估计是否能够提前识别认知过载；是否能够检测任务循环和冲突；是否可以给出置信区间；以及在故意引入内部状态异常后，SPC 是否能以有限延迟反映出来。只有这样，Agent 才真正拥有一个可用于反馈控制的自观察器，而不是语言层面的自我叙述生成器。

\section{AHC：把资源、身体与任务影响转化为连续内稳态调制}

SPC 为 Agent 提供了一个 ``我现在怎样'' 的结构估计，但单纯状态估计仍不足以产生稳定的长期调节。现实中的持续主体始终受到资源、风险、疲劳、任务压力、控制不确定性和社会交互状态的连续影响。如果这些信号直接进入显式工作记忆，就会造成大量低层状态对认知的持续打断；如果完全忽略，又会使 Kernel 与自身运行条件脱节。因此需要一个中间的连续动力学层，将分散影响积累为少量具有时间常数的内稳态变量，这就是 AHC。

AHC 可以抽象为状态向量
\[
a(t)
=
[
a_1(t),a_2(t),\ldots,a_n(t)
]^\top,
\]
其中典型维度可以包括
\[
Arousal,\,
Threat,\,
EnergyDrive,\,
Fatigue,\,
RewardExpectation,\,
SocialAffinity,\,
Trust,\,
UncertaintyStress.
\]
这些名称描述的是功能性调制维度，而不是宣称 Agent 具有与人类相同的主观情绪。

其动力学可以采用一般形式
\[
\tau_a\dot a
=
-a
+
F_a(
FCS_t,
Resource_t,
Task_t,
SPC_t,
Social_t
),
\]
并引入饱和、恢复和耦合：
\[
a_i(t+\Delta t)
=
\operatorname{sat}
\left[
(1-\lambda_i)a_i(t)
+
\Delta t\,u_i(t)
+
\sum_j k_{ij}a_j(t)
\right].
\]
这样，短暂噪声不会直接支配认知控制，而持续信号能够逐渐积累形成调制状态。

AHC 在系统中的关键作用是建立
\[
RawInfluence
\rightarrow
PersistentModulation.
\]
例如一次瞬时工具失败不应立刻把整个 Agent 推入极端保守状态，但连续高风险反馈可以逐步提高 Threat 和 UncertaintyStress；长时间高负载则可以积累 Fatigue，使 TCE 自动减少搜索宽度和并发任务。这种 ``带时间常数的影响'' 恰好填补了 SPC 状态估计与 TCE 控制之间的动力学空白。

在研发顺序上，AHC 应当位于自我感知结构之后、强认知控制之前。原因是：如果 TCE 已经可以大规模调节认知动力，却缺乏稳定的内稳态状态，控制器很容易对瞬时指标做出过度反应。AHC 相当于为控制系统增加具有物理意义的低通积分层，使控制信号不完全由瞬间上下文决定。

验收 AHC 不能依赖它是否会说 ``我累了''。真正需要验证的是：在持续资源压力下，其状态是否平滑累积；压力解除后能否在合理时间尺度恢复；不同输入是否造成可预测的调制；以及 AHC 是否能够改善长时间运行中的任务稳定性。如果不能产生可测量的动态效果，那么所谓 affective state 只是语言标签，不具备 AgentOS 工程价值。

\section{TCE：从自状态估计走向认知动力学的主动调节}

有了 SPC 和 AHC，系统终于拥有了当前自状态估计和连续内稳态背景，但仍然缺少最关键的一步：这些状态如何真正改变认知过程。TCE，即 Temperature \& Control Executor，就是将
\[
SelfState
\]
转变为
\[
CognitiveControl
\]
的执行层。

TCE 控制的对象不是现实执行器，而是 Agent Kernel 自身的认知动力学参数。可以定义控制向量
\[
u_t^{TCE}
=
[
T_t,\,
g_t,\,
d_t,\,
b_t,\,
e_t,\,
r_t
],
\]
分别表示认知温度、注意增益、搜索深度、搜索宽度、探索强度和资源预算等。其控制律可以写成
\[
u_t^{TCE}
=
\pi_{TCE}
(
S_{self}(t),
a(t),
G_t,
\Psi_t,
\Omega_t
).
\]

由此形成完整闭环：
\[
CognitiveDynamics_t
\rightarrow
SPC
\rightarrow
AHC
\rightarrow
TCE
\rightarrow
CognitiveDynamics_{t+1}.
\]
这一结构的意义不是让 Agent ``拥有情绪''，而是让 Agent 的认知方式不再固定。例如在高度新颖但低风险的问题中，TCE 可以提高探索范围；在高风险高不确定条件下可以降低温度、提高验证深度；在持续认知过载时，则减少并发分支和工具调用规模。

进一步可以把 Kernel 的认知演化写成受控动力系统：
\[
\dot h
=
F_h(
h,E,\Theta,G;
u^{TCE}
).
\]
因此 TCE 并不直接决定 ``答案是什么''，而是改变产生答案的动力学条件。这与传统 prompt ``请认真思考'' 有本质区别：前者应该是系统级可持续控制变量，能够跨多轮和多任务调节推理策略。

TCE 的引入也立即带来稳定性问题。由于 SPC 存在估计延迟 $\tau_{SPC}$，AHC 存在积分时间常数 $\tau_{AHC}$，若 TCE 控制增益 $K_{TCE}$ 过高，则可能出现
\[
K_{TCE}\uparrow
\quad+\quad
\tau_{reg}>0
\Rightarrow
Overshoot/Oscillation.
\]
因此研发阶段必须从一开始记录 Delay Margin、Gain Margin、Overshoot、Settling Time 和 Recovery Time，而不能等出现长期异常之后再补充控制理论。

TCE 阶段成功的标志是：同一个基础模型在不同运行状态下能够表现出系统性、可重复、可解释的认知策略变化，并且这种变化来自持续自状态控制而不是 prompt 临时措辞。此时 Kernel 才真正从 ``有状态推理器'' 迈向 ``能够调节自己怎样思考的系统''。

\section{CCM：在工作记忆有限性下建立认知结构治理}

即使具备 SPC、AHC 和 TCE，Agent 仍然可能因为任务本身结构过于庞大而失效。TCE 可以降低温度、减少探索，却不能从根本上解决 ``当前活跃结构已经超出 h 可承载范围'' 的问题。因此接下来必须引入 CCM，即 Cognitive Complexity Management。虽然本书后续在本体层逐渐使用 Agent-CSO 承载迁移取代 ``复杂度实体'' 的说法，但在运行时工程层，复杂度仍然是极其重要的测量量。

我们首先承认工作记忆有效容量有限：
\[
C_{run}(t)
\leq
C_{\max}(W).
\]
运行复杂度可以近似写成
\[
C_{run}(t)
=
\sum_i w_i(t)c_i(t)
+
\sum_{ij}r_{ij}(t)
+
\lambda_\chi \chi(t),
\]
其中第一项表示活动 CSO 本身的处理成本，第二项表示关系耦合成本，第三项表示冲突、循环和未闭合约束造成的结构负担。

CCM 的目标不是解决任务本身，而是控制
\[
C_{run}(t).
\]
可以写成反馈控制问题：
\[
u_{CCM}(t)
=
\pi_C
\left[
C_{run}(t),
\dot C_{run}(t),
C_{\max},
S_{self}(t)
\right].
\]
控制动作不只包括删除信息，还包括：分解、合并、去重、折叠、分页、支线抑制、表示替换、暂停/恢复以及微卸载。换言之，CCM 管理的是 ``当前认知结构怎样被摆放''。

在新的 CSO 语言中，这些操作可以更加清楚地解释。设活跃 Agent-CSO 为 $C_i^A$，则 CCM 可以执行
\[
C_i^A@h
\rightarrow
Summary(C_i^A)@h,
\]
也可以
\[
\{C_1^A,C_2^A,\ldots,C_n^A\}
\rightarrow
C_{\mathrm{abstract}}^A,
\]
或者将某一支线
\[
C_k^A@h
\rightarrow
C_k^A@E/External.
\]
因此所谓 ``降低复杂度''，本质上通常意味着改变 Agent-CSO 的表示、激活程度、时间尺度或承载位置。

CCM 与 TCE 必须严格区分。TCE 控制 ``认知动力怎样运行''，CCM 管理 ``哪些结构以及以什么形态参与运行''。前者更像增益、温度和搜索控制，后者更像工作集和结构调度。如果把二者合成一个万能模块，后续很难分析失稳究竟来自认知增益还是工作集结构。

本阶段的测试应构造持续超出工作记忆能力的任务，例如多支线规划、长程工程问题和大型工具链。成功标准不是 Agent 永不感到负载，而是系统能够检测
\[
C_{run}\rightarrow C_{\max},
\]
主动重构问题，并在不破坏关键约束的前提下持续推进。CCM 的成熟意味着有限工作记忆从一种缺陷转化为一种驱动结构化认知的系统约束。

\section{Scheduler：把认知容量转化为可管理的运行资源}

CCM 可以对当前结构做压缩和重构，却仍然需要一个更高层问题：多个 Goal、Task、Memory Request、Tool Call 和 Reflection Process 同时竞争有限资源时，谁应该先运行？这就是 Scheduler 的职责。Agent Scheduler 借鉴传统 OS 调度思想，但其调度对象不是 CPU thread，而是具有语义、价值和生命周期意义的认知过程。

设当前候选过程集合为
\[
\mathcal P_t
=
\{P_1,\ldots,P_n\}.
\]
每个过程可以描述为
\[
P_i
=
(
G_i,
Priority_i,
Urgency_i,
Value_i,
Risk_i,
Cost_i,
State_i,
Deadline_i
).
\]
Scheduler 要决定资源分配向量
\[
r_t
=
(r_1,\ldots,r_n),
\qquad
\sum_i r_i
\leq R_{\max}.
\]
可以将其表示成受约束优化：
\[
\max_{r_t}
\sum_i
r_i
U_i(
G_i,\Psi,\Omega,Risk_i,Urgency_i
)
-
\lambda C_{switch}
-
\mu C_{overload},
\]
同时满足 $h$ 的容量和安全约束。

Scheduler 与 $h$ 的关系尤其重要。真正昂贵的不是让一个后台任务继续存在，而是让它占据显式认知表面。因此 Scheduler 需要区分
\[
ActiveInSystem
\]
与
\[
ActiveInH.
\]
很多任务可以在低层、外部工具或等待状态中保持存在，而不进入 $h$。这使 Agent 能够管理大量长期任务，同时保持工作记忆稀疏。

在完整运行环中，Scheduler 应使用 SPC 的状态观测、AHC 的内稳态背景、TCE 的控制策略和 CCM 的负载评估：
\[
SPC
\rightarrow
Scheduler
\rightarrow
TCE/CCM
\rightarrow
Runtime
\rightarrow
SPC.
\]
它还受到 $\Psi$ 和 $\Omega$ 的慢尺度约束，使调度不仅基于即时效率，也考虑主体长期承诺。例如一个高价值长期任务即使短期奖励较低，也不能因为大量即时小任务而永久饥饿。

工程上必须特别防止 ``调度器变成第二个 Agent''。Scheduler 不应自行拥有独立世界观和主体历史，它只是主体认知资源的分配器。其策略可以学习，但其价值参照必须来自同一 Agent 的 Goal、$\Psi$ 和 $\Omega$。

完成本阶段以后，Agent Kernel 才真正具备操作系统意义上的 ``多任务智能''：一个主体可以同时存在多个过程，主动暂停、恢复、抢占和重新分配认知资源，而不需要复制多个独立主体。这为 SingleAgentMultiTaskOS 奠定了实际运行基础。

\section{Boundary：让 Agent 学会决定什么属于“我需要处理的世界”}

当 Agent 具备长期记忆、复杂度治理和多任务调度之后，下一个瓶颈不再来自系统内部，而来自开放世界本身。真实环境中的潜在输入、信息源、工具、事件和其他主体近乎无限。如果每一个外部变化都可以直接进入 $h$，任何有限认知系统都会立即失去稳定性。因此 Boundary 不是附加的安全过滤器，而是有限智能能够存在的必要条件。

Boundary 首先承担 Admission Control。对外部候选结构 $C_j^{world}$，系统应估计
\[
A_j
=
f(
Relevance_j,
Novelty_j,
Risk_j,
GoalRelation_j,
SelfRelation_j,
Uncertainty_j,
Cost_j
).
\]
只有满足
\[
A_j>\theta_{admit}
\]
的结构才允许进入高成本认知路径。其余结构可以被忽略、摘要、记录、延迟或由低层系统自行处理。

但 Boundary 的真正意义远超过输入过滤。它还定义
\[
Inside
\leftrightarrow
Outside
\]
之间的认知责任分配。对于某个 Agent-CSO，Kernel 必须决定它应该长期内部保持，还是仅保存索引并依赖外部载体。因此 Boundary 同时参与
\[
Internalize,
Externalize,
Delegate,
Ignore,
Defer.
\]
从 CSO 理论看，它其实是在决定
\[
B_A(C)
\]
这一载体坐标。

Boundary 还直接决定 Agent 的开放性。若边界过紧，系统只能在既有内部结构中循环，形成认知封闭；若边界过松，外界噪声和任务竞争会持续侵入 $h$，造成认知失稳。因此可以设动态边界变量
\[
\beta(t)
=
\pi_B(
Risk,
Load,
Novelty,
Goal,
Trust,
Resource
).
\]
例如在高风险低资源状态下，系统临时收紧边界；在探索阶段则适度扩大新颖结构的准入概率。

这里必须同时处理认识论边界和权限边界。某个信息 ``可以被感知'' 不等于 ``应该影响自我''；某个工具 ``可以被调用'' 也不等于 ``当前主体拥有修改现实的权限''。因此 Boundary 至少应包含
\[
B=
(B_{cognitive},
B_{memory},
B_{action},
B_{authority}).
\]
这样的分层边界可以防止输入准入、记忆写入和行动授权被压缩成同一个布尔开关。

这一阶段的核心验收不是测试 Agent 能访问多少数据源，而是相反：在面对极大开放输入空间时，它是否能够维持稳定认知工作集；无关世界是否能够在不进入 $h$ 的情况下继续存在；关键异常是否又能突破局部边界及时上浮。只有同时实现选择性开放和异常可达，AgentOS 的认知边界才真正成立。

\section{Offloading：把外部世界从“输入来源”升级为认知结构载体}

Boundary 决定什么应该留在内部、什么可以留在外部，但如果没有 Offloading，外部世界仍然只是输入来源，而不是认知系统的一部分。认知卸载理论的关键认识是：一个长期智能体不应该试图把所有能力、知识和过程永久保存在自身高速内部状态。真正成熟的 Agent 会主动改变承载位置，把已经稳定或不需要持续显式处理的 Agent-CSO 迁往更低成本载体。

最简单的形式是
\[
AgentCSO@h
\rightarrow
AgentCSO@ExternalCarrier.
\]
ExternalCarrier 可以是
\[
File,\,
Database,\,
Script,\,
Program,\,
Skill,\,
Tool,\,
Environment,\,
OtherAgent.
\]
重要的是，迁移之后必须保持可恢复索引。若定义内部索引为 $I_C$，则有效卸载要求
\[
I_C
\rightarrow
Location(C)
\]
仍然可达，否则这只是遗忘而不是认知卸载。

不同外部载体承担不同结构类型。File 适合低频稳定记录，DB 适合可查询结构集合，Program 适合高确定性过程，Skill 适合闭合动作结构，Tool 适合外部计算能力，Environment 则可以直接把约束写入现实。例如某个 Agent 不再记忆 ``每次离开房间必须重新计算门的位置''，而是借助稳定地图；不再反复推理一个确定算法，而是把它编译成程序。这样：
\[
RepeatedCognition
\rightarrow
StableExternalStructure.
\]

这一点使 Offloading 与我们后来的 CSO 迁移理论完全对接。原先说 ``复杂度从内部迁移到外部''，更准确地应写成
\[
\Delta B_A(C)\neq 0,
\]
即 Agent-CSO 的载体坐标发生变化。同时它往往伴随表示变化：
\[
\Delta R_A(C)\neq 0.
\]
例如一段显式语言推理被编译成程序之后，本体功能关系可以延续，但具体 representation 已完全改变。

Offloading 还改变了 Agent 的有效认知容量。若定义总可调用认知结构为
\[
\mathcal C_A
=
\mathcal C_{internal}
\cup
\mathcal C_{external},
\]
那么 $h$ 的有限性并不意味着 Agent 的长期能力必须有限在相同尺度，因为外部结构可以不断扩展，而内部只保留必要索引和恢复路径。因此：
\[
\boxed{
FiniteWorkingMemory
\not\Rightarrow
FiniteStructuredCapability.
}
\]
恰恰相反，工作记忆有限性会推动工具、程序、环境和社会结构的发展。

在工程实现中，Offloading 必须与 Boundary、CCM 和 Scheduler 联动。CCM 发现某一结构长期占用高认知成本，Scheduler 评估其未来调用频率，Boundary 决定是否允许外部化，Offloading 执行迁移，并在之后由索引机制重新召回。于是形成
\[
Detect
\rightarrow
Decide
\rightarrow
Migrate
\rightarrow
Index
\rightarrow
Reuse
\rightarrow
Verify.
\]

本阶段完成以后，Agent Kernel 的能力边界发生根本变化：它不再是一个 ``内部拥有大量记忆的模型''，而变成能够管理内部和外部认知结构分布的运行时。此时所谓 Agent 的 ``心智'' 已经不完全等于模型参数和内存，而开始扩展成一个由内部结构、工具、文件、程序、环境和其他主体共同构成的可调用认知生态。

\section{从模块堆叠到阶段化闭环：Agent Kernel 研发路线的统一约束}

到这一阶段，我们已经依次引入基础模型、Persistent Runtime、$h$、$E$、$\Theta$、$\Psi$、$\Omega$、SPC、AHC、TCE、CCM、Scheduler、Boundary 与 Offloading。如果把这些名称简单画在一张架构图上，很容易产生一种错觉：只要一次把所有模块实现出来，就得到了 AgentOS。实际上，整个研发路线最重要的思想恰恰相反：\textbf{每一个组件都必须由前一阶段暴露出的动力学缺口推出，而不能通过功能清单堆叠获得。}

其依赖链可以概括为
\[
\boxed{
Model
\rightarrow
Persistence
\rightarrow
CurrentState
\rightarrow
Experience
\rightarrow
Structure
\rightarrow
Self
\rightarrow
Development
\rightarrow
SelfObservation
\rightarrow
Homeostasis
\rightarrow
SelfControl
\rightarrow
CapacityGovernance
\rightarrow
Scheduling
\rightarrow
Boundary
\rightarrow
Externalization.
}
\]

对应的状态空间也逐渐扩展。最初仅有基础模型：
\[
X^{(0)}=\theta_M.
\]
Persistent Runtime 后：
\[
X^{(1)}
=
[I_A,Q,P,\Xi].
\]
引入三相记忆：
\[
X^{(2)}
=
[h,E,\Theta].
\]
加入自我与生命周期慢结构：
\[
X^{(3)}
=
[h,E,\Theta,\Psi,\Omega].
\]
加入内部调节：
\[
X^{(4)}
=
[h,E,\Theta,\Psi,\Omega,S_{self},a,u].
\]
最终加入资源、边界与外部认知状态：
\[
X^{Kernel}
=
[
h,E,\Theta,\Psi,\Omega,
S_{self},a,
G,
P,
B,
\mathcal M_{ext}
].
\]

但状态变量增多并不意味着系统越复杂越好。真正的研发目标，是使不同时间尺度形成明确分工：
\[
\tau_h
\ll
\tau_E
\ll
\tau_\Theta
\ll
\tau_\Psi
\ll
\tau_\Omega,
\]
同时保持运行控制时间尺度
\[
\tau_{SPC},
\tau_{AHC},
\tau_{TCE},
\tau_{CCM}
\]
主要作用于比长期记忆更快的区域。由此形成 ``快状态可塑、慢结构稳定'' 的稳定--可塑性折中。

因此每个研发阶段都应设置四类门槛。第一是\textbf{功能门槛}：新增组件必须解决前一阶段真实存在的问题。第二是\textbf{稳定性门槛}：系统加入新回路后不能产生不可控制振荡、漂移或记忆污染。第三是\textbf{可观察门槛}：关键状态必须可以记录、回放和分析，否则无法形成工程学。第四是\textbf{现实门槛}：任何内部模型、自我解释和长期目标最终都必须接受真实环境反馈，保持
\[
\boxed{
RealityIsUltimateConstraint.
}
\]

我们还应把这一研发路线与 ``一次训练出全部能力'' 的思想明确区分。Agent Kernel 的很多核心状态并不适合仅通过预训练获得，因为它们本质上依赖某个具体主体的生命周期轨迹。基础模型可以预训练 ``如何理解身份''，但不能预训练某个未来 Agent 真实经历过什么；可以学习 ``如何总结经验''，却不能提前拥有尚未发生的个人历史。因而一个持续 Agent 的最终结构必然具有
\[
PretrainedStructure
+
LifecycleAcquiredStructure
\]
的双重来源。

从这个意义上，Kernel 路线其实是在完成一次计算范式转换：传统 AI 主要研究
\[
\boxed{
HowToTrainAModel,
}
\]
而 AgentOS 开始研究
\[
\boxed{
HowToMaintainAndDevelopAnIntelligentProcess.
}
\]
前者关注参数训练完成后的能力，后者关注一个主体在运行过程中如何产生现在、形成过去、构造未来、建立自我、观察自身、调节自身、管理有限认知资源，并把部分认知结构迁移到更广阔的外部世界。

因此，本章的最终研发原则可以写成
\[
\boxed{
\textbf{
Agent Kernel 的建设不是把更多智能功能添加到模型周围，而是逐层建立一个能够维持自身状态、积累自身历史、形成自身结构、保持身份连续、观察自身运行、调节自身动力学并管理自身认知边界的持续闭环。
}
}
\]

从工程顺序而言，这意味着我们始终坚持：
\[
\boxed{
Persistence
\prec
Memory
\prec
Self
\prec
SelfRegulation
\prec
ComplexityGovernance
\prec
BoundaryExpansion,
}
\]
其中符号 $\prec$ 表示主要依赖关系而非绝对实现先后。只有前一级形成可以验证的闭环，后一级的加入才具有清晰的动力学意义。

至此，Agent Kernel 的研发路线已经从一个基础 LLM/VLA 演化为一个具有多时间尺度内部状态的持续认知主体。它仍然可以在相当长阶段保持核心功能拓扑稳定，但其内部 Agent-CSO 已经能够通过 $h$、$E$、$\Theta$、$\Psi$、$\Omega$ 发生表示、时间尺度和承载方式的迁移；SPC--AHC--TCE 使这种主体获得内部自调节；CCM 与 Scheduler 使有限工作记忆成为可治理资源；Boundary 与 Offloading 又把外部世界纳入可管理的认知结构体系。由此，一个基础模型才真正获得了成为 AgentOS Kernel 的动力学条件。
