\chapter{Scheduler：认知资源的调度}
\label{chap:scheduler}

\begin{chapterintro}
\textbf{本章总体说明}

本章确立 AgentOS 中 Scheduler 的理论位置：Scheduler 不是一个普通的任务队列，也不是传统操作系统调度器在认知系统中的简单翻版，而是连接有限工作记忆、目标体系、记忆系统、工具系统、认知控制系统与长期主体连续性的\textbf{离散认知资源分配器}。前文已经建立三个必要前提：第一，工作记忆 $h(t)$ 所能够稳定承载的有效关系结构存在有限上界；第二，SPC 能够对当前认知状态、负载、冲突、不确定性和运行相态形成不完全但持续更新的状态估计；第三，TCE 与 CCM 分别承担认知动力学调制和运行结构负载治理。由此产生一个不可回避的问题：即使系统已经能够知道“自己目前有多忙”，并且能够压缩、折叠或者降低局部认知负担，它仍然必须回答\textbf{谁现在获得计算、注意、工作记忆、记忆召回以及工具访问权}。

Scheduler 正是这一问题的回答者。本章将其形式化为一个受容量、安全、身份连续性、时间约束和长期价值结构共同约束的在线资源配置过程。它不直接完成推理，也不直接判断世界真伪，而是在多个竞争认知进程之间持续建立一个随时间变化的可执行秩序。Scheduler 的最终目标不是使每个任务都最快完成，而是维持整个持续智能体在有限资源条件下的\textbf{可运行性、响应性、连续性与长期有效性}。从这个意义上说，Scheduler 所调度的并不只是计算时间，而是智能体在每一个时刻“允许什么成为现在”的权利。
\end{chapterintro}

\section{从有限工作记忆到认知调度问题}

我们已经知道，持续智能系统不可能把当前所有可能相关的信息、目标、任务、推理支线、身体状态、记忆内容和工具返回结果同时维持在显式工作空间中。若以 $h(t)$ 表示当前工作记忆状态，那么其有限性并不仅表现为一个简单的存储容量约束，而表现为能够同时保持相干关系的结构上界。早期形式可以写为
\[
C_{\mathrm{run}}(t)\leq C_{\max}(W_h),
\]
其中 $W_h$ 表示工作记忆可用容量，$C_{\mathrm{run}}$ 表示当前实际运行的认知结构负载。随着 CSO 理论的形成，我们可以进一步把这一条件重写为一个更具结构意义的约束。设当前进入显式认知面的 Agent-CSO 集合为
\[
\mathcal A_h(t)=\{c_1,c_2,\ldots,c_n\},
\]
每一个 Agent-CSO $c_i$ 占据有效认知资源
\[
w_i=w(c_i,\mathcal R_i,\mathcal D_i),
\]
其中 $\mathcal R_i$ 表示该结构与当前其他结构的关系耦合，$\mathcal D_i$ 表示其当前处理深度。于是工作记忆容量条件应更加接近
\[
\sum_{c_i\in\mathcal A_h(t)}w_i
+
\sum_{i\neq j}\chi(c_i,c_j)
\leq W_h,
\]
其中 $\chi(c_i,c_j)$ 描述多个 Agent-CSO 同时存在时额外产生的关系维护成本。这个修正十分重要，因为十个彼此独立的简单对象和十个存在密集相互约束的对象，对工作记忆造成的负担显然不是同一数量级。

问题由此从“能不能存进去”转变成“哪些结构值得在当前时刻占据有限的显式认知面”。如果一个 Agent 同时具有若干目标
\[
\mathcal G_t=\{G_1,G_2,\ldots,G_m\},
\]
又存在若干运行中的认知进程
\[
\mathcal P_t=\{P_1,P_2,\ldots,P_n\},
\]
那么任何时刻都必须从中选择一个有限活动子集
\[
\mathcal P_t^{\mathrm{active}}\subseteq\mathcal P_t.
\]
这一选择不能完全依靠任务创建顺序，也不能简单使用固定优先级。一个刚刚出现的安全相关异常可能比已经执行数小时的长期规划更加紧迫；一个短期收益较低但与身份连续性高度相关的任务，又可能比局部高收益任务具有更高长期价值；一个工具任务虽然已经启动，却可能正在等待外部返回，此时继续为它分配高强度工作记忆没有意义。

因此持续智能必然产生调度问题。其本质可以概括为
\[
\boxed{
\text{有限显式认知资源}
+
\text{并发认知需求}
\Rightarrow
\text{认知调度}
}
\]
如果不存在 Scheduler，系统表面上仍然可以拥有记忆、工具和推理能力，但这些能力之间将缺少统一的时间秩序。最终可能出现三类典型退化。第一类是\textbf{认知拥塞}：过多目标同时进入 $h(t)$，使关系结构失去相干性；第二类是\textbf{认知饥饿}：长期重要但短期不紧迫的结构永久得不到资源；第三类是\textbf{认知颠簸}：系统不断在多个任务之间来回切换，切换本身耗尽了可用资源。这三个问题共同说明，Scheduler 不是性能优化的附加组件，而是有限认知系统得以长期存在的结构性条件。

在传统计算机操作系统中，Scheduler 的核心问题通常是 CPU 时间片如何分配，而 AgentOS 面临的资源集合明显更加异质。我们至少必须同时处理
\[
\mathcal R=
\{
R_h,
R_{\mathrm{att}},
R_{\mathrm{compute}},
R_{\mathrm{memory}},
R_{\mathrm{tool}},
R_{\mathrm{action}}
\},
\]
它们分别代表工作记忆空间、注意资源、推理计算预算、记忆召回带宽、工具访问预算以及行动控制机会。不同认知进程对这些资源的需求比例不同。纯内部反思主要消耗 $R_h$ 和 $R_{\mathrm{compute}}$；环境操作可能同时需要 $R_h$、$R_{\mathrm{tool}}$ 和 $R_{\mathrm{action}}$；长期经验整理则主要竞争 $R_{\mathrm{memory}}$ 与慢尺度计算资源。因此 AgentOS 的调度从一开始就是一个多资源、多时间尺度、多目标约束问题，而不能被压缩成单一 CPU 队列。

\section{Scheduler 的本体位置：调度什么，而不是思考什么}

为了避免将 Scheduler 写成一个无所不能的“中央大脑”，我们需要首先限定其本体位置。Scheduler 不负责理解一个 Agent-CSO 的语义内容本身，也不负责生成最终行动。它的核心对象是\textbf{认知进程的执行权与资源占用关系}。因此可以把任一待调度认知进程表示为
\[
P_i=
(
G_i,
\mathcal C_i,
s_i,
r_i,
d_i,
u_i,
q_i,
\ell_i,
\eta_i
),
\]
其中 $G_i$ 是该进程所属目标或目标集合，$\mathcal C_i$ 是其当前携带的 Agent-CSO 集合，$s_i$ 为执行状态，$r_i$ 为资源需求向量，$d_i$ 为截止或时间敏感度，$u_i$ 为预期效用，$q_i$ 为风险或关键性，$\ell_i$ 为上下文恢复成本，$\eta_i$ 为状态估计置信度。

Scheduler 输出的不是任务答案，而是资源配置向量
\[
a_i(t)=
\left[
a_i^h,
a_i^{att},
a_i^{cmp},
a_i^{mem},
a_i^{tool},
a_i^{act}
\right],
\]
并满足
\[
0\leq a_i^k\leq 1,
\]
以及总体资源约束
\[
\sum_i a_i^k(t)\leq R_k(t).
\]
这里的 $k$ 遍历工作记忆、注意、计算、记忆、工具和行动等不同资源类型。在某些情况下，$a_i^k$ 可以是连续比例；在另一些情况下，例如某个独占执行器或特定工具锁，它必须取离散值
\[
a_i^k\in\{0,1\}.
\]
因此 Scheduler 从一开始就是混合离散--连续资源分配系统。

为了保持概念清晰，我们可以给 Scheduler 一个较为严格的定义：
\[
\boxed{
Scheduler:
(\widehat X_t,\mathcal P_t,\mathcal G_t,\mathcal R_t)
\mapsto
\mathcal A_t
}
\]
其中 $\widehat X_t$ 是由 SPC 等状态估计机制提供的当前系统估计，$\mathcal P_t$ 是待调度进程集合，$\mathcal G_t$ 是目标结构，$\mathcal R_t$ 是当前可用资源，而 $\mathcal A_t$ 是下一控制窗口的资源分配和执行策略。

这个定义有一个十分重要的含义：Scheduler 调度的是\textbf{认知过程}，而不是 CSO 本体本身。CSO 可以长期存在于 $E$、$\Theta$ 或外部载体中，即使当前没有任何 Scheduler 资源分配给它。只有当某个 CSO 被激活、召回、参与决策或者进入特定任务时，它才通过某个认知进程取得运行资源。由此必须区分
\[
\boxed{
Existence\neq Activation\neq Scheduling
}
\]
一个结构可以存在而未激活，可以激活但仅处于低优先级后台状态，也可以被 Scheduler 提升为当前显式处理对象。

这也说明为什么 Scheduler 不是 Self。长期自我结构 $\Psi$ 可以影响 Scheduler 的优先级函数，但 Scheduler 本身只是一个运行机制。类似地，Goal 不是 Scheduler：目标定义“为什么值得做”，Scheduler 负责“什么时候做以及分配多少资源”。如果把二者混在一起，系统会失去层级分工，任何临时资源争夺都可能反过来改写长期目标。AgentOS 必须保持
\[
\boxed{
Value/Goal\rightarrow SchedulingConstraint,
\qquad
Scheduler\nrightarrow UltimateValueDefinition.
}
\]

从时间尺度上看，Scheduler 处在工作记忆动态与长期结构之间的中快尺度。它必须快于绝大多数任务生命周期，否则无法响应变化；但又不应该像最底层身体控制器那样在毫秒尺度重新规划整个认知资源分配。因此可以粗略写为
\[
\tau_{\mathrm{body}}
\ll
\tau_{\mathrm{sched}}
\lesssim
\tau_h
\ll
\tau_E.
\]
在纯数字 Agent 中，$\tau_{\mathrm{sched}}$ 可以明显缩短，但逻辑关系仍然成立：Scheduler 面向“当前认知周期”，而不是底层伺服环或生命周期级价值演化。

因此，Scheduler 在 AgentOS 中最准确的位置并不是“中央决策器”，而是
\begin{statementbox}
有限认知资源的时序治理层
\end{statementbox}
它决定什么在当前时刻成为显式认知事件，什么保持后台，什么暂停，什么等待，什么被重新提升，以及什么必须让出资源。

\section{Scheduler、SPC、TCE 与 CCM 的职责分离}

AgentOS 的运行控制系统包含多个相互作用但不能互相替代的组件，其中最容易混淆的是 SPC、TCE、CCM 与 Scheduler。若不在理论层面完成职责分离，工程实现很容易形成一个巨大而不可解释的控制模块。我们因此需要把四者明确写成四种不同的算子。

SPC 首先承担状态估计：
\[
\widehat X_t
=
\mathcal O_{\mathrm{SPC}}
(
h_t,
E_t,
\Theta_t,
\Psi_t,
x_t^{body},
\ldots
).
\]
它回答的是：
\begin{statementbox}
系统现在可能处于什么状态？
\end{statementbox}
SPC 的输出包含负载、冲突、不确定性、相态、目标竞争、循环风险和身体资源等估计，但它原则上不直接决定哪个任务必须运行。

TCE 则产生连续认知控制信号：
\[
u_t
=
\mathcal U_{\mathrm{TCE}}
(
\widehat X_t,
\Psi,
G_t
),
\]
它调节认知温度、探索强度、搜索深度、注意范围、控制增益、节奏和保守程度。它回答的是：
\begin{statementbox}
当前认知过程应该以怎样的动力学方式运行？
\end{statementbox}

CCM 面向结构负载治理。设一个待执行任务当前表现为结构
\[
\mathcal C_i,
\]
CCM 可以产生
\[
\widetilde{\mathcal C}_i
=
\mathcal T_{\mathrm{CCM}}(\mathcal C_i),
\]
其中 $\mathcal T_{\mathrm{CCM}}$ 可以是压缩、折叠、分解、支线抑制、表示重构、暂停或者微卸载。它回答的是：
\begin{statementbox}
怎样让当前认知结构变得可处理？
\end{statementbox}

Scheduler 最后根据前三者的结果决定
\[
\mathcal A_t
=
\mathcal S(
\widehat X_t,
u_t,
\widetilde{\mathcal P}_t,
\mathcal R_t
),
\]
回答：
\begin{statementbox}
有限资源现在应该分给谁？
\end{statementbox}

于是四者形成非常清晰的运行时闭环：
\[
\boxed{
SPC
\rightarrow
Scheduler
\rightarrow
TCE/CCM
\rightarrow
CognitiveDynamics
\rightarrow
SPC
}
\]
这里的箭头并不表示严格单向调用关系。实际上 Scheduler 在进行资源决策时会使用 TCE 当前给出的全局控制策略，同时可能要求 CCM 对某个进程先进行压缩后再重新评估；TCE 也会依据 Scheduler 当前承载任务的类型修改认知温度。因此更准确地说，这四者构成一个耦合的控制子系统，只是各自的控制变量不同。

我们可以利用一个简单例子理解这种区分。设 Agent 正在执行复杂规划任务 $P_1$，同时收到新的环境事件 $P_2$。SPC 首先发现 $P_2$ 具有高异常度，同时当前 $h$ 已接近容量上限。Scheduler 此时并不能仅凭“异常高”立即把两个任务同时放入 $h$，因为这可能导致系统失稳。于是它可以请求 CCM 将 $P_1$ 当前工作状态压缩成一个恢复检查点
\[
P_1\rightarrow Checkpoint(P_1),
\]
随后暂停 $P_1$，释放部分 $R_h$；与此同时，TCE 降低探索温度并提高风险敏感增益，使新进入的 $P_2$ 在更加保守的认知动态下获得资源。整个过程不是任何一个单独模块能够完成的。

因此必须坚持：
\[
\boxed{
SPC\neq Scheduler\neq TCE\neq CCM.
}
\]
四者分别对应
\[
Observation,\quad
Allocation,\quad
Modulation,\quad
LoadTransformation.
\]
这一区分也具有很强的控制理论意义。若状态观察器直接兼任资源调度器，观察偏差就会立即转化成执行偏差；若 TCE 同时承担任务选择，高增益认知控制可能导致目标切换振荡；若 CCM 同时决定优先级，则“容易压缩的任务”可能被错误地当成“更值得执行的任务”。模块分离并不意味着彼此隔离，而是使不同类型的错误能够被定位和约束。

从系统理论看，这也是 AgentOS 从大模型 Prompt 编排走向真正运行时架构的关键一步：我们不再把所有问题交给一次语言模型推理，而是把“状态估计”“认知动力控制”“结构负载治理”和“资源调度”分别建模，并通过显式状态和反馈闭环协调。这正是持续智能必须具备的运行结构。

\section{多资源认知调度的形式化目标}

传统任务调度常以最小平均等待时间、最大吞吐量或满足截止时间为主要目标。然而持续 Agent 的目标函数明显更加复杂，因为短期效率并不是唯一标准。一个 Agent 可以通过永久忽略长期身份相关任务获得极高短期吞吐量，但这会破坏主体连续性；也可以通过让每个紧急事件抢占所有资源获得极高即时响应性，却陷入永远不能完成长期工作的“认知中断风暴”。因此 AgentOS Scheduler 必须在效率、风险、目标价值、持续性和切换成本之间取得动态平衡。

设在调度窗口 $[t,t+H]$ 内，进程 $P_i$ 获得资源分配 $a_i(\tau)$。可以定义一个概念性的滚动目标：
\[
\max_{\mathcal A}
\int_t^{t+H}
\left[
\sum_i
V_i(\tau)a_i(\tau)
-
\lambda_C C_i(\tau)
-
\lambda_R R_i(\tau)
-
\lambda_S S_i(\tau)
-
\lambda_D D_i(\tau)
\right]d\tau,
\]
其中 $V_i$ 表示任务对当前目标体系的预期价值，$C_i$ 表示资源成本，$R_i$ 表示风险，$S_i$ 表示切换代价，$D_i$ 表示延迟或长期饥饿损失。这里并不要求工程实现真的实时求解连续最优控制问题，它首先是一个理论框架，用来说明 Scheduler 的优先级不可能被压缩成单一标量“priority”。

为了获得更可实现的近似，我们可以为每个进程定义动态调度势能：
\[
\Pi_i(t)
=
\alpha_g G_i
+
\alpha_u U_i
+
\alpha_r R_i
+
\alpha_n N_i
+
\alpha_p P_i
+
\alpha_v V_i
+
\alpha_d D_i
-
\beta_c C_i
-
\beta_s S_i.
\]
这里：
\begin{itemize}
\item $G_i$ 表示与当前显式目标的相关度；
\item $U_i$ 表示时间紧迫性；
\item $R_i$ 表示风险或安全重要性；
\item $N_i$ 表示新颖性和异常度；
\item $P_i$ 表示该问题的持续性，即是否反复出现而尚未闭合；
\item $V_i$ 表示与 $\Psi$、长期价值以及当前 Goal hierarchy 的一致程度；
\item $D_i$ 表示等待时间累积产生的抗饥饿权重；
\item $C_i$ 表示资源需求；
\item $S_i$ 表示切换到该任务所需的上下文恢复成本。
\end{itemize}

动态优先级由
\[
Priority_i(t)=\sigma(\Pi_i(t))
\]
产生，其中 $\sigma$ 可以是归一化函数，也可以结合分层阈值。这里最值得强调的是 $D_i$。若 Scheduler 只比较即时效用和紧迫性，那么短期事件会永久压制长期任务。为避免这一点，可以令
\[
D_i(t)=\gamma_i\Delta t_i,
\]
其中 $\Delta t_i$ 是该任务持续等待时间。只要任务仍然有效，其优先级就会随等待逐步提升，从而形成认知系统中的 aging 机制。

但优先级仍然不能直接决定是否进入 $h$，因为 Scheduler 还必须满足硬约束：
\[
\sum_i z_i w_i\leq W_h,
\]
\[
\sum_i a_i^{cmp}\leq R_{\mathrm{compute}},
\]
\[
\sum_i a_i^{tool}\leq R_{\mathrm{tool}},
\]
以及安全、权限和主体连续性约束
\[
\mathcal A_t\in\Gamma_{\mathrm{safe}}\cap\Gamma_{\mathrm{identity}}.
\]
其中 $z_i\in\{0,1\}$ 表示进程是否被允许进入显式认知表面。这样，Scheduler 的问题具有典型的 constrained optimization 特征。

更进一步，对于持续 Agent，我们还必须考虑预期信息增益。某个任务当前并不直接产生外部收益，但可能显著降低未来决策不确定性。因此可增加
\[
I_i
=
\mathbb E[
H(B_t)-H(B_{t+1})
],
\]
其中 $B_t$ 表示当前 belief state，$H$ 表示不确定性度量。由此，一个高信息增益的观测、记忆检索或者工具调用可以暂时获得高调度权，即使其即时行为价值较低。这使 AgentOS Scheduler 不只是“完成任务”的执行调度器，还能调度“为了知道下一步该做什么而进行的认知活动”。

所以 Scheduler 的真正优化目标不是
\[
\max Throughput,
\]
而更接近
\[
\boxed{
\max
\left(
GoalProgress
+
InformationGain
+
Continuity
+
Safety
-
CognitiveCost
-
SwitchingCost
\right).
}
\]
这也解释了为什么一个成熟 Agent 的调度策略必须随着主体的发展而改变：同样的计算预算，在不同 $\Psi$、不同目标结构和不同生活阶段下，最优资源配置并不相同。

\section{Goal、Task 与认知进程的层级调度}

持续 Agent 的任务体系不能简单建成一个平面队列。我们需要区分 Goal、Task 与 Cognitive Process 三个层次。Goal 表示未来状态的约束或价值方向，Task 是为了推进 Goal 而形成的可管理工作单元，Cognitive Process 则是实际占用资源执行某种推理、观察、记忆、规划或者工具交互的运行实体。三者可表示为
\[
G
\rightarrow
\{T_1,\ldots,T_m\}
\rightarrow
\{P_1,\ldots,P_n\}.
\]
一个 Goal 可以产生多个 Task，一个 Task 又可能动态生成多个认知进程；相反，某一认知进程也可能同时服务多个 Goal。例如建立一个环境地图既可能服务当前导航，也可能服务未来安全目标。

因此 Scheduler 不能直接使用简单的 Goal priority。需要把目标价值沿层级向下传播：
\[
V(P_i)
=
\sum_{G_j\in Ancestor(P_i)}
\omega_{ij}V(G_j),
\]
其中 $\omega_{ij}$ 表示认知进程 $P_i$ 对目标 $G_j$ 的当前贡献估计。该贡献并非固定，随着环境和任务状态变化可以重新估计。

这里需要一个重要原则：
\[
\boxed{
GoalPriority\neq ProcessPriority.
}
\]
一个长期高度重要的 Goal 可能暂时没有任何需要显式运行的进程；相反，一个价值较低的维护任务可能因为时间窗口即将关闭而需要立即执行。Scheduler 因此管理的是“Goal 对当前执行机会的投影”，而不是直接把长期价值大小转换成 CPU 时间。

为了避免大型 Goal 永久占据认知核心，可以引入预算机制。对目标 $G_j$ 定义认知预算
\[
B_j(t)=
[
B_j^h,
B_j^{cmp},
B_j^{tool},
B_j^{time}
].
\]
目标内部的任务只能在预算范围内竞争资源。如果某一 Goal 不断产生新的支线，CCM 可以折叠其内部结构，而 Scheduler 可以限制其总资源份额。这一机制能够防止我们此前讨论过的“认知任务自膨胀”：任务执行过程中不断发现更多相关问题，最终把整个 Agent 的认知空间吞噬。

与此同时，Goal 层必须允许抢占，但抢占应有结构条件。设当前任务 $T_i$ 正在运行，新任务 $T_j$ 到达。只有当
\[
\Pi_j-\Pi_i
>
\theta_{\mathrm{preempt}}
+
C_{\mathrm{switch}}(i\rightarrow j)
\]
时，Scheduler 才执行强抢占。这里加入切换成本十分重要。如果优先级差稍有变化就立即切换，那么系统会产生“调度振荡”。阈值 $\theta_{\mathrm{preempt}}$ 形成迟滞，使任务获得一定的执行连续性。

对于不可中断的认知过程，还应允许临界区：
\[
P_i\in\mathcal P_{\mathrm{atomic}}
\Rightarrow
Preempt(P_i)=False
\]
直到某个安全检查点。这里的“atomic”不是指整个推理任务不可打断，而是指某些短暂的结构转换必须完整完成，例如一次记忆事务写入、一个工具提交过程或者某种状态迁移。如果在中途暂停，恢复成本可能高于继续完成。

如此一来，AgentOS 不再表现为“一个模型不断接受 Prompt”，而更像一个真正的持续认知运行时：Goal 提供方向，Task 建立中层工作结构，Process 获得实际资源，而 Scheduler 维持三者之间的时间秩序。一个长期主体能够同时“拥有”许多目标，却只有极少数目标在某一个时刻真正占据当前显式认知面。这正是有限智能能够处理开放世界的必要条件。

\section{注意力调度与工作记忆准入}

如果说 CPU 时间是传统操作系统最稀缺的资源之一，那么对于 AgentOS 来说，更关键的稀缺资源往往是\textbf{进入 $h(t)$ 的资格}。因为只要某个结构进入工作记忆，它就不仅消耗存储位置，还会改变当前关系网络、注意分布和认知动力学。因此工作记忆准入必须成为 Scheduler 的核心职责之一。

设候选 Agent-CSO 集合为
\[
\mathcal C_t^{cand}
=
\{
c_1,\ldots,c_N
\}.
\]
每个候选结构都具有准入评分
\[
A(c_i)
=
f(
Rel_i,
Urg_i,
Risk_i,
Novel_i,
Residual_i,
Value_i,
InfoGain_i,
Cost_i
).
\]
然而准入并不是简单地选择评分最高的前 $K$ 个对象，因为对象之间存在关系结构。假设两个单独评分一般的 CSO
\[
c_i,c_j
\]
共同构成关键因果关系，那么联合价值
\[
A(c_i,c_j)
\]
可能远大于二者分别的评分。因此理想 Scheduler 实际处理的是一个带结构相互作用的选择问题：
\[
\max_{\mathcal S\subseteq\mathcal C_t^{cand}}
\left[
\sum_{c_i\in\mathcal S}A(c_i)
+
\sum_{i,j\in\mathcal S}R(c_i,c_j)
\right]
\]
满足
\[
C(\mathcal S)\leq W_h.
\]
这里 $R(c_i,c_j)$ 表示关系协同价值，而 $C(\mathcal S)$ 表示整个候选结构网络对工作记忆产生的真实负载。

这说明注意调度与工作记忆调度并不相同。某个 CSO 可以被弱注意但仍保留在 $h$ 中作为上下文背景；也可以获得高注意权但只短暂进入工作记忆。我们可以给每个当前 CSO 分配注意权重
\[
\alpha_i(t)\geq0,
\qquad
\sum_i\alpha_i(t)=1.
\]
TCE 可以调节注意分布的整体温度，例如高探索状态下令注意分布更加平坦，而高风险状态下令注意迅速集中；Scheduler 则决定哪些 CSO 根本有资格参与这个注意竞争。二者分别对应
\[
\boxed{
Scheduler:\ WhoEnters
}
\]
与
\[
\boxed{
TCE:\ HowStronglyToFocus.
}
\]

准入机制还必须具有退出策略。如果某个结构长期不再影响当前推理，其注意权重下降到
\[
\alpha_i<\theta_{\mathrm{evict}}
\]
且与当前目标相关度也低于阈值，则 Scheduler 可以触发
\[
h\rightarrow E,
\qquad
h\rightarrow External,
\]
或者直接释放其工作位置。这里应注意，“退出 h”不等于忘记。一个结构可以离开显式认知表面，却保留在情景记忆、结构记忆或者外部载体中，等待未来重新激活。

为了防止认知颠簸，准入与退出应采用不同阈值：
\[
\theta_{\mathrm{enter}}
>
\theta_{\mathrm{leave}}.
\]
这是一种典型迟滞机制。如果两者相同，当一个结构的评分在阈值附近波动时，就会不断进出工作记忆，造成极高的上下文切换成本。通过双阈值，只有显著重要的新结构才进入，而已进入结构只有在持续失去价值后才退出。

从认知理论角度看，这意味着“注意力”不再只是模型内部 token 权重，而是整个 AgentOS 的一种跨尺度晋升政策。我们此前已经提出
\[
\boxed{
Attention=CrossScalePromotionPolicy.
}
\]
Scheduler 正是这一政策的主要离散执行机制。绝大多数身体、工具、记忆和后台过程都应在局部闭环中自行运行，只有那些产生足够高残差、风险、价值或者新颖性的结构才被提升到 $h(t)$。因此成熟智能的标志之一反而是：
\[
\boxed{
ExplicitCognitionRatio\downarrow.
}
\]
系统能力越成熟，越多正常过程不需要持续占据工作记忆；Scheduler 的作用也从“让更多事情同时进入思考”转变成“保护显式认知只处理真正需要全局整合的问题”。

\section{记忆召回调度：不是能想起什么，而是什么值得现在想起}

在具有 $E$ 和 $\Theta$ 的持续 Agent 中，记忆检索本身也会竞争认知资源。传统检索系统通常将问题表达为：给定当前 query，返回最相似的若干记忆。然而对于 AgentOS，这个定义是不充分的，因为“相关”并不意味着“现在应该进入工作记忆”。一个高度相似但已经失效的旧经验可能造成严重干扰；一个语义相似度不高、但能够揭示当前风险的历史事件则可能非常重要。因此 Scheduler 必须对记忆召回结果进行时间化和资源化治理。

设记忆系统返回候选集合
\[
\mathcal M_t=
\{m_1,m_2,\ldots,m_k\}.
\]
每个候选记忆具有至少如下属性：
\[
m_j=
(
Rel_j,
Conf_j,
Age_j,
Value_j,
Cost_j,
Interference_j,
InfoGain_j
).
\]
Scheduler 可以计算
\[
Score(m_j)
=
\alpha Rel_j
+
\beta InfoGain_j
+
\gamma Value_j
+
\delta Conf_j
-
\mu Cost_j
-
\nu Interference_j.
\]
这里的 $Interference_j$ 很重要，因为一次记忆召回可能引入大量新的 CSO，从而破坏当前工作结构。如果召回一个完整长事件需要占据大量 $h$，Scheduler 可以要求记忆系统先生成摘要
\[
m_j\rightarrow Compress(m_j),
\]
只把最小必要结构送入当前认知面。

由此产生“渐进召回”机制。首先进入 $h$ 的不是完整记忆，而是一个低成本索引
\[
m_j^{index}.
\]
只有当当前推理确认其具有较高边际价值时，Scheduler 才继续分配带宽读取
\[
m_j^{summary},
\]
甚至最终读取完整情景
\[
m_j^{full}.
\]
这形成类似分页系统的认知机制：
\[
Index
\rightarrow
Summary
\rightarrow
FullEpisode.
\]
其意义在于避免任何一次记忆命中都把整个历史重新装入工作记忆。

结构记忆 $\Theta$ 的调度又与情景记忆 $E$ 不完全相同。$E$ 主要提供“过去发生过什么”，而 $\Theta$ 提供“当前可以用什么稳定结构解释和预测”。Scheduler 因此需要决定当前问题主要需要情景证据还是结构模型。对于高度熟悉任务，可以直接激活
\[
\Theta\rightarrow h
\]
而避免大量情景回放；对于异常事件，则可能同时调度若干 $E$ 用于比较过去失败轨迹。这一差异使记忆调度本身成为成熟度的一部分：新手依赖大量回忆，成熟系统更多依赖已经凝固的结构，只在结构失配时重新回到经验。

记忆写入同样需要调度。不是每一个当前状态都值得进入 $E$，也不是每一个情景都应立刻参与 $\Theta$ 更新。Scheduler 可以为写入分配后台资源窗口：
\[
B_{\mathrm{write}}(t).
\]
在高紧迫实时任务中，记忆整理可能被延迟；当系统进入低负载期，再执行
\[
h\rightarrow E,
\qquad
E\rightarrow\Theta
\]
的批量整理。这体现出一种重要的多时间尺度原则：\textbf{执行和巩固不必同步发生}。AgentOS 可以先保持生存和任务连续，再在适当时刻将经历转化为长期结构。

所以“记忆能力强”不能简单用存储数量或检索召回率衡量。对于持续 Agent，更重要的问题是：
\begin{statementbox}
能否在正确的时间，以正确的粒度，召回正确的结构。
\end{statementbox}
Scheduler 在这里承担了记忆系统与当前认知之间的时间边界管理，使记忆从被动数据库真正成为生命周期认知系统的一部分。

\section{工具与外部进程的异步调度}

一旦 Agent 能够调用文件、数据库、程序、网络服务和其他智能体，Scheduler 就必须处理一种与内部推理不同的任务：\textbf{外部进程具有不确定延迟，并且其等待期间不应持续占据核心认知资源}。这也是为什么 AgentOS 不应该把每一次工具调用都实现成同步阻塞的语言模型调用链。

设工具任务
\[
T_i^{tool}
\]
在时刻 $t_0$ 被发起。传统同步模式相当于
\[
Agent
\xrightarrow{call}
Tool
\xrightarrow{wait}
Result,
\]
在整个等待时间
\[
[t_0,t_r]
\]
内，当前任务保持阻塞。如果外部工具响应时间很长，则持续主体的有效认知能力被不必要地冻结。

AgentOS 更合理的模型是
\[
T_i^{tool}:
Running
\rightarrow
WaitingExternal
\]
随后释放工作记忆和主要计算资源，仅保留一个恢复句柄
\[
H_i=
(
TaskID,
ContextIndex,
ExpectedResult,
Timeout,
ResumePolicy
).
\]
在工具返回时，外部事件触发
\[
WaitingExternal
\rightarrow
Ready,
\]
Scheduler 再根据当前整体优先级决定是否立即恢复。结果返回并不自动等于获得最高优先级，因为 Agent 在等待期间可能已经进入更关键任务。

因此工具调度至少需要三个时间概念：
\[
t_{\mathrm{dispatch}},
\qquad
t_{\mathrm{return}},
\qquad
t_{\mathrm{resume}}.
\]
传统 Agent 往往默认
\[
t_{\mathrm{return}}
\approx
t_{\mathrm{resume}},
\]
而持续 Agent 必须允许
\[
t_{\mathrm{return}}
<
t_{\mathrm{resume}},
\]
即结果已经到达，但当前还没有必要立即处理。

工具调用本身也需要价值评估。设工具 $K_j$ 对当前任务的预期信息价值为 $I_j$，成本为 $C_j$，等待时间为 $L_j$，可靠性为 $Q_j$，风险为 $R_j$，则可以定义
\[
Utility(K_j)
=
\alpha I_j
+
\beta Q_j
-
\gamma C_j
-
\delta L_j
-
\eta R_j.
\]
若多个工具能够回答同一问题，Scheduler 不一定选择“最强”的工具，而应根据当前认知状态选择最合适的成本--价值组合。高风险任务可能更愿意使用多个独立来源进行交叉验证；低价值日常任务则可能直接选择低成本近似工具。

对于其他 Agent 的委派同样如此。对外部 Agent 发起任务，本质上可以表示为一种外部异步进程：
\[
P_i
\rightarrow
Delegate(P_i,A_j).
\]
委派以后，本地只保留监督和验证责任，而不需要继续执行完整认知过程。这样，Offloading 与 Scheduler 发生直接联系：Offloading 决定结构可以迁移到外部，Scheduler 决定什么时候迁移以及迁移以后本地还保留多少资源。

这一机制还有一个更深的认知意义。人类在现实中能够同时推进很多事情，并不是因为意识真正并行执行大量复杂推理，而是因为大量任务处于“等待世界”的状态。邮件已经发出、文件正在下载、其他人正在处理、程序正在运行，而主体只保留恢复索引。AgentOS 需要同样的结构。否则一个功能越来越丰富的 Agent 反而会因工具增加而更加容易被阻塞。

因此，成熟 Scheduler 必须遵循：
\[
\boxed{
Waiting\neq Thinking.
}
\]
外部等待应尽可能从显式认知中卸载，并通过事件驱动机制重新进入。这样才能使单一持续主体在不复制自己的情况下管理大量并行世界进程。

\section{事件驱动调度与认知抢占}

一个开放世界 Agent 无法预先知道未来会发生什么，因此 Scheduler 不能只按照预先生成的静态计划运行。它必须是一个事件驱动的在线系统。可以定义事件集合
\[
\mathcal E=
\{
E_{\mathrm{world}},
E_{\mathrm{body}},
E_{\mathrm{goal}},
E_{\mathrm{memory}},
E_{\mathrm{tool}},
E_{\mathrm{timeout}},
E_{\mathrm{risk}},
E_{\mathrm{internal}}
\}.
\]
这些事件分别来自外部世界、身体状态、目标变化、记忆返回、工具完成、超时、安全风险以及内部认知状态变化。

每个事件进入系统以后并不自动成为工作记忆内容，而首先形成一个事件描述
\[
e_t=
(
Type,
Source,
Magnitude,
Confidence,
Urgency,
Persistence,
GoalRelevance
).
\]
随后计算事件触发强度
\[
\Gamma(e_t)
=
f(
Residual,
Risk,
Novelty,
Persistence,
GoalRelevance
).
\]
我们此前已经反复提出一条重要原则：
\[
\boxed{
RealityDoesNotContinuouslyBecomeThought;
RelevantDeviationBecomesThought.
}
\]
也就是说，世界绝大部分变化都应由低层闭环或背景系统自行吸收，只有足够重要的偏差才提升到全局认知。Scheduler 正是实现这一晋升机制的核心组件之一。

当
\[
\Gamma(e_t)<\theta_{\mathrm{local}},
\]
事件保持在局部处理层；当
\[
\theta_{\mathrm{local}}
\leq
\Gamma(e_t)
<
\theta_{\mathrm{interrupt}},
\]
它可以进入普通任务队列；只有当
\[
\Gamma(e_t)\geq\theta_{\mathrm{interrupt}}
\]
时，才具有抢占当前认知的资格。这种分层阈值比“所有消息都打断 Agent”更符合持续系统需要。

即使达到抢占阈值，Scheduler 仍需判断当前任务是否处在适合中断的位置。设当前进程 $P_i$ 的中断成本为
\[
C_{\mathrm{int}}(P_i),
\]
新事件带来的延迟损失为
\[
L(e_t,\Delta t).
\]
只有当
\[
L(e_t,\Delta t)
>
C_{\mathrm{int}}(P_i)+M
\]
时，立即抢占才是合理的，其中 $M$ 是稳定裕量。如果事件非常重要但当前任务只需几十毫秒即可到达安全检查点，那么延迟极短时间后再切换可能更加稳定。

Scheduler 因而必须维护显式 checkpoint。暂停进程 $P_i$ 时产生
\[
CP_i=
\left(
\begin{gathered}
ActiveCSO,\ GoalState,\ PlanState,\ OpenAssumptions,\\
PendingTool,\ MemoryIndex,\ ResumeCondition
\end{gathered}
\right).
\]
之后恢复时，不必重新完整推理，而是通过
\[
Restore(CP_i)
\]
重新进入原有上下文。这实际上将认知连续性变成了可管理的系统对象。

事件调度还需要去抖动。一个持续异常信号可能每一个采样周期都产生事件，如果每次都重新触发认知，会形成事件风暴。因此对同源事件应进行聚合：
\[
\{e_t,e_{t+1},\ldots,e_{t+k}\}
\rightarrow
E^{aggregate},
\]
或者采用时间窗口
\[
\Delta T_{\mathrm{debounce}}
\]
对短时间重复事件进行压缩。只有异常强度或结构发生实质改变时才重新提升。

所以 AgentOS 的响应性不是“任何变化都立即思考”，而是\textbf{依据结构意义实施选择性的实时性}。这与最初关于异种速率文明以及多尺度智能的讨论完全一致：高层认知不能追逐所有高频变化，否则它会被低层世界拖入时间黑洞。Scheduler 的一项核心使命，就是保护高层认知的时间尺度边界。

\section{多时间尺度调度与快慢认知的协调}

AgentOS 的任务并不都属于同一时间尺度。某些任务要求秒级响应，例如当前交互；某些任务持续数分钟或数小时，例如复杂工程设计；还有一些过程跨越数天甚至生命周期，例如能力形成、自我维护和长期项目。因此 Scheduler 不能只维护一个全局优先级队列，而应显式建模任务的特征时间尺度。

设进程 $P_i$ 的特征时间尺度为
\[
\tau_i.
\]
可以将任务粗略分布到多个调度带
\[
\mathcal B=
\{
B_{\mathrm{fast}},
B_{\mathrm{working}},
B_{\mathrm{slow}},
B_{\mathrm{background}}
\}.
\]
不同频带拥有不同资源刷新周期
\[
\Delta t_{\mathrm{fast}}
<
\Delta t_{\mathrm{working}}
<
\Delta t_{\mathrm{slow}}.
\]
这意味着 Scheduler 不需要在每一个快速认知周期重新评估所有生命周期任务。长期任务可以只保留低频状态，每隔较大时间窗口重新评价其优先级；只有当产生显著事件时才提前唤醒。

这种设计体现
\[
\boxed{
AdjacentScaleCouplingPrinciple.
}
\]
高频变化首先影响相邻层，而不应每次直接修改最慢变量。比如一个工具失败通常只需要重新规划当前任务，不应该直接导致长期自我结构变化。相反，如果同类失败在较长时间内持续出现，则中层统计结构才可能逐步影响长期能力判断。

Scheduler 可以维护多尺度积分量：
\[
\bar r_i^{(T)}
=
\frac{1}{T}
\int_{t-T}^t
r_i(\tau)d\tau.
\]
短期 residual 由快速调度层处理；只有当
\[
\bar r_i^{(T)}
>
\theta_T
\]
持续足够长时间时，才生成慢尺度认知任务。于是：
\[
FastEvent
\rightarrow
PersistentPattern
\rightarrow
SlowTask.
\]
这使系统避免把高频噪声直接提升为长期认知问题。

反向过程同样重要。慢尺度目标并不需要持续进入 $h$，它们主要通过约束函数影响快任务调度：
\[
\Gamma_{\mathrm{fast}}
=
\Gamma_{\mathrm{physical}}
\cap
\Gamma_{\mathrm{goal}}
\cap
\Gamma_{\mathrm{identity}}.
\]
即慢变量定义允许区域，快 Scheduler 在其中进行局部资源优化。因此：
\[
\boxed{
SlowGovernance\neq FastMicromanagement.
}
\]
如果长期价值结构必须对每一个 token 级选择进行显式推理，系统不仅低效，而且可能失去快尺度闭环的自治性。

从调度角度，这可以实现为两类信息：慢层向下发送 constraint，而快层向上发送 residual summary。高层无需持续下达每一步操作，只规定：
\[
ForbiddenRegion,\qquad
PreferredRegion,\qquad
Budget,\qquad
RiskTolerance.
\]
快层在这一包络内运行。一旦局部问题无法在包络内闭合，再触发升级。

因此 AgentOS 的多时间尺度调度不是多个独立 Scheduler 的简单堆叠，而是
\[
\boxed{
FastLocalScheduling
\leftrightarrow
SlowConstraintScheduling
}
\]
的嵌套结构。这也为持续 Agent 提供一个非常重要的成熟指标：随着能力增长，更多稳定问题应能够在较快、较低层自动闭合，而较慢的显式认知资源逐渐只处理真正新颖、冲突或者需要跨尺度整合的问题。

\section{调度稳定性：饥饿、颠簸、锁死与优先级反转}

调度机制本身也可能成为智能系统的不稳定来源，因此 Scheduler 必须像 TCE 一样接受稳定性分析。最基本的问题是饥饿。设任务 $P_i$ 的基础价值较低，但长期保持有效，如果更高优先级事件不断到达，则可能出现
\[
\lim_{t\rightarrow\infty}
Allocated_i(t)=0.
\]
这意味着任务永久无法推进。对于持续主体，这类饥饿可能尤其危险，因为健康维护、长期记忆整理和低频自我检查通常不具有最高即时优先级，却不能永久缺席。

因此可引入 aging：
\[
Priority_i'(t)
=
Priority_i(t)
+
\gamma WaitingTime_i(t).
\]
或者给某类慢任务保留最低资源比例
\[
a_i(t)\geq a_i^{\min}.
\]
这使长期过程获得“存在权”，避免整个 Agent 被短期世界完全占据。

第二类问题是认知颠簸，即频繁切换。定义单位时间切换次数
\[
N_{\mathrm{switch}}(T),
\]
以及平均上下文恢复成本
\[
\bar C_{\mathrm{restore}}.
\]
则调度颠簸可以近似写为
\[
C_{\mathrm{thrash}}
=
N_{\mathrm{switch}}
\bar C_{\mathrm{restore}}.
\]
当
\[
C_{\mathrm{thrash}}
\]
接近实际认知工作成本时，系统看似一直忙碌，实际却没有任何任务真正取得进展。解决方法包括抢占迟滞、最小运行窗口、检查点和任务聚合。

第三类是认知锁死。假设进程 $P_1$ 等待工具结果 $R_2$，而产生 $R_2$ 的进程 $P_2$ 又等待 $P_1$ 释放某个认知或外部资源，则形成
\[
P_1\rightarrow R_2\rightarrow P_2\rightarrow R_1\rightarrow P_1.
\]
Scheduler 必须维护 wait-for graph
\[
\mathcal G_W
\]
并检测其中的环。对于认知资源，应尽量避免长时间持有不可抢占的全局锁；更优方式是异步消息、版本化状态和事务式 checkpoint。

第四类问题是优先级反转。低优先级任务可能持有高优先级任务所需的某项资源，导致真正关键任务无法运行。如果
\[
Priority(P_H)>Priority(P_L),
\]
但 $P_H$ 等待 $P_L$ 持有的资源，则需要临时提升
\[
Priority(P_L)\uparrow
\]
直到资源释放，这与传统 priority inheritance 思想在结构上相似。

更值得注意的是 AgentOS 特有的“语义优先级反转”。某个低级工具过程可能在计算资源上优先级很低，却承载高价值 Goal 的关键证据。如果 Scheduler 只根据进程类型排序，就可能错误延迟它。因此优先级必须由 Goal dependency graph 向下传播，而不是由模块名称决定。

我们还可以定义 Scheduler 的稳定性指标：
\[
\mathcal S_{\mathrm{sched}}
=
F\!\left(
\begin{gathered}
Throughput,\ Latency,\ Starvation,\\
SwitchRate,\ DeadlineMiss,\ CognitiveLoadVariance
\end{gathered}
\right).
\]
一个稳定 Scheduler 不是切换越少越好，也不是吞吐越高越好，而是在有限资源下使系统长期保持可预测的认知节律。其目标是让正常变化被局部吸收，重要异常能够及时提升，长期任务持续获得最小进展，同时避免高层工作记忆被中断风暴占据。

因此调度稳定性本身应被 SPC 观察。SPC 不只观察认知内容，还可以估计：
\[
SwitchRate,\quad
QueueDepth,\quad
StarvationRisk,\quad
hOccupancy,\quad
ToolWaitRatio.
\]
如果这些指标进入异常区，Scheduler 可以改变自身策略，例如降低抢占敏感度、增加批处理窗口或者扩大后台整理时间。由此形成
\[
Scheduler
\rightarrow
SystemState
\rightarrow
SPC
\rightarrow
SchedulerPolicy.
\]
Scheduler 也因此成为 AgentOS 自我调节的一部分，而不是一个静态算法。

\section{调度策略的适应与固定拓扑下的学习}

本编研究的仍然是功能拓扑基本固定的 AgentOS，但“固定拓扑”并不意味着 Scheduler 的策略必须固定。恰恰相反，一个持续智能体应该逐渐学习自己在不同任务、身体状态和环境条件下怎样分配认知资源更加有效。变化的首先不是模块连接方式，而是调度政策
\[
\pi_S.
\]

定义
\[
\mathcal A_t
=
\pi_S(
\widehat X_t,
\mathcal P_t,
\mathcal G_t,
\mathcal R_t;
\phi_t
),
\]
其中 $\phi_t$ 是 Scheduler 的可学习参数。长期运行以后，可以根据执行结果更新
\[
\phi_{t+1}
=
\phi_t
+
\eta
\nabla_\phi J_S.
\]
这里 $J_S$ 不应只包含任务完成率，还必须包括切换成本、认知过载、失败恢复、资源公平和长期目标进度。一个只奖励即时任务完成率的 Scheduler 很可能学会牺牲所有慢任务来追求短期吞吐，这是与持续主体目标相冲突的。

因此可定义综合经验代价：
\[
L_S
=
\lambda_1 L_{\mathrm{task}}
+
\lambda_2 L_{\mathrm{overload}}
+
\lambda_3 L_{\mathrm{switch}}
+
\lambda_4 L_{\mathrm{starvation}}
+
\lambda_5 L_{\mathrm{risk}}
+
\lambda_6 L_{\mathrm{continuity}}.
\]
Scheduler 的学习就是寻找
\[
\phi^\star
=
\arg\min_\phi
\mathbb E[L_S].
\]

但调度策略学习必须受到慢变量保护。Scheduler 不应因为一次偶然成功就彻底改变优先级机制。可以采用双时间尺度：
\[
\tau_{\mathrm{decision}}
\ll
\tau_{\mathrm{policy}}.
\]
瞬时决策快速变化，而 $\phi$ 只有在大量运行证据积累以后缓慢更新。对于安全相关权重甚至应由治理层锁定，使
\[
\phi=
[
\phi_{\mathrm{adaptive}},
\phi_{\mathrm{protected}}
].
\]
其中 protected 部分不可被普通在线学习任意修改。

长期经验还可以形成“调度习惯”。例如系统反复发现某类任务在清晨低负载阶段执行更有效，或者某类记忆整理适合在外部等待期间运行，那么 Scheduler 可以逐渐建立 context-conditioned policy：
\[
\pi_S(a|x,c).
\]
这里 $c$ 表示环境、主体状态和任务类型。这样 Agent 不是每一次都从零决定“现在做什么”，而是在经验基础上形成更稳定的时间组织方式。

这与我们此前关于技能沉降的思想具有一致性。认知内容可以从显式推理沉降为结构，调度策略本身也可以从显式权衡逐渐变成稳定运行策略。不同的是，在当前固定拓扑阶段，这种变化仍然发生在参数和策略层，而不直接增加新的功能节点或连接。换言之：
\[
\boxed{
AdaptiveScheduling
\neq
TopologicalRewriting.
}
\]
这一区分十分重要，它使我们能够在较安全、较可验证的系统结构中先研究长期认知调度学习，然后再讨论更加激进的结构自重组问题。

\section{从操作系统调度到“现在性的治理”}

到这里，我们可以重新理解为什么将其命名为 Scheduler 虽然借用了操作系统术语，但其理论内涵已经明显扩展。传统 Scheduler 决定的是
\[
\text{WhichProcessUsesCPUNow?}
\]
而 AgentOS Scheduler 更接近在回答
\begin{statementbox}
WhichPartOfTheAgent'sWorldBecomesExplicitNow?
\end{statementbox}
它决定哪个目标成为当前目标，哪个记忆成为当前记忆，哪个异常值得打断思考，哪个工具结果现在值得读取，以及哪个后台过程应该继续保持沉默。

因此 Scheduler 实际治理的是智能体的“现在性”。对于一个持续主体，世界中任何时刻都有远多于其能够显式处理的事实、需求和可能行动。$h(t)$ 是一条不断前进的有限认知切面，而 Scheduler 决定哪些结构穿过这一切面。可以把它形式化为
\[
\mathcal C_{\mathrm{world}}(t)
\xrightarrow{\;Boundary/Observation\;}
\mathcal C_{\mathrm{candidate}}(t)
\xrightarrow{\;Scheduler\;}
\mathcal C_h(t).
\]
与此同时，来自过去的 $E$、来自长期结构的 $\Theta$、来自目标体系和自我结构的约束，也都作为候选结构竞争进入同一有限现在：
\[
\{
World,
E,
\Theta,
Self,
Goal,
Tool
\}
\rightarrow
Scheduler
\rightarrow
h(t).
\]

这意味着智能体的“现在”并非世界的完整当前状态，而是一个经过选择的结构切面。对于同一个外部世界，不同的 Scheduler、不同的 Goal 和不同的 Self 会形成不同的当前认知世界。由此可以理解为什么调度并不是一个纯工程细节，它实际上是智能体认识论的一部分：系统能够知道什么，不仅取决于它拥有多少传感器和记忆，也取决于什么被允许在正确的时间进入显式认知。

但这一选择必须始终接受现实校验。Scheduler 可以决定暂时忽略一个低优先级事件，却不能使事件本身从现实中消失；它可以延迟处理记忆，却不能把预测状态冒充现实观测。因此其最终边界仍然是
\[
\boxed{
RealityIsUltimateConstraint.
}
\]
如果外部残差持续增大，原本被压低的事件必须逐渐提高调度势能，最终突破准入阈值。这确保 Scheduler 的选择性不会演变成封闭的认知偏见。

从系统角度，我们最终可以把本章确立的运行闭环浓缩为
\[
\boxed{
World/Memory/Self/Goal
\rightarrow
SPC
\rightarrow
Scheduler
\rightarrow
TCE+CCM
\rightarrow
h
\rightarrow
CognitiveAction
\rightarrow
Feedback
\rightarrow
SPC.
}
\]
其中 SPC 使系统知道自己正在发生什么，Scheduler 决定现在应该把有限资源交给什么，TCE 决定这些活动以怎样的动力状态运行，CCM 负责使进入运行态的结构保持在可处理范围内，而 $h(t)$ 则成为这些治理过程最终汇聚的显式认知表面。

\section{本章结论：Scheduler 是持续智能的时间秩序}

本章从工作记忆有限容量出发，推导了 Scheduler 在 AgentOS 中的必然性。只要一个持续智能体同时面对多个目标、任务、记忆、环境事件和外部工具，而显式认知资源又是有限的，它就必须建立某种资源竞争秩序。这个秩序不能完全由 Goal、SPC、TCE 或 CCM 中任何一个组件替代，因为“值得做什么”“系统现在如何”“认知过程怎样运行”“如何降低结构负载”和“谁现在获得资源”是五个逻辑上不同的问题。

由此，我们可以给 Scheduler 一个最终定义：
\begin{center}
\begin{minipage}{.9\linewidth}
\bfseries Scheduler 是 AgentOS 中负责在有限认知资源约束下，
依据目标价值、状态估计、时间要求、风险、信息增益和长期连续性，
动态决定认知进程执行权、工作记忆准入权以及跨资源分配关系的离散治理机制。
\end{minipage}
\end{center}

其最小状态可以写为
\[
S_{\mathrm{sched}}(t)
=
(
\mathcal P_t,
\mathcal G_t,
\mathcal R_t,
\mathcal Q_t,
\mathcal W_t,
\Pi_t
),
\]
其中 $\mathcal P_t$ 为进程集合，$\mathcal G_t$ 为目标集合，$\mathcal R_t$ 为资源状态，$\mathcal Q_t$ 为等待/就绪队列结构，$\mathcal W_t$ 为依赖关系，$\Pi_t$ 为动态优先级状态。Scheduler 的控制输出则是
\[
\mathcal A_t
=
\{
Admission,
Allocation,
Preemption,
Pause,
Resume,
Eviction,
Dispatch
\}.
\]

本章得到的主要理论原则可以归纳为：
\begin{statementbox}
有限工作记忆必然产生调度。
\end{statementbox}

\begin{statementbox}
存在不等于激活，激活不等于获得执行权。
\end{statementbox}

\begin{center}
\bfseries SPC 负责观察，TCE 负责调制，CCM 负责负载治理，Scheduler 负责资源分配。
\end{center}

\[
\boxed{
GoalPriority\neq ProcessPriority.
}
\]

\[
\boxed{
Waiting\neq Thinking.
}
\]

\[
\boxed{
RelevantDeviationBecomesThought.
}
\]

\[
\boxed{
SlowGovernance\neq FastMicromanagement.
}
\]

以及最重要的一条：
\begin{statementbox}
成熟智能并不是同时思考更多事情，而是越来越准确地决定什么值得在此刻成为思考。
\end{statementbox}

因此，Scheduler 的真正作用并不是提高一个算法的并行度，而是为持续主体建立时间秩序。它使有限的 $h(t)$ 不再被世界无差别占据，使过去、现在、未来目标以及外部事件能够在同一个认知切面上形成受治理的竞争关系。正是这种选择性的时间组织，使 AgentOS 有可能在不复制主体、不无限扩张工作记忆的情况下，同时维持多任务运行、长期计划、记忆整合、现实响应和身份连续。

从这里开始，AgentOS 已经不仅拥有“认知能力”，而开始拥有一种更接近操作系统意义上的\textbf{认知运行秩序}：世界持续发生，记忆持续积累，目标持续存在，但只有少数结构在某一时刻真正成为“现在”。Scheduler 所治理的，正是这个持续不断被重建的现在。
