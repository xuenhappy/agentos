\chapter{内部记忆、外部记忆与 Me}
\label{chap:internal-external-memory-me}

\begin{chapteroverviewbox}
本章确立 AgentOS 记忆理论中的一个基础原则：\textbf{长期智能体的记忆不能被限制在模型参数或内部存储之中。} 一个持续存在的 Agent 所能够重新进入未来认知过程的结构，可能承载于其内部参数、工作记忆、情景记忆与结构记忆之中，也可能被沉降到文件、数据库、程序、Skill、工具、环境以及其他智能体之中。因此，记忆的第一性问题不是“信息存放在哪里”，而是：\emph{过去形成的认知结构能否在未来被可靠地重新定位、恢复、解释，并重新参与当前闭环。}

本章据此区分 Internal Memory 与 External Memory，并引入外部认知世界 \(M_e\)（亦可简称为 Me）。这里的 Me 不是 ``self'' 意义上的 ``我''，也不是自我结构 \(\Psi\)，而是 Agent 可以通过稳定接口重新访问、调用、感知或委托的一组外部结构载体。内部与外部不是静态二分，而是在 Boundary 与 Offloading 作用下不断发生双向迁移的承载边界。后续章节可以在这一基础上继续讨论环境记忆、社会性记忆和具身外化，但本章只建立内部--外部记忆系统本身的统一理论。
\end{chapteroverviewbox}

\section{内部记忆：智能体自身边界之内的结构连续性}

我们首先需要澄清什么叫做 Agent 的``内部记忆''。在传统计算机系统中，内部存储往往意味着某一进程地址空间中的 RAM、缓存或持久化数据库；在神经网络语境中，人们又常把模型参数直接称为``记忆''。如果继续采用这种宽泛用法，就无法区分一个长期智能体中性质完全不同的结构：有些信息正在参与当前推理，有些信息属于可回放的经历，有些信息已经成为稳定的生成规律，而另一些结构甚至已经深度沉积为模型参数。因此，本书不再以物理存储介质定义内部记忆，而以\textbf{认知结构是否主要由 Agent 自身内部动力系统负责保持、更新和重新激活}来定义。

在此前建立的三相记忆模型中，内部记忆首先包含
\[
M_{\mathrm{int}}(t)
=
\{h(t),E(t),\Theta(t)\}.
\]
其中 \(h(t)\) 是当前显式工作状态，\(E(t)\) 是沿时间展开的经验轨迹，而 \(\Theta(t)\) 是较慢的生成结构。随着自我与生命周期变量被引入，内部长期结构还应进一步包括
\[
M_{\mathrm{int}}^{+}(t)
=
\{h,E,\Theta,\Psi,\Omega\},
\]
其中 \(\Psi\) 维持身份与价值连续性，\(\Omega\) 或 DGA 则表示更慢的生命周期生成倾向。需要强调的是，这些对象不必全部以同一种数据结构实现；相反，它们在工程上很可能分别对应活动上下文、事件存储、结构图谱、参数化模型、自我档案和超慢生成约束。它们之所以统一属于内部记忆，不是因为被保存在同一块硬盘上，而是因为其主要更新责任和解释责任仍然处于 Agent 的内部认知边界。

这意味着一个文件即使物理上位于本机磁盘，也未必属于 Internal Memory；反之，一个远端向量库若被 AgentOS 纳入内部生命周期管理，也可能在工程上具有``近内部''性质。因此，本章采用的是功能边界而不是机器边界。可以写成
\[
x\in M_{\mathrm{int}}
\iff
\mathrm{PrimaryGovernance}(x)=\mathrm{AgentInternalDynamics}.
\]
所谓 \(\mathrm{PrimaryGovernance}\)，指的是谁决定该结构何时写入、何时压缩、如何冲突消解、何时遗忘以及如何重新激活。这个定义可以避免把``服务器在哪里''误当成认知本体问题。

从认知科学角度，本章的这一划分与工作记忆、情景记忆、语义记忆、程序性记忆等传统分类具有一定对应，但并不要求逐一映射。我们的目标不是复制人类脑科学分类，而是建立一个适用于数字 Agent、机器人和长期软件智能体的工程结构。更重要的是，三相模型强调的不是记忆``内容种类''，而是认知结构在不同时间尺度上的动力学性质：
\[
\tau_h\ll\tau_E\ll\tau_\Theta\ll\tau_\Psi\ll\tau_\Omega.
\]
因此，内部记忆本身就是一个多时间尺度系统。快变量负责保持当前可操作状态，慢变量负责让过去不必每次重新计算，而超慢变量则使不同时间点上的 Agent 仍然可以被视为同一个持续主体。

这一理解也直接引出本章后面的核心问题：如果内部记忆能够承担一切，那么外部记忆就没有必要存在；但真实智能恰恰不可能无限扩张自身内部承载能力。工作记忆具有有限容量，结构记忆具有修改成本，模型参数存在重训练或持续学习风险，而很多高度稳定、低频调用的结构如果长期占据内部认知资源，反而降低系统适应性。因此，内部记忆不是越大越好，而是必须与外部承载共同组成一个能够长期重构的记忆系统。后文将看到，智能体真正需要维持的不是``所有信息都在我里面''，而是\textbf{我能够可靠知道什么结构在哪里，以及如何在需要时把它重新带回当前认知闭环。}

\section{外部记忆：从存储位置到认知可恢复结构}

如果把外部记忆简单定义成``不在模型里的信息''，那么互联网、整个文件系统甚至所有可访问网页都将被迫称为 Agent 的记忆。这显然失去了理论区分度。因此，本书采用一个更严格的定义：\textbf{外部记忆是位于 Agent 内部认知边界之外、但已经与该 Agent 建立稳定索引、访问路径或功能依赖，并能够在未来重新进入其认知与行动闭环的结构载体。}

设外部世界中存在某一结构 \(x\)，定义其是否属于 Agent \(A\) 的外部记忆，可以用一个可恢复条件表示：
\[
x\in M_e^A
\iff
P\left(
\mathrm{Recover}(x\,|\,A,t+\Delta t)
\right)
\geq
\eta,
\]
其中 \(\eta\) 是系统规定的最低可靠恢复阈值。这里的 Recover 不只是``文件还存在''，而包括 Agent 能够再次定位它、验证它的身份、理解其语义、判断版本是否有效，并让它重新参与当前任务。这一条件意味着，外部结构只有在形成认知可达性之后才真正具有记忆意义。

例如，一个随机存在于互联网中的 PDF 并不是某个 Agent 的外部记忆；但当 Agent 已经建立文献索引、语义标签、权限信息和调用路径，使其能够在适当任务中重新定位该 PDF，它就开始成为 \(M_e\) 的一部分。类似地，一个程序库本身也不自动构成外部记忆；只有当 Agent 知道``在什么条件下调用哪个函数、得到什么类型结果、如何验证执行结果''时，它才转化为可恢复功能结构。

因此，外部记忆至少具有四个必要条件。第一是\emph{可寻址性}，即 Agent 必须具有某种索引或路径。第二是\emph{可解释性}，即取回以后能够重新建立语义关系。第三是\emph{可验证性}，即 Agent 能够确认外部结构没有因为版本变化、权限变化或环境变化而失效。第四是\emph{可再进入性}，即结构能够真正重新进入 \(h(t)\)、\(E\)、\(\Theta\) 或行动过程，而不是停留在不可调用的数据孤岛中。

由此可以定义一个外部记忆对象
\[
m_e
=
(c,\iota,\sigma,v,p,r),
\]
其中 \(c\) 为实际承载内容或功能结构，\(\iota\) 为索引，\(\sigma\) 为语义描述，\(v\) 为版本或时间状态，\(p\) 为访问权限，而 \(r\) 表示恢复与调用方法。于是 Agent 真正需要内部保持的并不是整个 \(c\)，而至少需要保持一个足够稳定的
\[
\mathrm{Pointer}(m_e)
=
(\iota,\sigma,v,p,r).
\]
这正是外部记忆能够降低内部认知负担的原因：它把``完整结构''替换成``可恢复结构索引''。

这一观点与认知卸载、扩展心智和分布式认知理论有明显相似之处。人类不会把所有电话号码、地图、公式和操作规程完整保持在工作记忆中，而是通过纸张、书籍、软件和社会关系建立可恢复路径。不过 AgentOS 在这里进一步把这种现象工程化：外部记忆不是哲学上的``心智是否延伸到环境''之争，而是一个可以实际定义权限、版本、索引、失效检测和恢复概率的 Runtime 对象。

因此，外部记忆的核心不应表述为
\[
\mathrm{Memory}=\mathrm{Storage},
\]
而应改写为
\[
\boxed{
\mathrm{Memory}
=
\mathrm{RecoverableStructureAcrossTime}
}.
\]
只要过去形成的结构能够跨越时间重新作用当前状态，它就在功能意义上具备记忆属性；而它究竟位于参数、数据库、文件、环境还是另一个 Agent 中，是第二层问题。

\section{Me：Agent 的外部认知世界}

在内部--外部记忆理论形成之后，我们需要一个符号统一表示 Agent 可以稳定调用的外部认知结构集合。此前讨论中使用 \(M_e\) 表示 External Memory 或 External Cognitive World，本章保留这一记号，并将其简称为 Me。为了避免概念混淆，应再次明确：
\[
M_e\neq \Psi.
\]
\(\Psi\) 表示``我是谁''这一慢速自我结构，而 \(M_e\) 表示``哪些外部结构已经进入我的稳定认知可达范围''。前者属于身份，后者属于扩展认知资源。

可以把 Me 定义成一个带类型的外部结构空间：
\[
M_e
=
M_{\mathrm{info}}
\cup
M_{\mathrm{tool}}
\cup
M_{\mathrm{env}}
\cup
M_{\mathrm{social}}.
\]
其中 \(M_{\mathrm{info}}\) 是信息空间，包括文档、数据库、向量库、知识图谱、事件库等；\(M_{\mathrm{tool}}\) 是工具与程序空间，包括函数、API、程序、工作流、Skill 和算法；\(M_{\mathrm{env}}\) 是环境空间，表示 Agent 已经能够稳定感知并修改的外部结构；\(M_{\mathrm{social}}\) 则表示其他 Agent、人类、组织和社会规则所形成的可调用或可协同结构。

为什么必须把这些不同对象统一进 Me？因为从 AgentOS 的认知调度视角看，它们都具有一个共同功能：\textbf{使某些原本需要内部持续保持或重新计算的结构，可以通过较低成本的外部路径在未来重新获得。} 查询数据库与调用函数表面上完全不同，但在更高抽象上，两者都是
\[
h
\xrightarrow{\mathrm{request}}
M_e
\xrightarrow{\mathrm{return}}
h'
\]
的外部认知回路。前者返回信息结构，后者返回计算结果；环境可能返回新的物理状态，其他 Agent 则返回社会性判断、知识或行动结果。

因此，Me 不是一个静态仓库，而应写成动态系统：
\[
\tau_e\dot M_e
=
F_e(h,E,\Theta,M_e,B,u_T,\mathcal W),
\]
其中 \(B\) 是 Boundary，\(u_T\) 表示当前调度或控制信号，\(\mathcal W\) 表示外部世界变化。这个方程强调 Me 自身会变化：文件被更新，工具版本发生变化，环境被行动改变，其他 Agent 的状态也会变化。因此，外部记忆与内部长期记忆之间一个重要差异在于，内部记忆通常由 Agent 自身控制得更多，而 Me 往往受到外部独立动力学影响。

正因为如此，Me 中的任何结构都必须具有可信度和新鲜度。可以为一个外部对象定义
\[
q_e
=
f(
\mathrm{availability},
\mathrm{freshness},
\mathrm{integrity},
\mathrm{trust},
\mathrm{semantic\ compatibility}
),
\]
只有当 \(q_e\) 高于当前任务需求阈值时，它才适合作为有效认知载体。换言之，Agent 不应因为``曾经把某个文件存出去''就假设它永远可靠。

从智能体能力角度，Me 的扩大意味着 Agent 的认知边界不断向外扩展，但并不意味着所有这些结构都被``内化''。相反，成熟 Agent 应当学会保持一个较小而高质量的内部结构核心，同时建立越来越丰富但可治理的 Me。这个原则与传统``把更多知识装进模型''的扩展路线具有根本差异：真正长期智能的能力增长，很大一部分可能不是
\[
|\Theta|\uparrow
\]
而是
\[
|\mathrm{Reachable}(M_e)|\uparrow
\]
以及
\[
\mathrm{AccessCost}(M_e)\downarrow.
\]
也就是说，智能扩张不仅是知道更多，还包括拥有更好的外部结构网络。

\section{Skill、Script 与 Program：当经验变成可执行外部结构}

外部记忆最容易被误解为外部``数据''，但在 AgentOS 中，很多最重要的外部记忆并不是静态文本，而是可执行结构。一个已经重复解决多次的问题，如果仍然每次都重新进入 \(h(t)\) 进行显式推理，那么系统虽然记住了结果，却没有真正完成认知成熟。更有效的过程是把稳定经验压缩成 Skill、Script 或 Program，使原本需要显式协调的结构逐渐变成可直接调用的执行闭环。

我们可以把这种过程写成
\[
h
\rightarrow
E
\rightarrow
\Theta
\rightarrow
\mathrm{Executable}(M_e).
\]
最初，Agent 需要在工作记忆中逐步规划；随后这些轨迹进入 \(E\)，形成成功与失败经验；再经过 \(\Theta\) 的结构化学习，得到更稳定的规则；当该规则足够成熟时，便可以被进一步外化成程序、脚本或 Skill。于是过去的认知过程从``需要重新思考''变成``需要知道何时调用''。

这种变化不是简单的缓存优化，而是认知结构的位置重组。假设某任务 \(T\) 原本需要显式处理结构集合
\[
\mathcal C_T
=
\{C_1,\ldots,C_n\},
\]
每次执行都需要重新激活这些 Agent-CSO。经过程序化以后，只需要在内部保持
\[
C_{\mathrm{invoke}}
=
(\mathrm{condition},
\mathrm{interface},
\mathrm{expected\ outcome},
\mathrm{exception}),
\]
真正复杂的执行关系则被固化在外部程序中。因此原本显式认知负担
\[
C_{\mathrm{explicit}}(T)
\]
可以下降为
\[
C_{\mathrm{call}}(T)
+
C_{\mathrm{monitor}}(T).
\]
这正是认知卸载能够提升系统规模的根本原因之一。

不过，把 Skill、Script、Program 纳入外部记忆体系必须附带一个重要限制：可执行结构与信息型记忆具有不同的失败模式。文档过期可能导致判断错误，而程序过期则可能直接改变世界。因此执行型外部记忆必须同时保存版本、权限、依赖和验证逻辑。一个完整的外部 Skill 可形式化为
\[
S
=
(P_{\mathrm{pre}},
I,
\pi,
O,
P_{\mathrm{post}},
E_x),
\]
其中 \(P_{\mathrm{pre}}\) 是前置条件，\(I\) 是输入接口，\(\pi\) 是执行策略或程序，\(O\) 是输出，\(P_{\mathrm{post}}\) 是期望后置状态，而 \(E_x\) 表示异常与退出条件。

这意味着真正的 Skill Memory 不是``我以前做过''，而是``我已经形成了一个未来可以重新调用的稳定闭环''。这一点与传统程序性记忆理论和技能自动化研究存在明显对应，也与编译理论具有强烈结构类比：重复出现的高层表示被压缩成低层可执行表示。但是在本章中我们暂时不进一步讨论具身技能如何沉降到 Body Runtime；这里要建立的只是一个一般原则：

\begin{proposition*}
长期智能的记忆不仅要保存事实，也要保存已经学会如何完成某类结构转换。
\end{proposition*}

因此 External Memory 不能被缩减为 RAG 或向量数据库。一个真正的外部认知世界必须同时包含``可以查询的结构''和``可以执行的结构''。

\section{File、Database 与 Knowledge Store：外部结构的持久化载体}

文件、数据库、知识图谱和向量存储是最典型的外部信息型记忆，它们的共同优点是持久、容量大、易于复制，并可以独立于 Agent 当前认知状态长期存在。然而，正因为这些载体容量近乎无限，它们也最容易造成一个错误认识：只要把大量数据保存下来，就等于 Agent 拥有了大量长期记忆。实际上，没有索引、语义关系和恢复机制的数据只是一座信息仓库，并不会自动成为智能体的可用记忆。

可以将外部信息记忆表示成
\[
M_{\mathrm{info}}
=
(D,I,G,V,A),
\]
其中 \(D\) 是数据内容，\(I\) 是索引结构，\(G\) 是语义或关系图，\(V\) 是版本与时间结构，\(A\) 是访问与权限结构。对 Agent 而言，真正决定记忆价值的不是 \(|D|\)，而是
\[
U(M_{\mathrm{info}})
=
f(
P_{\mathrm{retrieve}},
T_{\mathrm{retrieve}},
Q_{\mathrm{semantic}},
Q_{\mathrm{fresh}},
Q_{\mathrm{trust}}
).
\]
如果数据量不断增长而检索概率下降，那么形式上的记忆容量在扩大，实际可用记忆却可能下降。

这与工作记忆有限容量定理形成直接对应。内部 \(h(t)\) 不可能同时载入整个数据库，因此外部记忆管理必须承担一种``分层寻址''作用：先通过较小索引确定候选区域，再将少量相关结构重新激活进入当前认知。于是理想路径不是
\[
M_e\rightarrow h
\]
的无差别加载，而是
\[
Goal
\rightarrow
Query
\rightarrow
Index
\rightarrow
Candidate
\rightarrow
Verification
\rightarrow
h.
\]
这实际上把外部记忆访问变成一个受目标约束的认知过程。

文件尤其具有一种特殊优势：它天然支持结构化外化。一个复杂任务的中间状态、计划、证明、图表或设计文档，可以从 \(h\) 中释放出去，随后在未来重新恢复。由此，Agent 可以把原本必须同时存在于工作记忆中的空间复杂度转换成沿时间展开的外部状态序列。这正是此前复杂度治理理论中``时序展开''的重要实现方式之一。

数据库则更适合高频、结构化和可查询的外部状态，而知识图谱适合保存关系显式的结构；向量存储适合语义近邻召回，但不能单独承担完整知识本体。AgentOS 因此不应绑定某一种存储技术，而应在更高层统一描述：
\[
\mathrm{ExternalStore}
:
\mathrm{CSO\ Descriptor}
\leftrightarrow
\mathrm{PersistentCarrier}.
\]
不同介质的作用只是实现这一映射的不同工程手段。

这里还必须强调版本管理。外部记忆并不像 \(\Theta\) 那样天然与 Agent 当前内部状态同步。一个文件可能来自三个月前，一个 API 可能已经改变，一个数据库记录可能被其他主体修改。因此每一次重新进入当前认知都应附带时间和来源：
\[
m_e
=
(c,t_{\mathrm{write}},t_{\mathrm{read}},source,version,confidence).
\]
这使 External Memory 不只是存储系统，也成为认识论系统。Agent 不仅要知道``我找到了什么''，还需要知道``这是什么时间、什么来源、多少可信度的结构''。

\section{Tool：外部计算结构作为认知能力的延伸}

Tool 与普通信息存储之间存在本质差异。文件告诉 Agent ``某个结构是什么''，而工具则允许 Agent 把一个尚未完成的结构转换过程交给外部系统执行。例如搜索引擎、编译器、数据库查询器、数学求解器、浏览器、代码执行环境乃至专用模型，本质上都提供了某种
\[
F_{\mathrm{tool}}:X\rightarrow Y
\]
的外部结构转换能力。

因此，把工具放入广义外部记忆体系，并不是因为工具``存储了数据''，而是因为它保存了过去已经被固化的计算、规则和功能拓扑。一个排序函数没有保存某次排序结果，却保存了``如何排序''这一稳定结构；一个搜索工具没有存储 Agent 的全部知识，却提供了稳定的外部检索闭环。由此我们可以把工具理解成
\begin{statementbox}
Externalized Cognitive Operator
\end{statementbox}
即外部化的认知算子。

对于长期智能而言，这一点具有极强的扩展意义。如果所有功能都必须被写入 \(\Theta\) 或底层模型参数，Agent 的内部结构会持续膨胀；而当大量稳定操作被外化成 Tool，Agent 内部只需保持：
\[
(\mathrm{when\ to\ call},
\mathrm{what\ to\ pass},
\mathrm{what\ to\ expect},
\mathrm{how\ to\ verify}).
\]
这相当于用一个低维调用结构替代一个高维内部执行结构。

假设某认知变换 \(F\) 在内部执行需要成本
\[
C_{\mathrm{int}}(F),
\]
而外部调用工具需要
\[
C_{\mathrm{ext}}(F)
=
C_{\mathrm{invoke}}
+
C_{\mathrm{communication}}
+
C_{\mathrm{verification}}
+
C_{\mathrm{risk}}.
\]
当
\[
C_{\mathrm{ext}}(F)<C_{\mathrm{int}}(F)
\]
并且外部工具可靠性满足要求时，持续外化是合理的。反之，如果工具调用延迟极高、权限不稳定或验证成本过大，则结构可能更适合内部化。

这里已经隐含了一个重要的``修改代价比''原则：Agent 不应固定追求内部或外部，而应比较不同载体的长期读写、更新、恢复和治理成本。可以粗略定义
\[
R_m(C)
=
\frac{
Cost_{\mathrm{internal}}(C)
}{
Cost_{\mathrm{external}}(C)
}.
\]
当 \(R_m\gg1\) 时，外部承载更有吸引力；当 \(R_m\ll1\) 时，内部化更合理。这个比值不只是计算成本，还应包含延迟、安全、隐私、可用性和结构稳定性。

因此，Tool Memory 的关键不是工具数量，而是 Agent 是否已经建立稳定的工具语义。一个拥有一万个 API 却不知道何时调用的 Agent，不比没有工具强多少。真正重要的是形成
\[
AgentCSO_{\mathrm{problem}}
\leftrightarrow
ToolCapability
\]
之间稳定的映射。这一映射一旦建立，外部工具就开始成为 Agent 长期能力结构的一部分。

\section{Environment：环境作为可写入的外部记忆}

传统记忆理论通常把环境视为信息来源，而不是记忆载体。但对于真正具身或长期运行的 Agent，这种划分是不完整的。只要 Agent 能够通过行动改变环境，并且这种改变能够在未来重新影响 Agent，那么环境本身就具备外部记忆性质。最简单的例子是把某个物体放在固定位置、改变一个目录结构、建立一个标签、调整房间布局，甚至在数字世界中重新组织文件。过去的认知决策被写进环境以后，未来 Agent 不需要重新内部记住全部决策过程，只需要重新观察环境即可恢复部分结构。

可以把这一过程写成
\[
AgentCSO_t
\xrightarrow{\mathrm{Action}}
E^{world}_{t+1}
\xrightarrow{\mathrm{Observation}}
AgentCSO_{t+k}.
\]
其中 \(E^{world}\) 不再只是外部扰动，而成为认知结构的持久载体。也就是说，Agent 可以把某些内部结构
\[
C_{\mathrm{int}}
\]
写成环境结构
\[
C_{\mathrm{env}},
\]
再在未来通过感知恢复
\[
\widehat{C}_{\mathrm{int}}.
\]
只要这个回路具有足够稳定性，环境就成为 External Memory。

这一思想与分布式认知中的 ``cognitive artifact'' 以及群体智能中的 stigmergy 有明显关系。蚂蚁并不需要在每个个体内部保存整个群体计划，而是通过环境中的信息痕迹协调行为。人类也不断把认知结构外化到道路、标志、建筑、日程、桌面布局和制度中。AgentOS 将这一机制推广到人工智能体：成熟 Agent 不应该只学习``适应世界''，还应该学习``如何改变世界，使未来认知更容易''。

这种环境外化带来一个重要的计算结果。设某问题每次重新求解的内部成本为 \(C_r\)，通过环境重构以后，未来重复任务成本下降为 \(C_r'\)，而一次性环境修改成本为 \(C_w\)。若任务预计重复 \(N\) 次，则环境外化在
\[
C_w+NC_r'
<
NC_r
\]
时具有长期收益。于是，环境改造不只是行动结果，也是一种认知投资。

但是，环境与文件最大的区别在于控制权通常更弱。环境可能被其他 Agent、自然过程或系统变化修改，因此环境记忆必须具有更强的观测验证。Agent 不应认为 ``我上次把东西放在那里，所以现在一定还在那里''。恢复外部环境记忆必须经过
\[
ExpectedState
\rightarrow
Observation
\rightarrow
Verification
\]
而不能直接把过去动作结果当成当前现实。这一原则与全书更高层的 Reality Authority 一致，但在本章只需保留为环境外部记忆的基本约束。

因此，Environment Memory 可以被理解成一种非常特殊的外部记忆：它既是记忆载体，又是当前世界的一部分；既保存过去行动形成的结构，又可能独立于 Agent 继续演化。它揭示了一个非常重要的事实：\textbf{认知并不总是在内部完成，很多成熟智能会主动重构环境，使未来问题本身变得更容易。}

\section{Other Agent：社会性外部记忆}

外部记忆理论走到这里，还需要面对一个比文件和工具更复杂的载体：其他智能体。一个 Agent 可以把知识、任务、判断甚至长期责任交给另一个 Agent，也可以在未来通过询问、协商和委托重新获得这些结构。从功能上看，这显然也是一种外部承载；但它又与普通数据库完全不同，因为 Other Agent 自身具有记忆、目标、边界和独立动力学。

因此，可以定义社会性外部记忆
\[
M_{\mathrm{social}}
=
\{A_1,A_2,\ldots,A_n\}
\]
以及 Agent \(A\) 对某个外部主体 \(A_j\) 的信任状态
\[
T_{A\rightarrow A_j}(t)
=
f(
reliability,
competence,
alignment,
availability,
history
).
\]
当 Agent 把某个结构 \(C\) 委托给 \(A_j\) 时，它实际上建立的是
\[
C
\xrightarrow{\mathrm{delegation}}
A_j
\xrightarrow{\mathrm{return}}
\widehat C.
\]
该过程的可靠性不只由存储介质决定，而由另一主体的能力和意图共同决定。

这说明 Other Agent 不能被简单降格成``远程数据库''。社会性记忆的特殊性就在于载体本身会解释、重构甚至拒绝返回结构。一个人类专家被委托保存某种知识，几年以后可能已经改变理解；一个组织可能改变制度；另一个 AI Agent 可能升级模型。因此社会性外部记忆必须同时保存 ``我把什么交给了谁'' 和 ``我为什么相信他仍然能够正确返回''。

可以写成：
\[
m_{\mathrm{social}}
=
(C,
A_j,
T_{A\to A_j},
Contract,
Context,
Verification).
\]
其中 Contract 不一定是法律意义上的合同，而可以是稳定协议、角色关系或调用接口。只有当这种关系具备长期可恢复性时，它才构成真正意义上的社会性外部记忆。

这与人类社会非常接近。个人并不需要知道整个社会的全部知识，而是知道 ``医生知道什么''、``工程师负责什么''、``某个机构保存什么记录''。成熟社会依赖的是认知分工和信任网络，而不是每个人的大脑无限增长。因此从 AgentOS 角度，群体智能的重要基础不是多个 Agent 同时说话，而是形成一个：
\begin{statementbox}
DistributedRecoverableCognitiveStructure
\end{statementbox}
即认知结构被分布保存到不同主体，并通过角色、协议和信任关系维持可恢复性。

这里也能看到社会性外部记忆和组织结构之间的潜在连接。如果某类 CSO 长期稳定地由某个 Agent 负责，那么这种反复委托关系会逐渐形成角色；角色进一步稳定以后则可能形成制度化功能拓扑。本章不展开组织层理论，但必须指出：社会性外部记忆是个体 Agent 向更高尺度组织智能过渡的重要接口。

\section{内部--外部修改代价比：结构应该承载在哪里}

内部与外部记忆理论不能停留在分类层面；真正的 AgentOS 必须决定某个结构应该保留在哪里。为此，我们需要建立一个明确的承载成本模型。不同载体之间没有绝对优劣：内部结构访问快、控制强，但会占用有限的模型、记忆和调度资源；外部结构容量大、易共享，却具有检索延迟、权限、版本和可靠性问题。因此，记忆分配本质上是一个长期最优化问题。

对某一认知结构 \(C\)，定义内部承载成本
\[
J_{\mathrm{int}}(C)
=
\alpha_1 C_{\mathrm{write}}
+
\alpha_2 C_{\mathrm{maintain}}
+
\alpha_3 C_{\mathrm{retrieve}}
+
\alpha_4 C_{\mathrm{interference}}
+
\alpha_5 C_{\mathrm{update}},
\]
外部承载成本则为
\[
J_{\mathrm{ext}}(C)
=
\beta_1 C_{\mathrm{offload}}
+
\beta_2 C_{\mathrm{index}}
+
\beta_3 C_{\mathrm{access}}
+
\beta_4 C_{\mathrm{verify}}
+
\beta_5 C_{\mathrm{failure}}
+
\beta_6 C_{\mathrm{security}}.
\]
一个最简单的承载判定是比较
\[
\Delta J(C)
=
J_{\mathrm{int}}(C)-J_{\mathrm{ext}}(C).
\]
若 \(\Delta J>0\)，则外部化具有潜在收益；若 \(\Delta J<0\)，内部保持更合理。

但仅比较静态成本仍不够。关键结构往往具有不同调用频率 \(f_C\)、失效风险 \(r_C\)、未来修改概率 \(p_C\) 和身份重要性 \(s_C\)。因此更完整的长期期望成本应写成
\[
\mathbb E[J(C)]
=
f_C J_{\mathrm{access}}
+
p_C J_{\mathrm{modify}}
+
r_C J_{\mathrm{failure}}
+
s_C J_{\mathrm{identity}}.
\]
对于极高频、低容量、强实时结构，内部化通常更合理；对于低频、大容量、可稳定索引结构，外部化通常具有优势；对于身份核心、价值核心和高安全结构，即使外部化成本较低，也可能由于 \(J_{\mathrm{identity}}\) 或安全项过高而必须保留内部冗余。

这一理论解释了为什么成熟智能不应追求``全部记住''或``全部外包''。过度内部化会导致认知拥塞，过度外部化则会造成依赖脆弱和身份空心化。真正合理的是根据结构性质形成分层承载。例如一个 Skill 的完整执行细节可以外化，但核心能力索引、调用条件和失败处理必须内部保留；一个复杂知识库可以外置，但与当前价值和身份高度相关的摘要结构仍应进入 \(\Theta\) 或 \(\Psi\) 附近。

这一思想与计算机存储层级具有某种相似性：寄存器、缓存、内存、磁盘和网络存储并非谁替代谁，而是根据频率、延迟与成本组成层级。但 AgentOS 比普通存储系统多出一个关键维度：\textbf{语义与身份重要度。} 一个信息即使访问频率极低，也可能因为属于``我是谁''而不能简单迁移到外部。反过来，一个高频但机械的动作如果已经稳定，也可能通过技能编译转移到更低层执行结构。

因此，内部--外部记忆分配可以被概括成：
\[
\boxed{
CarrierSelection
=
\arg\min_{b\in\mathcal B}
\mathbb E[J(C,b)]
}
\]
其中 \(\mathcal B\) 是所有可用承载位置。这个形式为后续 Boundary 和 Offloading 提供了一个清晰的理论基础：边界不是人为划线，而是一个持续进行的结构承载决策。

\section{Boundary：内部与外部不是固定边界}

当 Agent 具有内部记忆 \(M_{\mathrm{int}}\) 和外部认知世界 \(M_e\) 之后，必须引入一个动态 Boundary 决定结构如何跨越二者。如果没有 Boundary，外部化只能依靠开发者预先写死规则；而真正长期 Agent 应根据任务、风险、成本和自身状态动态决定：什么继续保持内部，什么部分外移，什么只保留摘要，什么交给工具或他者。

此前我们曾用
\[
B_t(m)
=
(d,\alpha,\pi)
\]
表示对某个结构 \(m\) 的边界决策，其中 \(d\) 是迁移方向，\(\alpha\in[0,1]\) 表示外部迁移比例，\(\pi\) 表示内部保留策略。这个形式非常重要，因为认知结构迁移通常不是二元的 ``inside/outside''。例如一个复杂项目可以把完整文档外置，但在内部保留目标、关键约束和索引；一个 Skill 可以把执行细节外化，同时保留调用条件和失败处理；一个社会性委托可以把任务交给其他 Agent，但仍保留监督责任。

因此，Boundary 的输出不是
\[
B(C)\in\{\mathrm{internal},\mathrm{external}\},
\]
而更适合写成分解：
\[
C
=
C_{\mathrm{core}}
\oplus
C_{\mathrm{index}}
\oplus
C_{\mathrm{payload}},
\]
然后分别决定
\[
B(C_{\mathrm{core}}),
\quad
B(C_{\mathrm{index}}),
\quad
B(C_{\mathrm{payload}}).
\]
这一结构解释了为什么真正有效的认知卸载必须``留下一根线''。如果完整结构被外化而内部没有索引，Agent 未来甚至不知道自己曾经拥有这段记忆；这不再是 offloading，而接近遗失。

Boundary 还必须具有方向性。外部结构可以重新内化：
\[
M_e\rightarrow h,
\]
内部结构也可以被外化：
\[
h/E/\Theta\rightarrow M_e.
\]
因此 Boundary 不是防火墙意义上的单向过滤器，而是一个双向认知膜。它类似细胞膜的地方不在于生物形态，而在于：边界本身通过选择性交换维持系统内部秩序。

从数学上，可以定义跨边界记忆流
\[
J_{i\rightarrow j}(t)
=
b_{ij}(t)\lambda_{ij}(t)\Phi_{ij}(C,t),
\]
其中 \(b_{ij}\) 表示边界是否允许该方向，\(\lambda_{ij}\) 表示当前迁移强度，\(\Phi_{ij}\) 则表示实际结构转换函数。于是 Boundary 的真正作用不是运输，而是控制哪些迁移通道可以打开。

边界控制还受到工作记忆状态影响。当 \(h(t)\) 接近容量上限时，外化倾向应该增加；当外部资源失效、网络不可用或安全条件下降时，Agent 又可能需要暂时内部化更多结构。因此：
\[
B_t
=
B(
h_t,
Goal_t,
Risk_t,
M_e(t),
Capacity_t
).
\]
这进一步说明认知边界本身是一个动态状态，而不是软件架构图上固定画出的边框。

\section{内部与外部记忆的双向流动}

到这里，我们已经可以把内部--外部记忆看成一个真正的动力系统，而不是两个存储桶。内部结构不断沉降到外部，外部结构又不断被召回、解释并重新进入当前认知。由此产生的核心过程可以概括成：
\[
M_{\mathrm{int}}
\leftrightarrow
M_e.
\]

为了更具体地描述这一过程，可以写出一个简化的耦合方程组：
\[
\tau_h\dot h
=
F_h(h,E,\Theta,M_e,u_T,x),
\]
\[
\tau_E\dot E
=
F_E(h,E,\Theta,M_e,u_T),
\]
\[
\tau_\Theta\dot\Theta
=
F_\Theta(E,\Theta,M_e,\Psi,u_T),
\]
\[
\tau_e\dot M_e
=
F_e(h,E,\Theta,M_e,B,u_T).
\]
这个方程组并不是最终工程算法，而是表明外部记忆不是外围附属组件，而是可以直接进入 Agent 内部认知动力学的状态变量。

不同方向的流具有不同意义。首先，
\[
h\rightarrow M_e
\]
表示工作记忆的直接卸载，例如将中间结果写入文件、数据库或程序。其次，
\[
E\rightarrow M_e
\]
表示经验外化，例如把成功轨迹编译成 Skill、操作文档或日志。再次，
\[
\Theta\rightarrow M_e
\]
表示稳定结构外化，例如将规则写成程序、把知识组织成数据库、把长期能力变成工具。反方向
\[
M_e\rightarrow h
\]
则是检索、工具结果、环境观测或他者反馈重新进入当前显式认知。

还有一种容易忽略的过程：
\[
M_e\rightarrow E/\Theta.
\]
外部信息被多次使用以后，可以重新形成内部经验或长期结构。例如 Agent 反复调用某个外部工具，逐渐学习其典型行为和限制，最终在 \(\Theta\) 中形成工具模型。也就是说，外部结构并不会永久保持外部；当访问频率、重要性或实时需求提高时，它可以被重新内化。

因此，内部--外部记忆具有类似缓存层级的动态交换，但比缓存更复杂，因为迁移过程中可能发生结构变换：
\[
C_{\mathrm{internal}}
\not\equiv
C_{\mathrm{external}}.
\]
内部表示可能是抽象语义图，外部表示可能是 JSON、文件、代码或环境结构。真正需要保持的是语义关系和恢复条件，而不是字节级一致。

可以定义结构保真度
\[
Q_{\mathrm{migration}}
=
\mathrm{Sim}_{semantic}
(
C_{\mathrm{before}},
\mathrm{Recover}(C_{\mathrm{after}})
),
\]
以衡量一次外化是否保留了未来需要的认知结构。如果 \(Q_{\mathrm{migration}}\) 太低，即使存储成功，认知上也可能已经发生不可逆损失。

这表明一个成熟 AgentOS 的外部记忆系统必须同时管理 ``流量'' 与 ``语义保真''。仅仅拥有高速数据库并不能解决问题；真正重要的是，结构能否跨边界迁移而不失去未来可用性。由此，记忆管理第一次从 ``save/load'' 升级为 ``structure migration''。

\section{外部记忆的恢复、版本、权限与生命周期}

一旦 Agent 把重要认知结构外化，随之而来的问题就是：这些结构如何在几个月、几年甚至更长时间后仍然可靠返回。传统短期 Agent 通常不面对这一问题，因为 Session 结束以后状态可以全部丢弃；长期 Agent 则必须把 External Memory 当成生命周期基础设施。

首先是索引。外部记忆必须具有多层索引：
\[
I
=
I_{\mathrm{semantic}}
\oplus
I_{\mathrm{temporal}}
\oplus
I_{\mathrm{relational}}
\oplus
I_{\mathrm{task}}
\oplus
I_{\mathrm{source}}.
\]
只有语义相似度索引往往不足以恢复复杂结构。例如一个项目文档可能语义上与多个版本高度相似，但时间索引和任务上下文决定了真正应该取回哪一份。

第二是版本。定义对象的版本序列
\[
m^{(0)}
\rightarrow
m^{(1)}
\rightarrow
\cdots
\rightarrow
m^{(k)}.
\]
Agent 必须知道当前任务需要的是``最新状态''还是``某个历史状态''。否则所谓记忆会不断被当前版本覆盖，导致过去经验无法重建。

第三是权限。外部记忆可能位于共享空间、组织系统或其他主体控制之下，因此可访问性本身具有动态性：
\[
P_{\mathrm{access}}(m,t)
\neq
\mathrm{constant}.
\]
Agent 不能把``当前可访问''当成``永久可访问''。对于身份关键或长期关键结构，系统必须考虑冗余、备份或内部摘要。

第四是完整性与来源。外部结构重新进入 h 时必须附带 provenance：
\[
Provenance(m)
=
(source,
time,
version,
author,
transformations).
\]
否则 Agent 可能把自己几年前的推测误认为已经验证的事实，或者把其他 Agent 修改过的内容误认为自身原始经验。

第五是生命周期管理。外部记忆也不能无限增长。系统需要定期进行压缩、归档、淘汰和结构重组。但与普通存储清理不同，删除一个外部记忆可能破坏未来的自我连续性或任务恢复，因此淘汰函数必须考虑：
\[
U_{\mathrm{retain}}
=
f(
future\ usefulness,
identity\ relevance,
dependency,
reconstructability,
storage\ cost).
\]
只有当未来价值低、依赖关系弱且可重建性高时，彻底删除才具有较低风险。

因此，External Memory Manager 不只是数据库管理器，而是一个管理认知结构跨时间连续性的系统。它必须支持版本、权限、来源、索引、备份、恢复和生命周期策略。这也是为什么 AgentOS 最终不能只在 LLM 上外挂一个向量库便称为拥有长期记忆：真正的长期记忆意味着\textbf{跨时间维持结构可恢复性的工程责任}。

\section{内部--外部记忆统一原理：从“拥有知识”到“拥有结构访问能力”}

现在我们可以回到本章最重要的理论结论。传统 AI 往往把能力理解成模型内部已经保存了多少知识，而 AgentOS 的长期智能理论迫使我们采用不同标准：一个 Agent 的有效认知能力，不等于内部参数和记忆之和，而取决于它能够在有限时间内可靠重新访问多少结构，以及能否把这些结构重新组织到当前任务中。

因此，可以定义 Agent 的有效记忆空间：
\[
M_{\mathrm{eff}}^A(t,\Delta)
=
M_{\mathrm{int}}^A(t)
\cup
\mathrm{Reachable}
(
M_e^A,
\Delta
),
\]
其中 \(\Delta\) 是当前任务允许的访问时间窗口。一个结构虽然理论上存在于外部世界，但如果需要数月才能重新找到，对秒级任务而言它并不属于有效记忆；相反，一个远端服务如果毫秒级可靠返回，其认知距离可能比本地冷存储更近。

这说明内部--外部边界应该进一步用``认知距离''而非物理距离描述。可以定义
\[
\fitdisplay{
d_{\mathrm{cog}}(C)
=
f(
latency,
retrieval\ uncertainty,
semantic\ reconstruction,
verification\ cost,
authority\ cost
).
}
\]
于是所谓``内部''和``外部''实际组成一个连续谱：工作记忆具有最低认知距离，结构记忆稍远，内部持久存储进一步增加恢复成本，稳定工具和数据库更远，而未知互联网资源或陌生 Agent 则具有更高认知距离。

从这个视角，成熟智能的发展不是简单让
\[
M_{\mathrm{int}}\rightarrow\infty,
\]
而是同时进行两件事：
\[
\mathrm{CoreInternalStructure}\rightarrow
\mathrm{compact\ and\ stable},
\]
以及
\[
\mathrm{ReachableExternalStructure}
\rightarrow
\mathrm{large\ and\ well\ indexed}.
\]
这与人类文明的发展极为相似：个体大脑容量并没有随着文明知识爆炸同比增长，但书籍、数据库、工具、制度和专家网络使个体能够调用的认知结构急剧扩大。

如果采用本书后期逐渐形成的 CSO 语言，本章的全部内容还可以进一步压缩成一句话：
\begin{conclusion}
内部记忆与外部记忆的区别，本质上是 Agent-CSO 的承载位置与恢复路径不同。
\end{conclusion}
一个结构可以从 \(h\) 沉降进 \(E\)，从 \(E\) 抽象进 \(\Theta\)，也可以从内部迁移到 Me；只要语义连续性、索引与恢复机制得到保持，它仍然可以参与同一主体的未来认知过程。

因此，真正需要保护的不是``字节留在内部''，而是
\[
\boxed{
StructuralContinuity
+
Recoverability
+
RealityVerification
}.
\]
这三个条件共同决定一次认知卸载究竟是成熟学习，还是不可逆遗失。

本章由此完成了 AgentOS 记忆理论从三相内部记忆向完整内外记忆体系的扩展。至此，一个持续 Agent 已经不再被限制在自身参数和内部存储中，而开始拥有一个可治理、可访问、可外化、可重新内化的外部认知世界 \(M_e\)。这个结论也为后续讨论具身环境、社会性协作以及更加一般的结构迁移奠定了基础，但在当前层级，我们应当把最核心的原则固定下来：

\begin{proposition*}
长期智能并不要求把世界装进自身；
它要求自身能够稳定地知道哪些结构必须内化，
哪些结构可以外化，
以及如何在需要时让外部结构重新成为当前认知的一部分。
\end{proposition*}

更形式化地：

\[
\boxed{
AgentMemory(t)
=
M_{\mathrm{int}}(t)
\bowtie
B_t
\bowtie
M_e(t)
}
\]

其中 \(M_{\mathrm{int}}\) 保存主体内部连续性，\(M_e\) 扩展主体可调用结构空间，而动态 Boundary \(B_t\) 决定结构如何在两者之间迁移。对持续智能而言，\textbf{记忆因此不再是一个仓库，而是一套跨时间、跨载体维持认知结构连续性的动力系统。}
