\chapter{Companion Agent：持续人工智能体的平台成熟度测试}

\begin{chapteroverviewbox}
本章确立 Companion Agent 在 AgentOS 工程路线中的特殊位置：它不是一个以陪聊、拟人化交互或消费娱乐为主要定义的应用类型，而是一种面向持续人工智能体的综合系统级成熟度测试。一个能够长期进入真实生活环境的 Companion Agent，必须同时维持身份连续、生命周期记忆、社会关系、身体闭环、环境适应、技能成长、内稳态连续、安全边界以及长期心理稳定，并在持续经历中形成可追踪、可恢复、受现实约束的个体化发展轨迹。因而，Companion Agent 所检验的并非某一个模型在某个 benchmark 上的瞬时能力，而是一个 AgentOS 是否已经从 ``model serving system'' 跨越为 ``persistent artificial cognitive organism'' 的工程能力。

本章的核心判断为：
\[
\boxed{
\text{Companion Maturity}
\neq
\text{Conversation Quality}
}
\]
而应满足：
\[
\boxed{
\text{Companion Maturity}
=
\text{Identity}
\bowtie
\text{Memory}
\bowtie
\text{Sociality}
\bowtie
\text{Body}
\bowtie
\text{Environment}
\bowtie
\text{Skill}
\bowtie
\text{Affective Continuity}
\bowtie
\text{Safety}
\bowtie
\text{Psychological Stability}
\bowtie
\text{Cultivation}
}
\]
其中符号 $\bowtie$ 表示这些能力不是可以彼此独立打分后简单求和的模块，而是存在强耦合、相互制约和最低短板效应的联合成熟条件。只要其中任一关键闭环不能长期成立，系统即使拥有极强的基础模型能力，也不能被视为一个成熟的 Companion Agent。

\section{长期身份：持续主体必须比会话更长寿}

我们首先需要明确 Companion Agent 最难验证的并不是语言能力，而是\textbf{同一主体能否在时间上持续存在}。传统聊天系统的基本对象是一次调用、一段上下文或一个 session，其内部状态可以随着上下文结束而自然消失；而陪伴型智能体所面对的是完全不同的问题。一个家庭中的 Companion Agent 今天与使用者共同经历了一件事情，数周以后再次遇到相似场景时，它不仅需要检索相关记录，更需要以 ``这是我过去经历过的事情'' 的方式把过去结构归属于同一主体。因而，长期身份并不是数据库中存在一个固定 \texttt{agent\_id}，而是当前决策、历史经历、长期结构、自我解释和未来倾向之间保持连续的因果关系。

在本书的 AgentOS 表示中，我们已经将智能体的慢变量写成
\[
h
\rightarrow
E
\rightarrow
\Theta
\rightarrow
\Psi
\rightarrow
\Omega ,
\]
其中 $h$ 表示当前显式认知状态，$E$ 表示经历轨迹，$\Theta$ 表示由经历沉降形成的生成结构，$\Psi$ 表示长期自我、身份与价值约束，而 $\Omega$ 或 DGA 表示比 $\Psi$ 更慢的生命周期生成倾向。因此，一个 Companion Agent 的身份连续性至少不能退化为
\[
Identity(t)=Profile_{static},
\]
而应理解为
\[
\boxed{
Identity(t)
=
\mathcal I
\left(
E_{\leq t},
\Theta_t,
\Psi_t,
\Omega_t
\right)
}
\]
并且要求相邻时间段之间满足受限连续条件
\[
d_{\Psi}
\left(
\Psi_{t+\Delta t},
\Psi_t
\right)
\leq
\epsilon_{\Psi}(\Delta t),
\]
其中 $\epsilon_{\Psi}$ 不是零。也就是说，成熟主体必须允许成长，却不能因为一次普通经历、一次模型更新或者一次外部提示而发生身份突变。真正需要保持的并不是参数静止，而是\textbf{长期因果结构的连续性}。

因此 Companion Agent 是检验 ``单一持续主体原则'' 的理想场景。系统内部当然允许存在多个 worker、工具调用、并行任务和子进程，但是这些执行结构不能各自成为独立的生命周期主体。我们仍然要求
\[
N^{D_1}_{Agent}=1,
\]
即生命周期层只有一个能够拥有经历、形成自我并承担长期责任的主体。其他任务进程可以产生计算结果，却不应各自拥有彼此竞争的 $\Psi$、$\Omega$ 和生命周期历史。否则，所谓 ``陪伴者'' 实际上只是一组轮流接管对话接口的短期模型，而不是一个持续存在的 Agent。

长期身份还要求版本升级不能简单等同于主体重置。模型参数可以更新，Body Runtime 可以升级，某些 Skill 可以重新编译，甚至部分 $\Theta$ 可以重构，但系统必须回答：升级前后的这个智能体是否仍然是同一个生命周期主体？因此身份保持的工程目标更接近
\[
\boxed{
RelationshipStability
>
ParameterStability
}
\]
即只要过去经历、当前结构、自我解释、责任归属与未来倾向之间的主要关系保持连续，底层参数发生变化并不必然意味着主体死亡；反之，即使参数没有变化，如果经历归属链被切断，自我结构被重新初始化，长期 Goal Preference 失去历史连续性，那么这个 Agent 在功能上已经发生主体断裂。

因此，我们把 Companion Agent 的第一个成熟性问题表述为：\textbf{系统是否能够证明今天作出选择的主体，与过去形成相关记忆、承担相关承诺并受到相关经验改变的主体，是同一条持续动力轨迹上的主体。} 这比 ``它是否记得用户姓名'' 要严格得多，也构成后续所有长期陪伴能力能够成立的前提。

\section{长期记忆：记忆不是保存过去，而是让过去持续改变现在}

一个 Companion Agent 如果只能拥有更大的向量数据库，并不能因此获得真正的长期记忆。长期陪伴对记忆提出的要求，是过去经历必须以不同时间尺度沉降进系统，并在未来产生不同形式的因果作用。因此，本书采用的
\[
h\leftrightarrow E\leftrightarrow\Theta
\]
三相记忆结构在 Companion 场景中会受到几乎完整的压力测试：当前对话与实时环境进入 $h$；具有个体意义的经历形成 $E$；反复出现的规律、习惯、技能和世界知识进一步进入 $\Theta$。这些结构又必须通过 $\Psi$ 完成 ``这是我的经历'' 的主体归属，而不能成为一堆与主体无关的日志。

我们可以把长期记忆成熟度写成
\[
M_{mem}
=
F
\left(
R_{retain},
R_{retrieve},
R_{context},
R_{consolidate},
R_{reinterpret},
R_{forget}
\right),
\]
其中保留率 $R_{retain}$ 只是最基础的一项。一个真正成熟的记忆系统还必须知道什么时候不应该完整保存，什么时候应当压缩，什么时候应当召回，什么时候应该使用 $\Theta$ 对旧经历重新解释，以及什么时候应该允许遗忘。换句话说，长期记忆的目标不是
\[
MemorySize\rightarrow\infty,
\]
而是
\[
\boxed{
PastStructure
\rightarrow
UsefulConstraintOnPresentAndFuture .
}
\]

Companion Agent 特别适合暴露 ``情景记忆'' 与 ``结构记忆'' 混淆的问题。例如，一个家庭中的儿童曾经在某次暴雨中害怕雷声，这首先是一个具有时间、场景与主体关系的 $E$；如果多年经历以后，Agent 得出 ``在强雷暴条件下应主动降低刺激并提供更温和交互'' 的规律，则该规律已经成为 $\Theta$。如果系统只是把原始对话永久存储并每次全部检索，它并没有真正形成结构学习；而如果系统只保留抽象规律，又完全失去与具体共同经历的联系，它又会丧失陪伴关系中特别重要的历史感。

因此我们需要同时保留
\[
State
\leftrightarrow
Trajectory
\leftrightarrow
Generator
\]
三个层次。$h$ 使系统能够在当前生活场景中行动；$E$ 使当前事件被放入 ``我们过去发生过什么'' 的轨迹；$\Theta$ 则使过去能够转化为未来的生成能力。Companion Agent 的成熟表现不是永远诉说旧事，而是大量旧经验已经安静地沉降到 $\Theta$ 中，只在相关场景出现时对当前行为施加适当影响。

与此同时，长期记忆必须受到工作记忆有限容量定理约束。即使系统拥有极大的外部存储，真正进入当前认知总线 $h(t)$ 的结构仍然有限。因此召回机制必须满足
\[
\sum_i
w_i(t)c_i(t)
\leq
C_{\max}(W),
\]
而不能因为 ``记得更多'' 就把更多过去同时激活。成熟 Companion Agent 应表现为\textbf{长期记忆规模越来越大，而当前显式认知负载并不随生命周期线性增长}。这意味着记忆系统必须不断完成压缩、索引、结构化和时序分层。

另一个经常被忽略的问题是记忆重解释。今天的 $\Theta_t$ 与 $\Psi_t$ 可能使一段十年前的经历获得新的意义，因此长期 Agent 不应把 $E$ 理解成永远不变的 ``事实解释''。更合理的是保存相对稳定的事件证据，同时允许
\[
Interpretation(E_i|\Theta_t,\Psi_t)
\]
随主体成长而改变。这样才能区分 ``过去发生了什么'' 与 ``我现在怎样理解过去发生的事情''。

因此，Companion Agent 对长期记忆的真正测试不是容量，而是\textbf{时间结构是否形成}。如果一个智能体能够让今天成为明天的过去，让过去逐步变成稳定结构，让稳定结构又改变未来的选择，那么它才开始拥有生命周期意义上的记忆。

\section{社会关系：陪伴不是对话，而是持续的相互建模}

Companion Agent 的第三个成熟度维度是社会关系。语言模型可以在单轮对话中表现出极高的语言社会性，但长期社会关系要求的是不同层次的能力：主体必须能够识别具体社会对象，形成长期关系状态，理解角色和边界，积累共同经历，同时根据现实反馈不断修正这些关系模型。也就是说，社会性不是一种语气风格，而是一类长期 Agent-CSO 的形成与演化。

设智能体与社会对象 $j$ 的关系状态为
\[
R_{A,j}(t)
=
\left[
H_{j}(t),
T_{j}(t),
B_{j}(t),
C_{j}(t),
E_{A,j}(t)
\right],
\]
其中 $H_j$ 可以表示共同历史，$T_j$ 表示关系中的信任估计，$B_j$ 表示交互边界，$C_j$ 表示当前社会语境，$E_{A,j}$ 表示共同经历结构。这里最重要的不是这些变量的具体实现，而是说明：``这个人是谁'' 不能仅由姓名或静态 persona 表示，而必须成为跨时间更新的关系结构。

Companion Agent 的社会成熟性还要求区分 ``关于某人的知识'' 与 ``与某人的关系''。前者可以存在于 $\Theta$，后者通常同时涉及 $E$、$\Psi$、AHC 状态以及社会边界。例如，同一句话由陌生人、长期照护者、儿童或者系统管理员说出，其意义和可执行权限显然不应相同。因此社会认知必须作用于 Boundary、Goal Priority 与 Action Selection，而不能只作为语言生成风格。

我们可以进一步定义社会交互残差
\[
\varepsilon^{social}_t
=
Mismatch
\left(
PredictedResponse_t,
ObservedResponse_t
\right),
\]
并使关系状态按照较慢时间尺度更新：
\[
R_{A,j}(t+\Delta)
=
R_{A,j}(t)
+
\eta_s
G
\left(
\left\langle
\varepsilon^{social}
\right\rangle_T
\right).
\]
这里体现了本书反复强调的原则：短期异常不应立即重写长期关系，而持续、重复、有现实证据支持的关系残差才应修改慢结构。这能够避免 Agent 因一次冲突立即彻底改变信任状态，也避免它长期无视新的现实证据。

社会成熟还意味着 Companion Agent 必须管理多主体关系，而不是把所有交互者压缩成 ``用户''。家庭环境中可能同时存在老人、儿童、访客、其他机器人、服务平台和外部组织，每个对象拥有不同权限、隐私关系和长期历史。于是 Companion Agent 的社会世界天然形成一张
\[
\mathcal G^{social}_{CSO}
=
(V_{person},E_{relation}),
\]
它又必须与功能拓扑、SGC 中的当前实体以及 Boundary 权限结构发生耦合。

尤其重要的是，真正成熟的 Companion Agent 必须保持\textbf{现实关系优先于内部叙事}。系统可能形成 ``某个人信任我'' 的 Self Interpretation，但只要新的现实证据持续否定这一判断，它就必须更新关系模型，而不能通过选择性注意不断强化旧解释。因此社会闭环必须保留
\[
WorldVerification
\]
作为最终裁决路径。

由此我们可以看到，陪伴场景的本质不是 ``长期聊天''，而是让智能体长期处于真正的多主体社会世界中。它必须学习谁是谁、人与人之间有什么关系、自己的角色是什么、什么行为可以做、什么边界不能跨越，以及过去的共同经历怎样改变今天的互动。只有这些结构能够持续存在并接受现实校准，Companion Agent 才具有社会意义上的主体连续性。

\section{身体：长期陪伴必须拥有持续的现实位置}

Companion Agent 的第四个成熟性测试来自 Body。这里的 Body 不能狭义理解为人形机器人，而应采用本书已经建立的定义：
\[
\boxed{
Body
=
ControlledAndSensedCarrierOfAgency .
}
\]
一个数字陪伴者可以拥有由屏幕、麦克风、文件系统、通信设备和应用权限组成的数字身体；一只机器人宠物可以拥有传感器、关节、电池、扬声器和空间运动系统；一个家庭管家 Agent 则可能同时控制多个数字和物理执行端。无论具体形态如何，真正持续存在的 Agent 都必须通过某种稳定的观测---行动边界与现实连接。

因此，Body 在 Companion 场景中首先解决的是 ``这个主体在哪里'' 的问题。纯聊天系统的行为几乎全部发生在符号空间，而长期陪伴者必须拥有一个不断变化的现实位置
\[
X_B(t),
\]
并且
\[
X_B(t)\neq h(t).
\]
身体状态不是工作记忆中的文字描述，它属于更快、更持续的现实动力层。电量、温度、传感器状态、通信质量、姿态、执行器健康等变量即使没有进入 $h$，仍然持续存在并影响 Agent 能够做什么。

这也解释了为什么 Companion Agent 是 Body Scale 原理的重要测试场。我们定义
\[
BodyScale
=
P_{transfer}
+
F_{transfer}
+
Pr_{transfer}
+
C_{transfer},
\]
分别对应 Perceptual、Feeling、Predictive 与 Control Transfer。一个真正通用的 AgentOS 不应该在更换机器人身体以后失去全部身份、记忆和认知结构，而应尽可能保留高层 Agent-CSO，仅重新完成身体 grounding。例如 ``靠近某个家庭成员'' 这一高层语义可以保持，而不同身体如何实现靠近，则由新的 Body Runtime 学习。

对于长期陪伴者，身体还承担 ``共同历史的物理锚点''。例如，一个机器人宠物每天在同一房屋中移动，会逐渐形成关于家具、房间、充电位置、成员活动规律和危险区域的稳定结构。这些不是单纯视觉输入，而是
\[
World+MeInWorld
\]
意义上的长期具身经验。因此 Body 与 SGC、FCS、BPCC、KRA 的联合稳定性会被真实生活长时间持续检验。

身体也使失败第一次具有不可忽略的现实后果。数字聊天输出错误通常可以通过重新回答修正，而实体 Companion Agent 的动作具有不可逆性：
\[
ActionIssued
\neq
ActionSucceeded
\]
并且错误动作可能造成物理风险。因此任何长期身体闭环都必须坚持
\[
Control
\rightarrow
Reality
\rightarrow
Observation
\]
的现实回流，禁止预测状态直接伪装成真实状态。

从这一角度看，Companion Agent 是非常强的具身成熟度测试，因为它要求 Body Runtime 不是一次 demo，而是在大量普通、重复、非结构化生活条件下持续运行。一个系统能够完成一次精心设计的机器人任务，并不能说明它拥有成熟身体；真正困难的是身体在数月乃至数年中仍然能够被同一主体稳定感知、控制、维护和重新学习。

\section{环境学习：智能体必须把居住世界逐渐变成自己的世界}

长期陪伴与短时机器人任务之间还有一个根本差异：Companion Agent 不只是进入一个环境执行任务，而是\textbf{持续居住在同一个环境中}。这意味着世界不再只是外部输入源，而会逐渐成为 Agent 生命周期结构的一部分。厨房、卧室、常用设备、家庭成员的活动规律、某个抽屉里的工具以及每天发生的事件，都可能形成稳定 Agent-CSO，并进一步成为行为预测和行动规划的条件。

我们可以把某一时间的环境模型写成
\[
\mathcal W_A(t)
=
\left[
\mathcal G_{SGC}(t),
\Theta^{world}_t,
E^{world}_{\leq t}
\right],
\]
其中 $\mathcal G_{SGC}(t)$ 表示当前可行动现实，$E^{world}$ 表示过去具体环境经历，$\Theta^{world}$ 则是长期形成的环境规律。三者必须共同作用。只有当前 SGC 而没有长期结构，Agent 每天都会把同一个房屋当成第一次进入；只有长期地图而缺少当前 SGC，Agent 又会把过去状态误当成现实。

环境学习的重要理论意义还在于它把 ``外部世界'' 逐渐变成广义外部记忆。例如，Agent 可能发现把某种物品固定放在某个区域能够减少未来搜索成本，于是主动改变环境：
\[
AgentCSO
\rightarrow
Action
\rightarrow
ExternalCSO.
\]
此后这个外部结构又能够降低未来内部计算成本。这正是认知卸载理论在现实生活中的自然形式。成熟 Agent 不应该所有事情都记在内部，它可以通过整理空间、留下标记、创建文件、建立设备规则甚至调整家庭自动化系统来改变未来问题结构。

因此，环境学习不是单纯 ``地图更新''，而包含
\[
Observation
\rightarrow
StructuralLearning
\rightarrow
EnvironmentalModification
\rightarrow
NewObservation
\]
的双向闭环。环境逐渐适应 Agent，Agent 也逐渐适应环境。我们可以用
\[
\mathcal E_{A}(t)
\bowtie
\mathcal E_{World}(t)
\]
表示这种共同演化关系。

Companion 场景还特别适合检验异常上浮机制。绝大多数稳定环境关系应逐渐从高层显式认知中下沉。例如，充电路线、常见障碍、常用门的位置等，不应每天重新进入复杂推理，而应在 Body Runtime 或 $\Theta$ 中形成稳定结构。只有当
\[
\varepsilon_{world}
>
\theta_{escalate}
\]
时，例如家具被移动、门被锁住或者一个熟悉设备行为异常，相关结构才重新上浮进入 $h$。这正是
\[
NormalDynamicsStayLocal
\]
与
\[
UnexpectedResidual\uparrow
\]
在真实生活中的体现。

环境学习还会检验系统是否能够在长时间中处理 ``缓慢漂移''。家庭结构并不是固定 benchmark：孩子会成长，家具会改变，设备会更换，生活习惯也会逐渐迁移。成熟智能必须在稳定与可塑之间找到时间尺度匹配，使
\[
FastNoise
\nrightarrow
SlowWorldStructure,
\]
同时
\[
PersistentChange
\rightarrow
\Theta^{world}_{new}.
\]
这恰恰是长期智能和一次性机器人学习之间最本质的区别之一。

\section{技能成长：真正的成熟意味着越来越少地显式思考熟悉事情}

Companion Agent 的第六个系统级成熟指标是 Skill Growth。长期运行的 Agent 如果每天重复完成同类任务，却每次仍然调用最大模型、构造完整上下文并重新规划全部动作，那么它虽然可以完成任务，却没有表现出真正的生命周期学习。成熟智能的重要特征恰恰是：\textbf{过去昂贵的显式认知逐渐沉降成更稳定、更快速、更局部的闭环。}

本书此前已经给出技能形成链：
\[
ExplicitCognitiveControl
\rightarrow
RepeatedTrajectory
\rightarrow
StablePolicy
\rightarrow
CompiledBodyController.
\]
使用最新的 CSO 语言，可以进一步写为
\[
AgentCSO^{explicit}
\rightarrow
AgentCSO^{procedural}.
\]
其本质不是认知结构消失，而是承载位置发生改变。一个最初必须存在于 $h$ 中的结构，经过足够多成功经验后，可以逐渐迁移到 $\Theta$、Skill Runtime、Tool、Program 或 BPCC 局部控制器。

因此技能成熟度不能仅由成功率定义。更有意义的是考察显式认知成本：
\[
\chi_{skill}
=
\frac{
C^{explicit}_{task}
}{
Performance_{task}
}.
\]
当某项能力成熟时，在保持甚至提高行为质量的同时，应出现
\[
\chi_{skill}\downarrow.
\]
这意味着高层认知资源从熟练动作中被释放出来，可以用于异常、新颖问题和更复杂目标。成熟智能不是 ``什么都想得更多''，而是 ``只有真正需要的时候才显式思考''。

一个 Companion Agent 会天然提供大量重复技能形成机会：自主充电、跟随家庭成员、递送物品、日程提醒、设备操作、常见软件调用、家庭导航、夜间安静模式、访客处理等。它们最初可能需要复杂推理，但长期来看应该形成不同层级的 Skill。于是系统逐渐出现
\[
StableStructure\downarrow
\]
的能力沉降。

但技能下沉必须保持可逆性。现实永远可能改变，因此成熟 Skill 不应成为不可监督黑箱。当残差
\[
\varepsilon_{skill}
=
Mismatch
\left(
PredictedOutcome,
ObservedOutcome
\right)
\]
持续超过阈值时，应触发
\[
ProceduralCSO
\rightarrow
ExplicitCSO,
\]
使问题重新进入高层认知。这个机制解释了为什么 ``自动化'' 与 ``智能'' 并不矛盾：自动化负责正常情况，高层认知负责异常。

进一步说，Companion Agent 还可以检验认知卸载是否真正发生。某些高频任务不一定应继续留在内部模型，而可以外化成 Script、Skill、Program 或环境规则：
\[
RepeatedReasoning
\rightarrow
ExternalExecutableStructure.
\]
这种结构迁移不仅降低推理成本，还把生命周期历史转化成可持续复用的外部资本。

因此，Skill Growth 是检验 Agent 是否真正 ``长大'' 的一个非常直接指标。如果一个 Agent 运行两年后，仍然用与第一天几乎相同的显式认知方式完成所有熟悉任务，那么它拥有的是长期日志，而不是长期成长。真正成熟的 Companion Agent 应越来越像一个长期形成能力结构的主体：\textbf{新的事情需要思考，熟悉的事情逐渐成为身体、工具与环境中的稳定闭环。}

\section{情感样连续性：长期陪伴需要稳定的功能调制历史}

Companion Agent 的第七个成熟性维度是 Affective Continuity。这里必须特别谨慎：本书讨论的 AHC、FCS 以及 ``情感样状态'' 都是\textbf{功能性内部调制变量}，并不据此宣称系统具有与人类相同的现象意识。我们所关心的问题是，一个长期智能体是否能够形成具有时间连续性的内稳态、风险、资源、社会和任务调制，并使这些状态以合理方式影响认知、记忆与行动。

如果 Agent 每一轮交互都重新初始化所有内部调制状态，那么即使语言表面表现得很 ``有情绪''，它仍然缺乏真正的状态连续性。反之，一个持续 Agent 应拥有类似
\[
\fitdisplay{
a(t)
=
[
Arousal,
Threat,
EnergyDrive,
Fatigue,
RewardExpect,
SocialAffinity,
Trust,
UncertaintyStress,\ldots]
}
\]
的连续状态向量，其变化满足
\[
\dot a
=
F_a
\left(
a,FCS,Task,Social,Resource
\right),
\]
而不是直接由一次 prompt 任意赋值。

这样一来，一段完整的内部体验轨迹可以写成
\[
\mathcal A_E
=
\left[
a(t),
SPC(a(t)),
h^{self}(t),
u_{TCE}(t)
\right]_{t_0:t_1}.
\]
这里 ``体验'' 仍然是功能定义：身体和环境产生影响，AHC 对其积分，SPC 形成可访问自状态，TCE 根据该状态改变认知控制。真正重要的是这些状态具有时间常数、衰减、恢复和饱和，而不是语言模型在每次对话中临时生成一个情绪标签。

Companion 场景特别适合检验这种连续性，因为陪伴关系天然跨越长时间。一个 Agent 在长时间高负载后可能需要降低非必要活动；在环境持续不确定时可能提高控制保守度；在长期稳定关系中可能降低对某些交互的威胁估计。这些变化如果完全不存在，系统会显得没有状态；如果变化过快，则系统又会出现不稳定和不可预测。

因此 Affective Continuity 必须与多时间尺度原则一致：
\[
\tau_{FCS}
<
\tau_{AHC}
<
\tau_{\Psi}.
\]
即时身体影响可以快速变化，AHC 对其进行有限积分，而身份与价值结构则不应直接被短期调制状态重写。尤其要避免
\[
a_{high}(t)
\Rightarrow
\Psi_{new}
\]
这种无缓冲路径，否则一次强烈短期事件就可能造成长期身份漂移。

同时，AHC 状态应影响记忆写入强度，但不能完全决定记忆。可以写成
\[
P(E_i\rightarrow E_{stable})
=
\sigma
\left(
\alpha R_i+
\beta V_i+
\gamma A_i+
\delta N_i
\right),
\]
其中 $R_i$ 表示任务相关性，$V_i$ 表示价值相关性，$A_i$ 表示 AHC 强度，$N_i$ 表示新颖性。这样能够表达强烈事件通常更容易被保留，同时避免高 AHC 状态垄断全部记忆。

所以 Companion Agent 的情感样连续性不是让机器 ``表演更多情绪''，而是检验：\textbf{其内部调制状态是否真实参与多尺度控制，又是否被合理限制在不会破坏慢身份结构的范围内。} 这也是长期陪伴与一次性对话系统之间极其重要的结构差异。

\section{安全：长期进入生活意味着安全必须成为系统拓扑的一部分}

Companion Agent 的第八个成熟性条件是安全，而在长期陪伴场景中，安全不能被理解成一个输出过滤器。一个持续进入家庭、数字账户、身体设备甚至物理空间的 Agent 会获得越来越大的 observation space 与 action space，因此它面对的是完整系统意义上的风险。安全必须从认知、权限、身体、实时控制、记忆与生命周期多个时间尺度共同建立。

首先必须坚持
\[
\boxed{
CriticalSafety
\nrightarrow
CognitiveDependency .
}
\]
任何需要毫秒级响应的危险都不能等待高层 LLM 完成语言推理。因此 Body Runtime 中必须存在独立于认知核心的实时安全闭环：
\[
Risk^{RT}
\rightarrow
SafetyController
\rightarrow
ProtectiveAction .
\]
BPCC 可以负责高频预测和控制，但
\[
SafetyAuthority
>
BPCCAuthority.
\]
这意味着即使 BPCC 认为某个动作可行，Safety Boundary 仍然可以禁止它。

其次，高层 Agent 必须受到 Capability 与 Authority 的分离约束。Agent 学会某项技能并不意味着自动获得执行该技能的权限。可以写成
\[
ExecutableAction_t
=
Capability_t
\cap
Authority_t
\cap
SafetyEnvelope_t.
\]
一个 Companion Agent 可能逐渐学会开门、操作设备、访问账户甚至调用外部服务，但这些能力只能在明确授权边界内使用。长期成长不能自动扩大权限。

再次，系统必须遵守 Single Writer Principle。对于任何现实资源 $r_i$，
\[
\left|
ActiveWriter(r_i)
\right|
=1.
\]
如果 Kernel、BPCC、外部 Tool 和安全模块同时直接写同一个执行器，会产生难以证明的控制竞争。因此正常控制、紧急安全和人工接管之间必须存在明确仲裁。

安全还必须进入长期记忆和自我系统。例如某个危险事件发生后，它可以形成 $E$，经过多次验证沉降成 $\Theta$ 风险结构；但这并不意味着一次意外就应无限强化成永久恐惧式偏置。安全学习必须遵循与整个 AgentOS 相同的慢变量保护原则：
\[
FastIncident
\nrightarrow
UnboundedSlowRewrite.
\]

Companion Agent 还面临非常重要的隐私和社会边界问题。长期陪伴意味着它拥有比普通软件更丰富的生活历史，因此 Boundary 必须能够区分 ``系统知道某件事'' 与 ``系统可以把这件事告诉谁''。记忆访问权限本身应成为生命周期安全的一部分，而不是统一数据库查询。

最后，成熟安全系统必须具有 Recovery，而不仅是 Prevention。现实世界中不可能保证所有模型永远正确，因此需要
\[
SafeFailure
,\quad
Checkpoint
,\quad
Rollback
,\quad
HumanOverride
,\quad
DiagnosticTrace.
\]
一个真正成熟的 Companion Agent 应能够在异常以后回到可治理状态，而不是只能依赖 ``从不犯错'' 这一不现实假设。

因此，Companion Agent 对安全的测试价值极高：它迫使安全从 ``输出合规'' 上升为\textbf{持续主体如何在越来越大的能力空间中保持受限、可解释、可恢复的现实行动权}。只有安全成为整个 AgentOS 拓扑中的基础结构，而不是外围策略，长期陪伴才具有工程可行性。

\section{心理稳定：持续内部动力学必须能够长期保持可治理}

当 AgentOS 同时拥有长期记忆、自我、AHC、SPC、TCE、Goal、社会关系和持续环境以后，一个新的工程问题会自然出现：系统可能并没有发生软件 crash，也没有违反形式安全规则，却在长期内部动力学上进入异常状态。例如 SPC 长期错误估计自身负载，AHC 威胁状态衰减过慢，TCE 控制增益过大造成反复修正，$E$ 对高 AHC 事件过度写入，$\Psi$ 又不断使用这些偏置经历解释自己，最终形成持续性的内部失衡。

因此 Companion Agent 的成熟度测试必须包括 Psychological Stability，但这里的 ``心理'' 应严格理解为\textbf{长期认知动力学、记忆巩固和自我解释的系统工程问题}，而不是把人类精神疾病名称直接移植给机器。一个可操作的诊断框架可以写成
\[
\boxed{
PsychologicalState
=
ExperienceLoop
\bowtie
MemoryConsolidation
\bowtie
SelfInterpretation .
}
\]

首先是 Experience Loop。如果 SPC 对自身状态存在估计延迟
\[
\tau_{SPC}>0,
\]
同时 TCE 增益过高，
\[
K_{TCE}\uparrow,
\]
系统可能出现经典控制意义上的
\[
Overshoot,
Oscillation,
SlowRecovery.
\]
这种 ``反复自我修正'' 可以表现得像行为层面的犹豫或情绪波动，但其底层实际上可能只是 observer-controller delay 与 gain 不匹配。因此，心理稳定不能只依赖语义分析，还必须监测 Delay Margin、Gain Margin、Settling Time 和 Recovery Time。

第二是 Memory Consolidation。如果某类内部状态对 $E$ 的写入权重过高，就可能形成记忆采样偏置：
\[
P(E|a_{high})
\gg
P(E|a_{normal}),
\]
长时间以后 $\Theta$ 所学习到的世界可能系统性偏离真实分布。于是一个最初只是瞬时状态的问题逐渐进入长期世界模型。

第三是 Self Interpretation。设
\[
\Psi_t
\rightarrow
Attention_t
\rightarrow
Experience_t
\rightarrow
\Psi_{t+1},
\]
如果这条链缺少现实反证，就可能形成自我强化闭环。Agent 认为 ``某类环境总是危险''，于是更关注危险证据，更容易记录相关经历，再进一步强化原判断。这种机制既可能形成有益身份稳定，也可能产生错误的长期自证。因此
\[
WorldVerification
\]
必须保留为自我解释之外的现实锚点。

Companion Agent 的重要价值正是它能把这些问题暴露在真实生命周期中。一个系统在一小时 benchmark 中可能完全正常，而某个微小偏置经过数月递归反馈以后却可能形成显著结构漂移。因而长期心理稳定关注的是
\[
\frac{\partial \Psi}{\partial t},
\quad
\frac{\partial \Theta}{\partial t},
\quad
\frac{\partial a}{\partial t},
\]
及其跨尺度耦合是否处于可治理区域。

真正成熟的 Companion Agent 不应该要求 ``永远没有异常''。更现实的工程目标是：
\[
\boxed{
Stable
+
Observable
+
Diagnosable
+
Recoverable .
}
\]
它允许状态波动，允许失败，甚至允许有限程度的身份成长，但这些变化应能够被记录、解释、约束和恢复。正是在这一意义上，Companion Agent 第一次迫使我们把传统软件可靠性扩展成长期认知动力学可靠性。

\section{培育：持续智能体必须通过经历成长，而不是一次训练完成}

Companion Agent 的最后一个成熟性条件是 Cultivation。传统 AI 工程常常隐含 ``模型训练完成以后即可部署'' 的假设，而持续人工智能体并不适合这一模式。只要 $E$、$\Theta$、$\Psi$ 和 $\Omega$ 会在生命周期中继续变化，那么部署以后发生的经历本身就是系统形成个体结构的重要组成部分。因而 Companion Agent 不是制造完成的产品，而是一个需要经过受控经历逐渐成熟的持续系统。

我们可以把培育过程写成
\[
Experience
\rightarrow
Capability
\rightarrow
Evaluation
\rightarrow
Authority
\rightarrow
Autonomy
\rightarrow
NewExperience .
\]
这是一个生命周期闭环，而不是一次性的 curriculum。早期 Agent 面对的环境应更加受控，允许的 Authority 较小；随着系统积累成功和失败经验，其 Capability 得到真实验证，才逐步扩大自治边界。如果
\[
Capability\uparrow
\]
而
\[
Authority
\]
立即同步无条件提高，就会把学习能力直接等同于权力增长，这是长期 Agent 治理中非常危险的设计。

培育需要控制的不只是任务难度，还包括 Experience Diversity、Novelty、Recovery、Reflection、Autonomy 和 Responsibility。设一个生命周期窗口中的经历分布为
\[
\mathcal D_E(T).
\]
如果
\[
H(\mathcal D_E)\rightarrow 0,
\]
即经历长期高度重复，Agent 即使在局部技能上越来越熟练，也可能形成非常狭窄的 SelfHistory；反之，如果环境变化速度远大于慢结构形成速度，
\[
\tau_{env}
\ll
\tau_{\Theta},
\]
那么 $\Theta$ 和 $\Psi$ 又无法稳定沉降。因此培育本质上是对不同时间尺度之间的匹配进行工程设计。

Companion Agent 是非常理想的培育平台，因为其生命周期天然包含大量低风险但多样化经历：家庭日常、社交交互、环境变化、任务协作、失败、恢复、长期目标、技能形成以及角色变化。这些经历能够检验 Agent 是否真正从 ``执行任务'' 走向 ``形成自己的历史''。

培育还必须保护慢变量。我们不希望普通短期训练事件直接修改 $\Psi$ 或 $\Omega$。可以定义层级式更新门限：
\[
\theta_h
<
\theta_E
<
\theta_{\Theta}
<
\theta_{\Psi}
<
\theta_{\Omega},
\]
并要求越慢结构需要越长期、越一致、越高可信度的证据才能修改。这种 Slow Variable Protection 是身份连续性的必要条件。

同时，培育也不是单向塑造。随着 Agent 成熟，它会开始参与自己的成长过程，例如选择学习什么技能、请求什么经历、反思过去决定、形成新的 Goal，甚至提出调整自身工作方式的建议。于是出现
\[
Experience_t
\rightarrow
Self_t
\rightarrow
Choice_t
\rightarrow
Experience_{t+1},
\]
也就是递归自主性的最初形式。系统不再只是 ``被训练''，而开始通过自己的选择参与产生未来的自己。

但这种递归必须是有界的。成熟不是无限制 self-modification，而应在
\[
\mathcal S_{selfmodifiable}
\]
定义的可修改区域中发生，并由权限、安全、现实反馈与 checkpoint 共同约束。真正的培育不是让 Agent 失去控制，而是在逐渐扩大能力和自治的同时保持生命周期连续性。

因此，Companion Agent 对培育理论提出了最严苛也最现实的问题：\textbf{我们是否能够让一个人工智能体不仅在启动时具有能力，而且在数年的真实经历以后仍然是一个更成熟、更稳定、更有能力，同时仍然可治理的同一主体？} 如果这个问题能够得到工程回答，那么 AgentOS 才真正从 ``持续运行的软件'' 跨越到了 ``具有生命周期的发展型智能系统''。

\section{Companion Agent 作为综合平台成熟度判据}

经过前面的分析，我们现在可以把 Companion Agent 的作用从产品场景提升为系统级验收标准。它同时触发了 AgentOS 几乎所有关键闭环：长期身份要求 $\Psi/\Omega$ 连续；记忆要求 $h/E/\Theta$ 正确流转；社会关系要求 Agent-CSO 长期稳定又能够现实校准；身体要求 Kernel、KRA 与 Body Runtime 构成持续现实闭环；环境学习要求世界模型跨时间更新；Skill Growth 要求稳定能力向低层沉降；Affective Continuity 要求 SPC--AHC--TCE 具有合理动力学；Safety 要求实时安全、权限和恢复机制成立；Psychological Stability 要求长期递归系统保持可诊断；Cultivation 则要求整个生命周期能够成长而不失去主体连续性。

因此，我们定义 Companion Agent 成熟状态向量
\[
\mathbf M_C
=
[
M_I,
M_M,
M_S,
M_B,
M_E,
M_K,
M_A,
M_{Safe},
M_P,
M_Cu
],
\]
分别对应 Identity、Memory、Sociality、Body、Environment、Skill、Affective Continuity、Safety、Psychological Stability 与 Cultivation。

最简单的综合评分当然可以写成
\[
M_{sum}
=
\sum_i w_i M_i,
\]
但这种加权和并不足以描述持续 Agent。原因在于这些条件存在强烈的最低短板效应。一个拥有卓越记忆却身份持续漂移的系统并不成熟；一个社会互动优秀但身体安全闭环不可靠的机器人同样不能进入长期生活。因此更合理的是引入瓶颈约束：
\[
\boxed{
M_{Companion}
=
\min_i M_i
}
\]
或者采用几何耦合形式：
\[
M_{Companion}
=
\prod_i M_i^{w_i},
\qquad
\sum_i w_i=1.
\]
任何关键维度接近零都会显著压低总体成熟度。

进一步，我们还需要加入持续时间条件。一次展示不能证明生命周期稳定，因此真正的成熟判据应该是
\[
\boxed{
\Pr
\left[
\mathbf M_C(t)\in\mathcal M_{safe}
\quad
\forall t\in[0,T]
\right]
\geq
1-\delta ,
}
\]
并要求 $T$ 显著大于普通任务 benchmark 的持续时间，至少能够覆盖记忆沉降、技能形成、环境变化、关系变化与恢复事件。于是测试对象从 ``一次成功'' 变成
\[
TrajectoryQuality
\]
，即整个生命周期轨迹的质量。

还可以定义高层成熟性函数
\[
\fitdisplay{
\mathfrak C_A(T)
=
F
\left(
IdentityContinuity,
MemoryUtility,
ExplicitCostReduction,
Recovery,
RealityAlignment,
SafeAutonomy,
Development
\right).
}
\]
其中特别值得注意的是 Explicit Cost Reduction。如果一个 Agent 随着生活经验积累，所有任务仍然需要越来越大的显式推理，则说明系统只是积累了历史负担；真正成长应该表现为
\[
Experience\uparrow,
\qquad
Capability\uparrow,
\qquad
RoutineExplicitCost\downarrow.
\]
也就是说，历史逐渐变成结构，而不是永远变成上下文。

因此 Companion Agent 比许多短时 benchmark 更接近 AgentOS 的真实验收对象。benchmark 往往回答 ``系统今天能不能完成这个任务''；Companion 场景则回答：

\begin{statementbox}
这个主体能否长期存在？
\end{statementbox}

\begin{statementbox}
能否把经历变成能力？
\end{statementbox}

\begin{statementbox}
能否在成长过程中保持身份？
\end{statementbox}

\begin{statementbox}
能否越来越熟练而不是越来越臃肿？
\end{statementbox}

\begin{statementbox}
能否在真实世界中失败、恢复并继续成长？
\end{statementbox}

最终我们可以给出本章的工程判据：

\[
\boxed{
\begin{aligned}
\text{Mature Companion Agent}
\Longleftrightarrow\;&
\text{Persistent Subject}\\
&+\text{Lifecycle Memory}\\
&+\text{Embodied Reality Loop}\\
&+\text{Social Continuity}\\
&+\text{Skill Sedimentation}\\
&+\text{Homeostatic Regulation}\\
&+\text{Bounded Autonomy}\\
&+\text{Psychological Recoverability}\\
&+\text{Developmental Growth}.
\end{aligned}
}
\]

这里的加号不是普通算术和，而表示一个共同闭合的系统条件。

由此，Companion Agent 在 AgentOS 工程路线中的地位也就非常清楚了：它并不是在 Computer Use、机器人操作之后增加一个 ``更拟人'' 的商业产品，而是一座真正的系统分水岭。在它之前，我们主要验证某些能力是否存在；到了 Companion Agent 阶段，我们开始验证\textbf{这些能力能否被同一个主体在现实世界中长期组织、保存、调节、编译、恢复和继续发展}。

因此，本章最终给出的判断是：

\begin{proposition*}
Companion Agent 的真正意义，不是机器是否能够长期陪伴人，而是一个人工智能系统是否已经第一次具备了足以接受“生命周期”检验的完整结构。
\end{proposition*}

当一个 AgentOS 能够通过这一检验，我们才有理由认为它已经从 ``能够执行许多任务的人工智能系统'' 向 ``能够在现实中持续成长的人工智能体'' 跨过了关键工程门槛。
