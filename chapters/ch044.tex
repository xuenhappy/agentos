\chapter{环境与社会性外部记忆}
\label{chap:environment-social-external-memory}

\begin{chapteroverviewbox}
本章完成一个从``记忆存储''到``世界结构承载''的重要理论扩展。此前我们已经把 Agent 的记忆体系从内部的 $h$、$E$、$\Theta$ 扩展到 Skill、Script、File、Database、Program 与 Tool，并把这种过程理解为认知结构从内部载体向外部载体的迁移。本章进一步指出：真正能够承担外部认知结构的并不只有计算机文件和显式工具，\textbf{环境本身以及其他智能体同样能够成为认知结构的稳定承载者}。

因此，我们将外部记忆的一般形式从
\[
M^{ext}=\{\text{File},\text{DB},\text{Tool},\text{Program}\}
\]
扩展为
\[
\boxed{
M^{ext}
=
M^{artifact}
\cup
M^{environment}
\cup
M^{social}
\cup
M^{institution}
}
\]
其中，$M^{environment}$ 表示被 Agent 主动塑造、能够改变未来认知与行动条件的环境结构；$M^{social}$ 表示由其他 Agent 承载、通过查询、协作、授权、委派与信任关系而可被调用的认知结构；$M^{institution}$ 则表示在多主体长期互动中沉降形成的角色、协议、制度与组织结构。

本章的核心命题不是``世界就是记忆''，而是一个更加严格的判断：
\begin{statementbox}
只有当外部结构与 Agent 建立了稳定、可索引、可恢复并能够改变未来行为的闭环关系时，
它才成为该 Agent 的广义外部记忆。
\end{statementbox}
由此，认知卸载不再只是把信息写入硬盘，而成为 Agent 改变未来计算条件的过程；社会协作也不再只是消息交换，而成为多个主体之间的认知结构分布与共同承载。我们将在这一章中逐步建立从环境记忆、工具记忆、社会性记忆一直到组织制度这一超慢结构层的统一理论。
\end{chapteroverviewbox}

\section{修改环境就是修改未来的认知条件}

我们首先从一个极其普通、却长期被认知理论低估的事实开始：一个智能体并不需要把所有需要记住的结构都保存在自己的内部。它可以通过改变世界，使未来再次遇到同一个问题时，现实本身已经携带了解题所需要的一部分结构。人把钥匙固定放在门边，把某件待办物品放在显眼位置，把道路修成可以反复通行的路径，把生产线上不同工具按照操作顺序排列，本质上都不是单纯的``环境整理''，而是在改变未来认知过程的输入结构。

为了形式化这一点，设智能体内部认知状态为
\[
X_A(t),
\]
外部环境状态为
\[
X_W(t),
\]
而当前行动为
\[
u_A(t).
\]
传统的封闭认知模型往往主要研究
\[
X_A(t+1)
=
F_A\!\left(
X_A(t),O(X_W(t))
\right),
\]
即世界通过观测 $O$ 改变 Agent。但真实智能系统还具有反向作用：
\[
X_W(t+1)
=
F_W\!\left(
X_W(t),u_A(t)
\right).
\]
因此，未来的认知输入并不是完全由一个独立于主体的世界给定，而部分取决于 Agent 此前采取过什么行动。于是下一轮认知状态应写成
\[
X_A(t+2)
=
F_A\!\left[
X_A(t+1),
O\!\left(
F_W(X_W(t),u_A(t))
\right)
\right].
\]
这意味着行动不仅解决当前问题，也能够通过改变 $X_W$ 改变未来问题本身。

我们可以把这种作用定义为\textbf{环境认知沉降（environmental cognitive sedimentation）}。设某一 Agent-CSO 为
\[
C_A,
\]
如果该结构最初只能通过内部显式加工被维持，例如
\[
C_A@h,
\]
而经过一次环境修改 $\Phi_W$ 后，未来只需要读取环境中的某个稳定结构 $C_W$ 即可恢复相同功能，则存在
\[
C_A@h
\xrightarrow{\Phi_W}
C_W@Environment.
\]
当下一次任务出现时，
\[
C_W
\xrightarrow{Observation}
\widetilde C_A
\]
重新激活内部结构。于是一次完整的环境记忆循环成为
\[
\boxed{
AgentCSO
\rightarrow
EnvironmentCSO
\rightarrow
FutureObservation
\rightarrow
AgentCSO'.
}
\]

这一过程与简单的``把东西放在外面''有本质区别。真正构成外部记忆，需要至少满足四个条件。第一，外部结构必须具有一定的\textbf{持续性}，即其寿命不能明显短于需要调用它的任务周期；第二，它必须具有\textbf{可寻址性}，Agent 必须知道什么时候、在哪里以及通过什么观测方式能够重新获得它；第三，它必须具有\textbf{功能恢复性}，重新观察该结构后能够恢复一部分原本需要内部维持的认知关系；第四，它必须具有\textbf{未来行为效应}，即该外部结构确实能够改变之后的判断、计划或动作。由此可以定义环境结构成为外部记忆的充分功能条件：
\[
\mathcal M_W(C)
=
P_{persist}(C)
\cdot
P_{address}(C)
\cdot
P_{recover}(C)
\cdot
I(C;Action_{future}),
\]
其中最后一项不是要求使用严格互信息作为唯一指标，而是表达：如果一个外部结构对未来行动没有任何可测影响，就不应仅因为它存在于环境中而把它称作该 Agent 的记忆。

这使我们能够重新理解所谓``认知负担''。假设某一任务在完全内部化情况下需要维持一组关系
\[
\mathcal C_{int}
=
\{C_1,\ldots,C_n\},
\]
其工作记忆运行负载为
\[
L_h
=
\sum_{i=1}^{n}
w_i\,\kappa(C_i),
\]
其中 $\kappa(C_i)$ 表示某一 Agent-CSO 在当前表示方式下的关系维持成本。如果其中部分结构可以写入环境，
\[
\mathcal C_{ext}
\subset
\mathcal C_{int},
\]
那么新的内部实时负载近似成为
\[
L'_h
=
\sum_{C_i\in
\mathcal C_{int}\setminus\mathcal C_{ext}}
w_i\,\kappa(C_i)
+
C_{index},
\]
其中 $C_{index}$ 是维护外部结构索引所需的内部成本。外部化真正有价值的条件不是 $C_{index}=0$，而是
\[
\boxed{
C_{index}
+
C_{retrieve}
<
C_{maintain}.
}
\]
这就是环境记忆成立的第一个经济原则：\textbf{智能体不必保留外部结构的全部内容，只需要保留足够稳定的索引、意义和调用关系。}

这一观点与外部认知、扩展认知以及生态心理学中的若干思想存在联系，但我们的关注点有所不同。这里不需要首先回答``认知究竟位于头脑内部还是扩展到世界''这一哲学争论，而是把它变成一个可工程化的问题：某个 Agent-CSO 当前由什么载体承担？这个载体的修改成本、恢复成本、可靠性和时间尺度分别是多少？因此，本章使用``环境记忆''并不是扩大记忆概念的修辞，而是在 AgentOS 中引入一个可测量的\textbf{认知结构载体选择问题}。

由此我们获得一个非常重要的结论：
\begin{conclusion}
行动可以同时是一种任务执行和一种未来认知结构写入。
\end{conclusion}
当 Agent 改造环境时，它并不只是让世界变成自己想要的状态，还可能让未来的自己面对一个更容易理解、更容易预测、更容易控制的世界。从长期智能角度看，成熟 Agent 的能力并不表现为把所有世界结构都复制进内部，而表现为它越来越善于决定：什么应该内部记住，什么应该写入环境，以及什么只需要保留一个重新获得它的路径。

\section{工具是稳定化的动作结构与认知结构}

环境外部化的一种高度结构化形式就是工具。我们通常把工具理解为一个被 Agent 调用的外部执行器，但从认知结构动力学角度看，工具的含义要更深。一个真正成熟的工具往往同时承载了过去的认知、过去的控制经验以及过去对环境规律的压缩。换句话说，工具不仅``帮助我们完成动作''，它还把大量本来需要实时推理的结构固化成了一个可重复调用的外部闭环。

设某一任务最初需要显式认知过程
\[
\Gamma_C
=
(C_1,C_2,\ldots,C_n),
\]
并经过
\[
h
\rightarrow
E
\rightarrow
\Theta
\]
逐渐形成稳定经验。如果这些结构最终被编码为一个工具 $T$，则可以写成
\[
\Gamma_C
\xrightarrow{compile}
T.
\]
以后执行相同功能不再需要重新显式展开完整的 $\Gamma_C$，而只需要维持
\[
C_{goal}
+
C_{tool-index}
+
C_{condition},
\]
然后调用
\[
T(input)\rightarrow output.
\]
因此从 AgentOS 视角看，成熟工具是一种\textbf{被封装起来的历史认知结构}。

这一点在数字环境尤其明显。一个脚本可以把几十步显式操作折叠成一次调用；一个数据库索引把过去大量搜索决策编码进数据结构；一个编译器把关于计算机体系结构、优化与语言规则的大量知识沉积成稳定程序；一个地图系统将此前必须依赖个人空间记忆的结构迁移到外部载体。物理工具同样如此。一把扳手将关于力矩传递的结构压缩进几何形态；夹具将定位约束固化进机械结构；生产线把任务顺序写进空间布局。因而：
\[
\boxed{
Tool
=
ExternalizedConstraint
+
ExternalizedProcedure
+
ExternalizedCapability.
}
\]

这让我们能够严格地区分``普通物体''与``作为 Agent 外部认知结构的工具''。设环境中对象 $O_i$ 的物理状态为
\[
x_i^W,
\]
只有当 Agent 建立
\[
\chi_A(O_i)
=
(
Capability,
Precondition,
Invocation,
ExpectedOutcome
)
\]
这样的稳定功能关系后，$O_i$ 才真正成为该 Agent 的工具。换句话说：
\[
\boxed{
Object\neq Tool;
\qquad
Tool=Object+StableAgentRelation.
}
\]
同一个锤子对于一个从未理解其用途的系统只是一个外部对象，而对已经建立稳定 affordance 与动作模型的 Agent 来说，它才是可以承担认知与行动结构的工具。

更进一步，我们可以把工具理解成一种外部化的\textbf{局部闭环}。若原本高层需要完成
\[
Perceive
\rightarrow
Reason
\rightarrow
Plan
\rightarrow
Control
\rightarrow
Verify,
\]
那么成熟工具可能已经在自身内部或物理结构中闭合其中一部分。例如一个恒温控制器自己完成测量和调节，一个导航器自己完成路径搜索，一个数据库查询系统自己完成索引搜索。因此 Agent 对工具的正确调用并不是``把全部问题交出去''，而是把一个已经可以局部闭合的子问题交给一个具有相应能力边界的结构：
\[
C_{subproblem}
\xrightarrow{delegate}
T
\xrightarrow{result}
C_{result}.
\]
只有异常、冲突或能力边界被突破时，该结构才重新上浮到高层显式认知。

由此可以把工具形成过程理解为一种承载迁移：
\[
\boxed{
ExplicitAgentCSO
\rightarrow
StableProcedure
\rightarrow
ExternalToolCSO.
}
\]
如果该工具以后又被智能体频繁调用，那么它在 Agent 的内部不需要保留完整实现，而只需要保留一个较小的工具模型：
\[
M_A(T)
=
(
Capability,
Cost,
Risk,
Reliability,
Interface
).
\]
这类似于一个内部``认知句柄''。Agent 不需要知道数据库内部每一个 B-tree 节点，不需要知道操作系统每一次系统调用的机器指令，也不需要知道机械臂控制器内部每一个 servo 更新过程。成熟智能的一个标志，恰恰是能够在保持功能可验证性的条件下容忍这种内部不可见性。

这里出现了第二个重要经济原则。设一个功能结构内部维持成本为 $C_{in}$，工具化一次性的编译成本为 $C_{compile}$，每次工具调用成本为 $C_{call}$，预计未来重复次数为 $N$，则只有当
\[
C_{compile}
+
N C_{call}
<
N C_{in}
\]
时，工具化才具有长期成本优势。更现实地，还需加入可靠性与切换成本：
\[
C_{compile}
+
N(C_{call}+C_{verify})
+
C_{failure}
<
N C_{explicit}.
\]
因此，\textbf{不是所有可以外化的能力都应该立即工具化}。对于低重复、高变化、高不确定任务，显式认知仍然可能更经济；对于高重复、低残差、接口稳定的任务，则应逐步向工具或技能沉降。这与我们此前提出的``稳定能力向下、异常结构向上''完全一致，只是这里的``向下''跨过了 Agent 边界，进入外部世界。

工具理论同时解释了为什么文明能够表现出远超单个人脑容量的累积能力。每一代人并不需要重新推导所有物理、数学、机械和计算规则。大量过去的认知已经沉积成工具、程序、仪器、语言和基础设施。当一个 Agent 使用它们时，它实际上在调用其他主体过去已经完成的结构压缩。因此：
\[
\boxed{
ToolUse
=
AccessToSedimentedHistoricalCognition.
}
\]
这并不意味着工具本身必然是智能体，而意味着它可以成为智能体功能拓扑之外的一个稳定认知承载节点。

从这一点出发，我们可以重新理解 AgentOS 中 Skill、Program 与 Tool 的关系。Skill 更接近主体内部或身体层已经编译的局部闭环，Program 是以数字符号系统外化的稳定过程结构，Tool 则是具有明确能力接口、能够被主体调用的外部功能结构。三者之间没有绝对本体边界，它们更像同一 Agent-CSO 在不同承载位置上的实现：
\[
\boxed{
AgentCSO
\rightarrow
Skill
\rightarrow
Program
\rightarrow
Tool
}
\]
并且在需要重新分析时又可以沿反方向被重新显式化。我们因此不再把工具使用看成 Agent 智能之外的附加能力，而把它理解为长期智能扩张其有效结构边界的基本机制之一。

\section{其他 Agent 作为社会性认知载体}

如果环境和工具能够承担认知结构，那么一个更强但也更复杂的外部载体就是\textbf{其他智能体}。与文件或工具不同，其他 Agent 本身拥有自己的状态、记忆、目标、边界与学习过程。因此，把其他 Agent 视为外部认知载体并不意味着把他者降格为被动存储设备；恰恰相反，它意味着承认一个长期智能系统可以把部分结构稳定地分布在多个具有自主状态的主体之间，并通过关系而不是通过物理所有权来访问这些结构。

设主体 Agent 为 $A_i$，另一个 Agent 为 $A_j$。如果某一结构 $C$ 主要由 $A_j$ 长期维持，而 $A_i$ 不必保存其完整内容，只需要维持
\[
M_{ij}(C)
=
(
Who,
Capability,
AccessProtocol,
Reliability,
Trust,
Cost
),
\]
那么对 $A_i$ 而言，$A_j$ 就承担了某种社会性外部记忆功能。最简单的形式是：
\[
A_i:
\quad
``C\text{ 由 }A_j\text{ 知道}''
\]
而不是
\[
A_i:
\quad
\text{``我内部保存 }C\text{ 的全部内容''}.
\]
于是检索过程不再是
\[
MemoryAddress\rightarrow Data,
\]
而是
\[
SocialIndex
\rightarrow
Agent_j
\rightarrow
Query
\rightarrow
Response
\rightarrow
Verification.
\]

这一结构与认知科学中所谓 transactive memory system 有相似之处：群体成员并不需要每个人都知道全部知识，而需要知道``谁知道什么''。但在 AgentOS 框架中，我们需要进一步把这种现象形式化为认知结构承载关系。定义社会性承载矩阵
\[
R^{soc}_{ij}(C)\in[0,1],
\]
表示 Agent $A_i$ 对 ``$C$ 可由 $A_j$ 稳定获得'' 的依赖程度。同时定义信任估计
\[
T_{ij}(C,t)
=
P(
C_j^{reply}\text{ satisfies required function}
\mid
H_{ij}^{t}
),
\]
其中 $H_{ij}^{t}$ 表示双方截至时刻 $t$ 的历史互动。于是社会性外部记忆并不是一个无条件可访问的存储，而是一个带有可靠性、权限、延迟和战略性的动态认知载体。

这使其他 Agent 与普通外部文件产生了本质区别。文件的状态通常不会因为``被询问''而改变目标；但其他 Agent 可能拒绝、隐藏、误解、重新解释，甚至主动改变自己的知识。因此社会性检索必须满足：
\[
Retrieve_{social}
=
Query
+
Interpretation
+
TrustEvaluation
+
Verification.
\]
其中 Verification 尤其重要。Agent 不能因为某个可信主体给出了答案，就把该结果直接升级为 Reality Authority。社会性信息仍然属于间接证据：
\[
Agent_j^{claim}
\neq
WorldObservation.
\]
因此，当结果足以影响高风险行动时，仍然需要现实验证或多源交叉验证。

我们还必须区分多种社会性承载关系。第一类是\textbf{查询关系}：$A_i$ 保留问题索引，$A_j$ 提供知识。第二类是\textbf{委派关系}：$A_i$ 不仅请求信息，而且把某一子任务及其局部决策权交给 $A_j$。第三类是\textbf{协作关系}：多个 Agent 分别维持问题的不同部分，并在共享边界进行结构耦合。第四类是\textbf{授权关系}：某些结构只有具有合法权限的 Agent 才能修改或确认。第五类是\textbf{依赖关系}：主体长期将某一能力完全放在其他 Agent 上，形成稳定的社会功能拓扑。

可以统一表示为
\[
\mathcal R_{ij}
=
(
C_{shared},
Authority,
Trust,
Latency,
Cost,
Persistence
).
\]
当该关系长期稳定时，主体的内部认知拓扑会发生改变。原本需要内部保留的结构
\[
C_A
\]
可能缩减成
\[
Index(A_j,C)
+
TrustModel(A_j)
+
VerificationPolicy.
\]
因此：
\begin{statementbox}
社会化并不一定增加每个个体内部知识量，
反而可能通过可靠分工降低个体内部显式结构负担。
\end{statementbox}

这也解释了为什么群体能力不能简单表示成个体能力之和：
\[
Capability_{group}
\neq
\sum_i Capability_i.
\]
一方面，群体具有更多分布式结构；另一方面，它还会产生协调成本：
\[
C_{coord}
=
f(
N,
Dependency,
Communication,
Conflict,
Latency
).
\]
因此真正有效的群体智能要求：
\[
Gain_{distribution}
>
Cost_{coordination}.
\]
这与前文关于智能尺度和延迟之间的约束重新连接起来：当主体数量增加以后，如果每一个局部问题都需要所有成员同步参与，那么系统很快被协调成本吞噬；只有形成局部闭环、分工、稳定索引和有限上浮机制，社会性外部认知才真正产生规模效应。

从 CSO 角度看，这意味着认知结构可以具有分布式所有权。对于一个复合问题
\[
C^{global},
\]
可能存在
\[
C^{global}
=
\bigcup_{i=1}^{n}
C_i
+
R(C_1,\ldots,C_n),
\]
其中任一单独 Agent 都没有完整结构，完整结构只存在于主体间关系中。此时我们已经不能说 ``$C^{global}$ 存储在某个 Agent 内''，而应该说：
\[
\boxed{
C^{global}
\text{ is carried by a social functional topology.}
}
\]
这是社会性外部记忆比普通文件记忆更加深刻的地方：有些认知结构的真正载体不是某个节点，而是节点之间的关系。

因此，本章采用``社会性外部记忆''并不是主张把其他主体当作自己的存储设备，而是建立一种更一般的认知系统论：\textbf{一个成熟智能体能够利用具有自身自主性的其他认知主体作为分布式结构载体，同时必须维持对访问权限、信任、误差、依赖和现实验证的明确模型。}在更高尺度上，稳定的社会性认知关系将逐渐沉降为角色、协议和组织结构，这正是后面几节需要考察的问题。

\section{查询、协作、授权与委派：社会性认知结构的四种基本操作}

为了使社会性外部记忆从哲学描述进入可工程讨论，我们需要明确一个 Agent 究竟如何操作由其他主体承载的认知结构。历史讨论中曾经使用过``说服、征服、顺从''等较粗糙的社会作用术语；在本书的正式理论中，我们将其改写为更加中性、可操作并适用于人工智能系统的四种基本关系：\textbf{查询（query）、协作（collaboration）、授权（authorization）与委派（delegation）}。这四种操作分别改变信息结构、共同处理关系、修改权限边界和重新分配功能责任。

首先考虑查询。查询不转移任务控制权，只请求一个由其他 Agent 承载的结构：
\[
Q_{ij}(C_q)
\rightarrow
A_j
\rightarrow
C_r.
\]
其中 $C_q$ 是查询 CSO，$C_r$ 是返回结构。主体 $A_i$ 保持决策责任，因此必须进行
\[
Verify(C_r)
\]
并决定是否使返回结构进入自己的 $h$、$E$ 或 $\Theta$。查询的关键成本包括
\[
C_Q
=
C_{locate}
+
C_{communicate}
+
C_{interpret}
+
C_{verify}.
\]
只有当
\[
C_Q<C_{internal-reconstruct}
\]
时，外部查询才是合理的认知卸载。

第二种关系是协作。协作意味着多个 Agent 对同一个高层 CSO 进行互补处理。例如：
\[
C
\rightarrow
(C_1,C_2,\ldots,C_n),
\]
分别分配给
\[
A_1,A_2,\ldots,A_n,
\]
最后重新组合：
\[
\hat C
=
Merge(C_1',C_2',\ldots,C_n').
\]
真正困难的不只是任务分解，而是结构边界。若各子任务之间存在强耦合，
\[
I(C_i;C_j)\gg0,
\]
则独立处理会失去关键关系，导致
\[
C_{merge}
\]
显著上升。因此，协作调度需要寻找一种切分，使
\[
\min
\left(
\sum_i C_{local}(C_i)
+
C_{coord}
+
C_{merge}
\right).
\]
这与我们关于工作记忆有限性、任务分解和 CCM 的讨论在更大尺度重新出现：个体内部不能无限维持复杂结构，群体也不能通过无限通信逃避复杂度。有效协作依赖的是\textbf{正确的结构边界}。

第三种关系是授权。授权改变的不是知识内容，而是某个 Agent 对某一状态空间的合法修改范围。可以定义
\[
Auth_{ij}
:
\mathcal S_j
\rightarrow
\mathcal A_i^{allowed},
\]
即 $A_j$ 允许 $A_i$ 在某些资源或状态上执行某类动作。授权之所以与外部记忆有关，是因为一个外部结构即使``知道应该怎样改变''，没有对应执行权，也不能成为完整功能闭环。例如某个维护 Agent 知道服务器出现问题，但只有具有运维权限的主体才能改变生产配置。因此社会性结构承载不仅包括：
\[
WhoKnowsWhat,
\]
还必须包括：
\[
\boxed{
WhoMayChangeWhat.
}
\]
这意味着群体认知拓扑天然包含权限拓扑。

第四种关系是委派。委派比查询更深，因为主体将一个子目标以及一定范围内的局部决策权交给另一个 Agent：
\[
(G_i,\mathcal A_i,\mathcal C_i)
\xrightarrow{delegate}
A_j.
\]
其中 $\mathcal A_i$ 表示允许的动作空间，$\mathcal C_i$ 表示约束。成熟委派并不是只发送一句目标，而需要同时定义：
\[
D_{ij}
=
(
Goal,
SuccessCriterion,
Constraint,
Authority,
Budget,
Deadline,
EscalationRule
).
\]
因此：
\[
\boxed{
Delegation
=
GoalTransfer
+
BoundedAuthorityTransfer
+
ReturnContract.
}
\]
如果没有返回契约，委派就容易演化成主体无法观察的认知黑箱；如果没有局部自治，委派又退化成高频远程操控，失去社会性外部承载的意义。

我们可以把这四种关系放到一个二维空间中。一条轴表示\textbf{状态所有权转移程度}，另一条轴表示\textbf{控制权转移程度}。查询具有低控制权转移；协作共享状态但未必转移最终控制；授权主要扩大合法动作集合；委派则同时转移部分任务结构与控制责任。因此社会性外部认知并不是一种单一 API，而是一组具有不同因果含义的关系操作。

长期来看，这些操作还会产生认知结构学习。Agent $A_i$ 会形成关于 $A_j$ 的稳定结构：
\[
AgentCSO_i(A_j)
=
(
Capability_j,
Reliability_j,
Cost_j,
Trust_j,
Authority_j,
History_{ij}
).
\]
这个结构经过重复互动不断更新：
\[
T_{ij}(t+1)
=
T_{ij}(t)
+
\eta
\left(
Outcome_{ij}(t)-Prediction_{ij}(t)
\right).
\]
这里不必把 Trust 机械压缩成单一标量，但该形式清楚说明：社会关系本身也处于预测—行动—残差—更新闭环之中。

由此我们获得一个重要结论：\textbf{社会性认知扩展并不意味着主体边界消失，而是要求边界变得更加精确。}如果 $A_i$ 不知道什么结构由自己负责、什么结构由他者承载、什么时候应该验证、什么时候应该授权、什么时候必须收回委派，那么群体规模越大，错误传播反而可能越严重。因此，社会性外部记忆必须和 Boundary 原理共同理解。开放边界增加可调用结构空间，而精确边界保证责任、权限和验证关系不会随外部化一起消失。

\section{群体认知：认知结构分布而不是多个大脑简单相加}

当多个 Agent 长期建立查询、协作、授权和委派关系后，我们面对的不再只是``一个 Agent 使用另一个 Agent''，而是一个新的问题：完整认知结构可能开始分布于主体之间。此时群体智能不能用个体智能简单求和描述，而必须把主体及其关系共同视为一个更高尺度的功能网络。

定义群体
\[
\mathcal A
=
\{A_1,\ldots,A_N\},
\]
主体之间的功能关系构成图
\[
\mathcal G_S
=
(V_S,E_S),
\]
其中
\[
V_S=\{A_i\},
\]
而每条边
\[
e_{ij}
=
(
Information,
Authority,
Trust,
Dependency,
Latency
)
\]
描述两个主体之间可持续的认知耦合。此时一个群体级 CSO $C_G$ 的有效承载状态可以表示为
\[
\mu_G(C_G)
=
\{
(A_i,C_i),
e_{ij}^{relevant}
\},
\]
即其内容既分布在主体节点，也存在于主体间关系中。

我们可以用一个简单例子理解这一点。假设团队中一名成员知道客户需求，一名成员掌握工程实现，一名成员拥有预算权限。如果三个主体之间没有形成有效关系，那么即使全部必要知识都``存在于团队里''，任务仍然可能无法完成。完整能力需要：
\[
Knowledge
+
Relation
+
Authority.
\]
因此：
\[
\boxed{
CollectiveCapability
\neq
StoredKnowledge.
}
\]
更严格地说：
\[
Capability_G
=
F(
\{Capability_i\},
Topology_G,
Protocols,
Authority,
Latency
).
\]

这意味着认知结构具有一个非常容易被忽略的部分：\textbf{关系本身也是结构承载}。例如``谁负责什么''并不属于任何专业知识本身，但没有这个结构，所有专业知识都会陷入重复搜索与协调。于是角色分工实际上构成一种\textbf{元记忆}：
\[
MetaMemory_G:
C
\mapsto
Carrier(C).
\]
群体不用每个成员掌握全部内容，而需要保持一张稳定的``认知结构到承载者''映射。该映射越准确，
\[
C_{search}\downarrow,
\]
群体运行效率越高。

但群体规模扩展会带来另一个基本约束。若任意两主体都需要保持高带宽同步，则连接数可能接近
\[
|E|\sim O(N^2),
\]
协调成本迅速增长。因此大规模智能系统必须形成稀疏层级结构：
\[
|E_{effective}|\ll N^2.
\]
这与我们关于多尺度智能的早期结论完全一致：\textbf{规模扩大必须伴随局部闭环和较慢的跨层协调，否则整体无法保持高频同步。}

可将群体总认知成本概念性写成：
\[
J_G
=
\sum_i J_i^{local}
+
\lambda_C C_{communication}
+
\lambda_R C_{redundancy}
+
\lambda_D C_{dependency}
+
\lambda_E C_{error-propagation}.
\]
一个好的群体拓扑不是让通信最大，而是使
\[
J_G
\]
最小，同时保持任务能力。由此可以解释为什么成熟组织会出现部门、专业化、负责人、接口、协议和层级：这些结构本质上是在压缩跨主体协调复杂度。

这一观点也使我们能够重新理解``群体涌现''。群体能力不是凭空涌现的神秘属性，而可能来自至少四类新增结构。第一，主体之间形成了互补的 Agent-CSO 分布；第二，关系图产生了单个主体内部没有的全局结构；第三，局部闭环降低了中央认知压力；第四，长期反馈使角色与连接逐渐稳定。于是：
\[
\boxed{
CollectiveEmergence
=
DistributedStructure
+
RelationalStructure
+
LocalClosure
+
HistoricalSedimentation.
}
\]

在这里，社会性外部记忆和认知卸载再次汇合。对于个体 $A_i$ 而言，把结构交给其他主体可以降低其自身 $h$ 与长期记忆压力；对于群体而言，这些结构并没有消失，而是重新分布到了群体拓扑中。因此：
\[
C_{individual}\downarrow
\]
并不必然意味着
\[
C_{group}\downarrow.
\]
更准确的关系是：
\[
\boxed{
InternalLoad
\rightarrow
DistributedStructuralLoad.
}
\]
我们早期使用``复杂度迁移''语言描述这一现象，而在当前 CSO 本体中应解释为 Agent-CSO 承载位置发生改变。

这里还必须强调现实验证。群体系统容易产生一种特殊风险：同一错误结构可能通过信任边快速传播，最终形成大规模自我强化。因此社会性结构稳定不能仅依赖重复出现：
\[
Frequency\neq Truth.
\]
一个结构即使在所有主体之间广泛传播，也不能因此被视为现实正确。群体认知仍然必须保持：
\[
\boxed{
Reality
\rightarrow
Observation
\rightarrow
Evidence
}
\]
这一外部校准通路。否则社会性记忆就可能从提高认知能力的基础设施，转化为错误结构的放大器。

所以，群体认知的成熟并不体现在``所有主体思想一致''，而体现在能够保持多样局部模型、清晰分工、有限耦合、现实验证以及稳定的冲突解决机制。一个高质量群体系统应该使必要结构能够跨主体流动，又不要求每一个主体同步拥有全部结构。这正是多尺度智能原则在社会维度上的一次重新出现。

\section{组织制度作为超慢外部结构}

当某些社会关系反复出现并长期有效时，认知结构会发生进一步沉降：它不再依赖某两个具体 Agent 每次临时协商，而被写入角色、协议、流程、标准、法律、组织结构甚至物理基础设施中。我们把这一层称为\textbf{制度性外部记忆（institutional external memory）}。

设某种协作模式在时间区间 $T$ 内反复发生：
\[
A_i
\xrightarrow{C}
A_j.
\]
如果每次都需要重新确定``由谁负责、如何传递、什么时候验证、失败怎么办''，协调成本为
\[
C_{coord}^{dynamic}.
\]
当该关系长期稳定以后，可以形成协议
\[
P_{ij}(C),
\]
于是下一次不再重新协商全部结构，而按
\[
P_{ij}
\]
执行。此时：
\[
\boxed{
RepeatedCoordination
\rightarrow
Protocol.
}
\]
进一步，当多个协议围绕稳定功能形成角色集合
\[
R_1,R_2,\ldots,R_k,
\]
便产生组织结构：
\[
\boxed{
RepeatedSocialCSOFlow
\rightarrow
Role
\rightarrow
Protocol
\rightarrow
Institution.
}
\]

这与前文提出的功能拓扑沉降具有高度一致的形式。个体 Agent 内部：
\[
RepeatedCSOFlow
\rightarrow
StableFunctionalCoupling.
\]
群体层则出现：
\[
RepeatedInterAgentCSOFlow
\rightarrow
StableOrganizationalCoupling.
\]
因此，制度可以理解为：
\[
\boxed{
Institution
=
SlowMemoryOfRepeatedCollectiveCoordination.
}
\]
这是一种结构动力学定义，而不是关于制度全部社会意义的穷尽性定义。

制度性结构的重要性质是：它的时间尺度通常明显慢于成员个体行为。可以写成
\[
\tau_{action}
\ll
\tau_{task}
\ll
\tau_{role}
\ll
\tau_{institution}.
\]
成员可以不断变化，但角色和协议仍然保持。于是制度实现了跨主体和跨生命周期的结构连续性。例如某个岗位的具体人员可以更换，而：
\[
RoleSpecification
\]
仍然持续存在。这意味着认知结构已经从
\[
Agent_j
\]
迁移到：
\[
Role_j.
\]
主体不再需要知道``某个人是谁''，而只需要知道：
\[
``\text{该功能由此角色承担}''
\]
即可调用整个组织结构。

这是一种重要的认知压缩。例如一个大型组织如果要求每个人都记住所有人的能力、权限和历史，认知成本极高；角色制度把大量主体细节压缩成较少的功能节点：
\[
A_1,\ldots,A_N
\rightarrow
R_1,\ldots,R_K,
\qquad
K\ll N.
\]
因此群体 Agent 只需维持：
\[
AgentCSO(Role)
\]
而不必维持：
\[
AgentCSO(EveryIndividual).
\]
从信息组织角度看，制度就是一种超慢尺度的关系压缩器。

但制度沉降也带来经典的稳定性—可塑性矛盾。因为慢结构的价值在于减少反复协调，它不能因为一次异常就重新改变：
\[
FastNoise
\nrightarrow
InstitutionChange.
\]
另一方面，如果环境长期改变，而制度仍然锁定过去的 CSO 流，则会出现：
\[
StructuralMismatch
=
Demand_{current}
-
Topology_{institution}.
\]
随着长期残差积累：
\[
\langle \varepsilon_{institution}\rangle_T
\uparrow,
\]
最终必须触发制度重构。因此理想制度更新需要满足：
\[
\theta_{on}>\theta_{off},
\]
即建立新结构所需证据应高于短暂保持旧结构的阈值，从而形成迟滞，防止组织频繁震荡。

这正是我们在智能拓扑理论中提出的\textbf{慢变量保护原则}在社会系统中的表现。制度越底层、权限越大、影响范围越广，其修改时间尺度原则上应越慢：
\[
\tau_{institution}
\propto
Impact
\times
Irreversibility
\times
Dependency.
\]
这并不是说大制度永远不应改变，而是说改变深层拓扑的证据门槛应显著高于修改局部运行状态。

制度结构同时具有记忆与控制双重性质。一方面，它保存过去反复有效的关系；另一方面，它直接塑造未来主体的可行行为域。因此可以写成：
\[
Institution
:
History
\rightarrow
Constraint(FutureAction).
\]
这与 Agent 内部 $\Theta$ 的作用存在明显同构：$\Theta$ 由过去经验形成，但并不只是过去的记录，而是未来状态生成与行动选择的结构约束。我们不能因此把制度简单等同于 $\Theta$，但可以说二者在不同尺度上都体现：
\[
\boxed{
PastInteraction
\rightarrow
SlowStructure
\rightarrow
FutureConstraint.
}
\]

这使我们能够重新理解社会传承。当一个新 Agent 进入一个已有组织时，它并不从零开始发现全部协作规律，而是首先进入一个已经存在的协议—角色—制度场：
\[
Institution
\rightarrow
AgentConstraint.
\]
同时，该 Agent 的长期行为又可能改变制度：
\[
AgentResidual
\rightarrow
InstitutionUpdate.
\]
因此：
\[
\boxed{
InstitutionShapesAgents;
\qquad
PersistentAgentResidualShapesInstitution.
}
\]
这就是自顶向下约束与自底向上结构学习在组织层面的统一形式。

从 AgentOS 视角看，制度性结构的重要意义在于提示我们：未来多个持久 Agent 组成的系统不能只依赖消息协议和一次性任务路由。随着系统运行时间增长，重复关系必然需要沉降成更慢的组织结构。如果没有这一层，每一轮协作都重新产生高额协调成本；如果这一层完全不可改变，又会形成僵化。因此真正成熟的多 Agent 系统最终需要同时管理\textbf{动态互动}和\textbf{互动历史沉降出的慢拓扑}。

\section{个体、组织与文明的多尺度外化}

现在我们可以把前几节整合成一个更加完整的多尺度图景。一个认知结构最初可能存在于个体工作记忆中，随后进入个体长期结构，再外化成工具和环境，进一步通过其他 Agent 被分布式承载，最终沉降成组织制度。于是认知结构存在一条可能的尺度迁移链：
\[
\boxed{
h
\rightarrow
E
\rightarrow
\Theta
\rightarrow
Skill
\rightarrow
Tool/Environment
\rightarrow
SocialCarrier
\rightarrow
Institution.
}
\]
这不是每一个 CSO 必然经历的固定流水线，而是说明一个结构可以在不同时间尺度和功能边界上寻找更稳定、更低成本的承载位置。

设第 $k$ 个承载层具有状态空间 $\mathcal X_k$、特征时间尺度 $\tau_k$、修改成本 $C_k^{mod}$ 与检索成本 $C_k^{ret}$。一般而言，越慢、越外部、越制度化的结构往往具有：
\[
\tau_k\uparrow,
\qquad
C_k^{mod}\uparrow,
\]
而单次个体认知负担则可能：
\[
C_h\downarrow.
\]
因此，长期结构迁移实际上在做一个多目标优化：
\[
\min_{k}
\left[
C_k^{maintain}
+
\lambda_1 C_k^{retrieve}
+
\lambda_2 C_k^{modify}
+
\lambda_3 Risk_k
\right],
\]
同时要求：
\[
Reliability_k\geq r_{min},
\]
\[
Latency_k\leq l_{max},
\]
\[
Authority_k\in FeasibleSet.
\]
这说明外部记忆从来不是``越外越好''。一个必须毫秒级响应的结构不适合存放在遥远社会关系中；一个极少变化、多人长期共享的规则也没有必要让每个人持续放在 h 中。真正的 AgentOS 应该根据结构时间尺度、使用频率和控制风险选择承载层。

当这种迁移跨越单个主体以后，文明获得了超越个体寿命的结构连续性。一个人可以把 Agent-CSO 写成文字：
\[
AgentCSO_i
\rightarrow
TextCSO,
\]
文本经过数百年再次被另一个主体读取：
\[
TextCSO
\rightarrow
AgentCSO_j.
\]
于是：
\[
\tau_{carrier}
>
\tau_{individual}.
\]
这意味着文明创造了一种其寿命超过任何参与主体的外部结构层。

语言、文字、数学、科学、标准、程序、机器和制度共同组成这种跨生命周期承载网络。一个新生主体不需要重新发明语言、数制、道路、计算机和组织流程，而是在一个已经高度结构化的外部环境中开始学习。因此其初始认知条件实际上是：
\[
X_A(t_0)
\quad\text{embedded in}\quad
X_{civilization}(t_0).
\]
这说明个体智能从来不是完全独立生长的。文明提前改变了环境 CSO，使个体面对的是一个``已经被过去智能加工过的世界''。

从这个意义上，可以定义文明尺度外部认知资本：
\[
K_C(t)
=
K_{artifact}
+
K_{tool}
+
K_{institution}
+
K_{knowledge}
+
K_{infrastructure}.
\]
$K_C$ 并不是严格可加的标量，更准确地应被理解成一个多层图：
\[
\mathcal G_C^{civilization}.
\]
个体 Agent 可以通过接口
\[
\mu_i:
\mathcal G_C^{civilization}
\rightarrow
AgentCSO_i
\]
选择性获得其中极小一部分结构。没有任何个人拥有文明全部知识，但文明可以通过分布式结构让这些知识在需要时被重新组织起来。

这里可以看出我们早期所谓``智能折叠''的一种现实形式。个体是一个局部智能系统；组织在更慢尺度上也有状态、记忆、协议和反馈；文明又在更慢尺度上维持语言、文化、科学、法律和技术基础设施。可以概念性写为：
\[
Agent
\subset
Organization
\subset
Civilization,
\]
同时：
\[
\tau_{Agent}
<
\tau_{Organization}
<
\tau_{Civilization}.
\]
但必须注意，这里说的是\textbf{功能尺度上的嵌套}，不是宣称组织或文明天然具有单一主观意识。我们研究的是同类闭环结构在不同尺度上的重复。

这种多尺度外化还解释了一个重要现象：随着文明成熟，越来越多过去需要个体显式认知的东西会变成背景基础设施。例如导航知识可以沉降进地图和 GPS，计算规则可以沉降进计算机，协调规则可以沉降进协议，安全要求可以沉降进工程标准。于是：
\[
ExplicitIndividualCognition
\downarrow
\]
并不必然意味着：
\[
CivilizationalCapability
\downarrow.
\]
相反，它可能意味着：
\[
\boxed{
HistoricalCognition
\rightarrow
StableExternalStructure.
}
\]

当然，这一过程存在一个反向风险：如果个体对外部结构形成过度依赖，却失去了索引、验证和恢复能力，那么：
\[
Externalization
\rightarrow
Fragility.
\]
当外部结构不可用时，能力可能迅速下降。因此成熟外化要求不仅考虑平均效率，也需要考虑韧性：
\[
J
=
Efficiency
+
\lambda_R Resilience.
\]
对于高风险结构，Agent 应保留必要冗余，或者维持多个外部载体，而不是把全部认知依赖集中在单一点。

于是我们得到一个完整原则：
\begin{proposition*}
认知外化的目标不是让内部越来越空，
而是使结构进入最适合其时间尺度、调用频率、风险与修改成本的承载层。
\end{proposition*}
从这个意义上，个体学习、工具形成、组织制度和文明积累并不是四类完全不同的现象，而是同一个认知结构迁移原则在不同尺度上的表现。

\section{从外部记忆到分布式认知拓扑}

完成环境、工具、社会与制度四个层次以后，我们现在可以正式修正``外部记忆''这一概念。如果仍然把它理解成一堆位于主体之外的存储对象，那么前面的理论会显得过于松散。真正统一这些现象的不是``它们都在外面''，而是：\textbf{这些外部结构都能够在主体不持续内部维持完整 CSO 的条件下，通过稳定关系承担未来认知和行动的一部分功能。}

因此定义 Agent 的广义认知承载图：
\[
\mathcal G_A^{carrier}
=
(
V_A^{int},
V_A^{ext},
E_A^{access}
),
\]
其中
\[
V_A^{int}
=
\{h,E,\Theta,\Psi,\ldots\}
\]
表示内部载体，
而
\[
V_A^{ext}
=
\{
Skill,
File,
Program,
Tool,
Environment,
Agent_j,
Institution
\}
\]
表示外部载体。$E_A^{access}$ 则描述 Agent 如何索引、调用、修改和验证这些载体。

于是一个 Agent 的实际认知边界并不等于它的物理边界：
\[
Boundary_{physical}
\neq
Boundary_{cognitive}.
\]
但同样不能简单说认知边界无限扩展到整个世界，因为只有建立稳定访问关系的外部结构才属于该 Agent 的功能认知系统。我们可以定义有效外部认知集合：
\[
M_A^{eff}
=
\left\{
C\in World
\mid
Access_A(C)\geq\theta_a,\;
Recover_A(C)\geq\theta_r,\;
FunctionalInfluence_A(C)\geq\theta_f
\right\}.
\]
这样既避免了``所有世界都是我的记忆''的无限泛化，也允许认知系统跨越皮肤、机箱和单一计算进程。

从最新的 CSO 理论看，这一章的全部内容可以统一成 Agent-CSO 承载映射的变化。对于同一个结构 $C$：
\[
\mu_A(C,t)
=
Carrier_t(C).
\]
它可能依次经历：
\[
h
\rightarrow
E
\rightarrow
\Theta
\rightarrow
Tool
\rightarrow
Environment
\rightarrow
SocialRole.
\]
因此真正变化的不是一种``复杂度物质''在空间中搬运，而是：
\[
\boxed{
\Delta
(
Representation,
Function,
Timescale,
Boundary,
Carrier
).
}
\]
这也是为什么本书保留``复杂度卸载''作为工程语言，却在本体层采用 CSO Migration 作为更基础解释。

我们还可以重新定义 AgentOS 的智能资源调度问题。传统 OS 调度计算资源：
\[
Process\rightarrow CPU,
\]
而 AgentOS 更深层的任务是：
\[
\boxed{
CSO\rightarrow Carrier.
}
\]
系统需要判断某一结构当前应当：

保持在 $h$；

写入 $E$；

抽象进 $\Theta$；

编译成 Skill；

保存为 File；

固化为 Program；

调用 Tool；

写入 Environment；

委派给 Other Agent；

还是依赖 Organization/Institution。

因此，可以构造一个概念性承载决策：
\[
k^*
=
\arg\min_k
J(C,k),
\]
其中
\[
J(C,k)
=
\alpha C_{runtime}
+
\beta C_{retrieval}
+
\gamma C_{modification}
+
\delta C_{latency}
+
\eta C_{risk}
-
\zeta C_{persistence}.
\]
约束则包括：
\[
Authority(C,k)=Allowed,
\]
\[
Reliability(C,k)\geq r_{min}.
\]
这将``认知卸载''从经验性的工具调用提升成一个统一的结构调度问题。

此外，分布式认知拓扑还需要考虑\textbf{结构所有权和现实权威}。如果一个 Agent 把某项知识委托给其他 Agent，那么对方是认知结构的承载者，却并不因此获得定义现实的权力；如果某个制度保存了一个规则，也不意味着该规则永远正确。因此必须始终区分：
\[
CarrierAuthority
\neq
RealityAuthority.
\]
外部结构可以承担记忆和控制，但最终仍然必须接受现实反馈校准：
\[
\boxed{
RealityIsUltimateConstraint.
}
\]

这同样适用于文明结构。制度、文化、数据库和 AI 模型可能长期保存某种结构，而环境已经发生改变。如果没有外部残差进入系统，慢结构会形成路径依赖和错误固化。因此分布式认知拓扑必须具有：
\[
Observe
\rightarrow
Residual
\rightarrow
Escalation
\rightarrow
Revision
\]
这一通道。换句话说，一个结构之所以成为记忆，并不意味着它拥有永久真理地位；记忆必须能够被现实重新解释。

最终，本章得到一种比``内存—外存''更一般的 Agent 结构：
\[
\boxed{
Agent
=
InternalDynamics
\bowtie
ExternalCarrierTopology.
}
\]
其中内部部分提供当前整合、自我、预测和治理，外部部分提供跨时间、跨空间和跨主体的结构承载。主体的连续性并不要求所有信息始终位于内部，而要求它能够维持：
\[
Identity
+
Index
+
Access
+
Verification
+
ControlBoundary.
\]
只要这些关系保持连续，Agent 就能够在大规模外部化的同时仍然保持一个明确的主体中心。

因此，本章最终要确立的不是``Agent 可以使用外部记忆''这样一个普通工程事实，而是一条更加基础的智能动力学原则：

\begin{proposition*}
成熟智能并不通过无限扩大内部认知容量来承载世界；
它通过不断调整认知结构的承载位置，
使快速、变化、全局相关的结构保留在内部显式闭环中，
而将稳定、重复、可局部闭合或可社会化的结构逐渐沉降到技能、工具、环境、其他主体和制度之中。
\end{proposition*}

因此，从个体到组织、从程序到文明，真正连续的不是某个具体载体，而是 CSO 与其功能关系。认知结构可以改变身体、改变介质、改变主体，甚至跨越多个生命周期继续存在。所谓外部记忆，最终应被理解成一种\textbf{跨边界认知结构承载拓扑}；而所谓认知卸载，则是在这个拓扑上重新安排未来认知成本、控制责任与现实验证路径的过程。
