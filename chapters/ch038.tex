\chapter{CCM：认知复杂度管理——有限工作记忆约束下的运行态结构治理}

\begin{chapteroverviewbox}
本章研究 AgentOS 中一个由工作记忆有限性必然推出的核心运行机制——认知复杂度管理器
（Cognitive Complexity Management，CCM）。在前文中，我们已经建立工作记忆 $h(t)$ 的有限容量约束，
并说明智能体能够同时保持全局可访问、相互关联且可用于当前推理的认知结构数量存在上限。
SPC 能够观测这一运行状态，AHC 能够提供内稳态与调制信息，TCE 则能够调节认知动力学的温度、
搜索范围、注意增益与收敛程度。然而，仅依靠 SPC--AHC--TCE 仍然不能回答一个更加基础的问题：
\textbf{当进入当前认知空间的结构本身已经超过可稳定处理范围时，系统究竟应该对这些结构做什么？}

CCM 正是对这一问题的回答。它不是新的推理主体，也不是第二套规划器，而是位于工作记忆有限容量约束之上的
\textbf{运行态认知结构治理机制}。它通过复杂度估计、结构分解、合并、去重、折叠、支线抑制、
暂停与恢复、表示重构以及局部卸载等操作，使当前进入 $h(t)$ 的 Agent-CSO 集合保持在一个可解释、
可控制并具有足够相干性的区域内。

需要特别说明的是，本章继续使用 ``复杂度'' 一词，是因为 CCM 面向的是工程意义上的运行负载与结构压力。
在本书已经建立的 CSO 本体论中，复杂度并不是一种独立流动的实体。真正被管理的是 Agent-CSO 及其关系、
耦合、激活范围、时间尺度和承载方式。因此，本章可以被更严格地理解为：
\[
\boxed{
\mathrm{CCM}
=
\text{有限工作记忆约束下的 Agent-CSO 运行态结构治理}
}
\]
复杂度只是描述这种结构状态是否超出当前认知承载能力的一组可测工程量。

本章的理论目标不是让 Agent ``永远保持简单''，而是建立一个更重要的原则：
\begin{statementbox}
复杂问题可以很复杂，但任一时刻进入显式全局处理面的结构必须保持有限。
\end{statementbox}
这一区分构成 AgentOS 处理长期复杂任务、持续认知与认知稳定性的关键基础。
\end{chapteroverviewbox}

\section{工作记忆有限性为何必然要求主动复杂度治理}

我们首先回到前文已经建立的工作记忆有限容量定理。设智能体在时刻 $t$ 的显式工作记忆状态为
\[
h(t)=\{c_1(t),c_2(t),\ldots,c_n(t)\},
\]
其中 $c_i(t)$ 并不简单表示一个 token、一句话或者一个孤立变量，而应理解为当前进入全局显式认知面的
Agent-CSO，或者由若干 Agent-CSO 构成的局部关系结构。真正占用认知容量的并不是元素数量本身，而是这些
元素之间需要同时维持的约束、依赖、因果、冲突、条件和目标关系。因此，对于一个具有 $n$ 个活跃节点的
认知结构，如果其有效关系集合为 $E_h(t)$，那么当前认知负荷更合理的描述并不是单纯的 $n$，而应写为
\[
C_{\mathrm{run}}(t)
=
\Phi
\left(
|V_h|,
|E_h|,
D_h,
U_h,
X_h,
T_h
\right),
\]
其中 $|V_h|$ 表示当前活跃 Agent-CSO 数量，$|E_h|$ 表示必须被同时维护的关系数量，$D_h$ 表示结构依赖深度，
$U_h$ 表示不确定性，$X_h$ 表示冲突程度，而 $T_h$ 表示当前认知线程之间的耦合强度。

因此，工作记忆有限并不意味着智能体最多只能记住固定数量的项目，而意味着存在一个与其表征效率、
认知模型能力以及当前状态相关的稳定工作区：
\[
\boxed{
C_{\mathrm{run}}(t)\leq C_{\max}(h,t).
}
\]
这里的 $C_{\max}$ 并不必然是严格常数。认知表示方式改变、当前 TCE 控制状态变化、结构被重新压缩以后，
有效容量都可能发生变化。但是无论其具体数值如何，只要系统运行于有限物理资源之上，
\[
C_{\max}<\infty
\]
都是不可回避的约束。

这一约束带来一个非常重要的推论。复杂问题本身的结构规模
\[
C_{\mathrm{problem}}
\]
完全可能远远大于
\[
C_{\max}.
\]
如果智能体解决问题的方式要求
\[
C_{\mathrm{problem}}\leq C_{\max},
\]
那么任何工作记忆有限的系统都不可能稳定解决超过自身瞬时容量的问题。现实智能显然并非如此。
人类能够完成需要数年建设的大型工程，计算机系统能够处理远大于 RAM 的数据集，一个成熟 Agent 也应能够处理
远超过单次认知窗口的任务。因此真正需要满足的条件不是
\[
C_{\mathrm{problem}}\leq C_{\max},
\]
而是
\[
\boxed{
C_{\mathrm{active}}(t)\leq C_{\max},
\qquad
\forall t.
}
\]

这意味着复杂问题必须通过时间展开、层次分解、结构压缩和选择性激活，使其在任何一个局部时刻只暴露当前真正
需要全局协调的一小部分结构。由此，我们可以把复杂任务处理的根本问题从 ``能否容纳全部问题'' 改写成：
\begin{statementbox}
如何控制任意时刻进入全局显式认知面的结构规模？
\end{statementbox}

CCM 因此不是为了提高某一个推理步骤的聪明程度而存在，而是为了保证整个认知系统不因为需要处理的结构不断增加而
失去相干性。SPC 可以告诉系统 ``当前已经过载''，TCE 可以降低认知温度、减少探索或者提高抑制增益，
但如果工作记忆中依然同时保留十条相互纠缠的任务支线，那么单纯降低温度并不能从根本上消除结构负荷。
CCM 必须实际改变当前认知结构本身：
\[
\mathcal{G}_{h}(t)
\longrightarrow
\mathcal{G}'_{h}(t),
\]
使
\[
C(\mathcal{G}'_{h})
<
C(\mathcal{G}_{h}),
\]
同时尽可能保持当前目标所需的信息充分性：
\[
I(\mathcal{G}'_{h};G_t)
\approx
I(\mathcal{G}_{h};G_t).
\]

因此，CCM 的第一原则可以正式表述为：

\begin{definition*}
最小充分认知原则：当前工作记忆只应保留完成当前闭环所需的最小充分结构。
\end{definition*}

这里的 ``最小'' 并不是追求信息数量绝对最少，而是在任务能力与运行稳定之间寻找一个动态可行区域。
如果删除过多结构，则系统无法正确决策；如果保留过多结构，则工作记忆的关系耦合、冲突和搜索空间会快速扩大。
CCM 的工作正是持续寻找这一中间区域。

从控制论角度看，我们可以把 $C_{\mathrm{run}}(t)$ 看成受控状态，把
\[
C_{\max}
\]
看成安全边界，而将 CCM 的结构操作记为控制输入 $u_C(t)$：
\[
\dot C_{\mathrm{run}}
=
F_C
\left(
C_{\mathrm{run}},
D_{\mathrm{task}},
u_C,
\xi
\right),
\]
其中 $D_{\mathrm{task}}$ 表示任务持续注入的新结构，$\xi$ 表示环境扰动。CCM 的目标不是强制
$C_{\mathrm{run}}$ 始终极低，而是维持
\[
C_{\mathrm{run}}(t)
<
C_{\mathrm{safe}}
<
C_{\max},
\]
并保留一定结构余量：
\[
M_C(t)
=
C_{\max}
-
C_{\mathrm{run}}(t).
\]
这个余量非常重要，因为一个完全占满工作记忆的系统即使当前仍然能够运行，也已经失去处理意外事件的能力。
因此，成熟智能不能长期生活在容量边界上，而必须主动保留面向未来扰动的认知裕度。

\section{输入复杂度探测：在结构进入工作记忆之前估计其认知成本}

如果 CCM 只在 $h(t)$ 已经过载以后才开始工作，它就只能充当事故处理器，而不能成为真正的认知治理机制。
因此 CCM 的第一类能力不是压缩，而是预测。任何新任务、事件、工具结果、记忆召回或内部目标在进入工作记忆之前，
都应该形成一个粗略的认知成本估计：
\[
\widehat{C}_{\mathrm{in}}
=
\mathcal{E}_{C}
\left(
x_{\mathrm{in}},
h_t,
G_t,
\Theta_t
\right).
\]

这里 $x_{\mathrm{in}}$ 表示待进入认知面的新结构，$G_t$ 表示当前目标，$\Theta_t$ 表示已有结构知识。
估计器 $\mathcal{E}_C$ 的任务不是精确预测未来所有推理步骤，而是回答：
\begin{statementbox}
如果让这个结构进入当前认知循环，它大约会占用多少关系空间，并产生多少新的耦合？
\end{statementbox}

我们可以把输入认知成本进一步分解为
\[
\widehat C_{\mathrm{in}}
=
\alpha C_V
+
\beta C_E
+
\gamma C_D
+
\delta C_U
+
\eta C_X
+
\zeta C_N,
\]
其中 $C_V$ 表示新增活跃结构数量，$C_E$ 表示新增关系数，$C_D$ 表示依赖深度，$C_U$ 表示不确定性，
$C_X$ 表示与当前结构之间的冲突，$C_N$ 则表示新颖性导致的结构解释成本。

例如，一个与当前任务高度相关但完全陌生的输入，即使文字长度很短，也可能具有很高的 $C_N$ 和 $C_E$；
相反，一大段已经高度熟悉、能够直接映射到现有 $\Theta$ 模式中的信息，其原始数据规模很大，
但有效认知成本可能很低。这说明：
\[
\boxed{
\text{数据量}\neq\text{认知复杂度}.
}
\]

更进一步地，输入复杂度必须是条件性的：
\[
C(x\mid h,G,\Theta)
\neq
C(x).
\]
同一个结构，对于不同 Agent、不同成长阶段以及不同当前上下文，其认知成本可能完全不同。
一个熟练程序员看到标准循环结构时，可以通过已有 $\Theta$ 将其压缩成一个整体 Agent-CSO；
一个没有相关结构记忆的 Agent 则必须展开其中许多细节。因此，认知成本本质上取决于：
\begin{statementbox}
新结构与已有结构之间是否存在可利用的结构映射。
\end{statementbox}

从工程实现角度看，输入复杂度估计不需要始终依赖大模型进行完整预推理。可以建立一个较轻量的估计器，
使用若干可直接测量的代理变量：
\[
z_C
=
[
N_{\mathrm{entity}},
N_{\mathrm{relation}},
N_{\mathrm{constraint}},
D_{\mathrm{dependency}},
H_{\mathrm{uncertainty}},
R_{\mathrm{novelty}},
R_{\mathrm{conflict}},
G_{\mathrm{relevance}}
].
\]
再通过
\[
\widehat C_{\mathrm{in}}
=
f_{\mathrm{probe}}(z_C)
\]
形成快速估计。

这里可以借鉴计算机操作系统中的 admission control 思想，但我们需要特别注意二者的差别。
传统 admission control 判断的是 CPU、内存、带宽是否足够，而 CCM 需要判断的是一个新认知结构是否会使
当前显式关系网络失去相干性。两个任务即使计算资源完全足够，也可能因为目标关系高度纠缠而导致
$h(t)$ 过载。

因此 CCM 不仅关心
\[
\mathrm{ComputeCost}(x),
\]
还必须关心
\[
\mathrm{CouplingCost}(x,h).
\]
可以定义：
\[
C_{\mathrm{couple}}(x,h)
=
\sum_{c_i\in h}
w_i
R(x,c_i),
\]
其中 $R$ 描述新增结构与已有活跃结构的有效耦合程度。若一个输入会同时改变当前五个假设、三个子目标和两个工具选择，
它的认知影响远高于一个可以独立处理的输入。

由此 CCM 可以形成一个简单的预测判据：
\[
C_{\mathrm{run}}(t)
+
\widehat C_{\mathrm{in}}
<
C_{\mathrm{safe}}
\quad
\Rightarrow
\quad
\mathrm{DirectAdmission}.
\]
如果
\[
C_{\mathrm{run}}(t)
+
\widehat C_{\mathrm{in}}
\geq
C_{\mathrm{safe}},
\]
则不意味着拒绝问题，而意味着需要在真正展开之前改变它的进入形式：
\[
x
\longrightarrow
\widetilde{x}.
\]

这种改变可能是摘要、分块、延迟、只激活索引、调用已有结构模板或者先建立局部子问题。
因此，复杂度探测真正实现的是：
\begin{statementbox}
先预测认知成本，再决定展开粒度。
\end{statementbox}

这也是 CCM 与普通 ``上下文截断'' 的根本区别。上下文截断是在资源不足以后机械删除信息；
CCM 则试图在认知结构进入系统以前预测其结构成本，从而决定最合适的表示方式。
成熟智能不是被动地承受复杂度，而应在复杂度真正成为内部负担之前主动改变其进入形式。


\section{$\Theta$ 预模拟：利用已有结构提前预测认知展开路径}

输入复杂度探测仍然存在一个困难：仅从输入的表面结构，我们只能估计静态复杂度，却无法知道它进入工作记忆以后会触发
多少进一步推理、记忆召回和目标分支。因此 CCM 还需要利用长期结构记忆 $\Theta$ 进行有限的预模拟。

设新输入为 $x$，当前状态为 $h_t$。传统方式是直接执行：
\[
h_{t+1}
=
F(h_t,x),
\]
然后观察系统是否过载。但成熟 CCM 应尽可能先构造一个低成本预测：
\[
\widetilde h_{t+1:t+k}
=
\widetilde F_{\Theta}
(h_t,x,G_t),
\]
其中 $\widetilde F_{\Theta}$ 不是完整认知执行，而是利用 $\Theta$ 中已有任务模式、因果模式、经验摘要和技能结构，
预测如果当前结构被完全激活，未来若干认知步可能出现什么。

这里的关键是区分：
\[
\boxed{
\text{认知模拟}
\neq
\text{认知执行}.
}
\]
完整执行可能需要大量工作记忆空间，而预模拟只需要估计宏观结构量，例如：
\[
\widehat N_{\mathrm{branch}},
\qquad
\widehat D_{\mathrm{reason}},
\qquad
\widehat N_{\mathrm{recall}},
\qquad
\widehat N_{\mathrm{tool}},
\qquad
\widehat C_{\mathrm{peak}}.
\]

特别重要的是峰值复杂度：
\[
\widehat C_{\mathrm{peak}}
=
\max_{\tau\in[t,t+k]}
\widehat C_{\mathrm{run}}(\tau).
\]
一个任务平均复杂度可能很低，但在某一步需要同时维护大量条件。如果 CCM 只看平均值，就会低估这种瞬时爆发。
因此预模拟的目标之一是发现：
\begin{statementbox}
未来是否存在认知峰值。
\end{statementbox}

例如，一个表面上只有一句话的问题可能要求比较五种方案，每种方案又涉及成本、安全、时间和长期影响。
如果直接展开，工作记忆可能形成近似：
\[
5\times4
\]
个相互比较结构。$\Theta$ 预模拟如果识别到这是 ``多方案多指标比较'' 模式，就可以提前建议将问题转化为矩阵、
表格或分阶段比较，而不是在 h 中同时展开所有交叉关系。

形式化地，我们可以定义预模拟产生一个结构风险向量：
\[
r_{\Theta}(x)
=
[
\widehat C_{\mathrm{peak}},
\widehat B,
\widehat D,
\widehat U,
\widehat X,
\widehat T
],
\]
其中 $\widehat B$ 表示预期分支数，$\widehat D$ 表示依赖深度，$\widehat U$ 表示未知量，
$\widehat X$ 表示潜在冲突，$\widehat T$ 表示预计完成时间或认知步数。

CCM 根据该风险向量决定结构策略：
\[
u_C
=
\pi_{\mathrm{CCM}}
\left(
r_{\Theta},
C_{\mathrm{run}},
M_C,
G_t
\right).
\]

需要强调的是，$\Theta$ 预模拟不能成为一个新的中央推理过程，否则会出现悖论：为了判断任务是否复杂，
系统先完整解决了一遍任务。因此我们要求预模拟满足：
\[
C(\widetilde F_{\Theta})
\ll
C(F),
\]
即预模拟本身的认知成本必须显著低于真正执行。

在工程上，这可以通过模式级预测实现。例如 $\Theta$ 不需要知道最终答案，只需要识别 ``这是递归搜索''、
``这是多约束计划''、``这是跨文件信息整合''、``这是高度不确定的开放研究''。这些结构标签本身已经能够显著提高
CCM 的复杂度预测能力。

这一机制使 $\Theta$ 在 AgentOS 中具有一个常被忽略的重要功能：它不仅负责知识和规律，也可以作为
\begin{proposition*}
认知成本预测模型
\end{proposition*}
参与运行时调度。

这也解释了为什么一个成熟 Agent 通常比初生 Agent 更善于 ``知道一个问题大概有多难''。随着长期经验增长，
$\Theta$ 中积累的不只是答案，还包括问题结构、失败模式、搜索深度、所需工具和典型计算路径。
因此：
\begin{statementbox}
经验不仅降低解决问题的成本，也提高预测问题成本的能力。
\end{statementbox}

从控制角度看，这相当于为 CCM 增加一个前馈控制项。单纯运行态监控属于 feedback control：
\[
Error
\to
Adjustment.
\]
而 $\Theta$ 预模拟提供：
\[
Prediction
\to
PreAdjustment.
\]
于是 CCM 从单纯的反馈复杂度控制器升级为：
\[
\boxed{
Feedforward+Feedback
}
\]
联合治理机制。这对于避免系统频繁进入临界或湍流状态具有重要意义。


\section{运行态复杂度估计：从静态容量约束到动态负载场}

即使输入已经经过预估，真正运行中的认知结构仍然会不断变化。新的记忆被召回，某些假设失败，
新的冲突产生，工具反馈可能引入意外结果。因此 CCM 必须持续估计
\[
C_{\mathrm{run}}(t),
\]
而不能把输入时的预测当成真实运行状态。

最简单的运行复杂度模型可以写成：
\[
C_{\mathrm{run}}(t)
=
\sum_{i=1}^{n}
a_i(t)c_i(t),
\]
其中 $a_i(t)$ 表示第 $i$ 个认知结构的当前激活权重，$c_i(t)$ 表示其局部认知成本。
但是这一表达忽略了关系复杂度。实际工作记忆中的困难往往来自两个结构同时存在以后产生的新耦合，
因此更加合理的二阶形式是：
\[
C_{\mathrm{run}}
=
\sum_i a_i c_i
+
\lambda
\sum_{i\neq j}
a_i a_j r_{ij},
\]
其中 $r_{ij}$ 表示两个活跃 Agent-CSO 之间需要被显式维持的关系强度。

当存在高阶约束时还可以扩展为：
\[
C_{\mathrm{run}}
=
C_V
+
C_E
+
C_H,
\]
其中：
\[
C_V=\sum_i a_i c_i,
\]
\[
C_E=\lambda_2\sum_{ij}a_i a_jr_{ij},
\]
\[
C_H=\lambda_3\sum_{ijk}a_i a_j a_k r_{ijk}.
\]
$C_H$ 用于描述必须同时理解三个以上结构之间关系的高阶依赖。

这说明，认知负载可能具有超线性增长：
\[
n\uparrow
\quad\not\Rightarrow\quad
C_{\mathrm{run}}\propto n.
\]
在高耦合情况下甚至可能近似：
\[
C_{\mathrm{run}}\sim O(n^2)
\]
或者更高。因此工作记忆管理的真正困难不是 ``项目太多''，而是：
\begin{statementbox}
同时活跃的关系网络过于稠密。
\end{statementbox}

除了结构规模，我们还必须考虑动态变化率：
\[
\dot C_{\mathrm{run}}(t)
=
\frac{dC_{\mathrm{run}}}{dt}.
\]
如果
\[
C_{\mathrm{run}}<C_{\max}
\]
但
\[
\dot C_{\mathrm{run}}\gg 0,
\]
系统虽然尚未过载，却正在快速接近临界区。成熟 CCM 应当对此提前响应。

因此可定义三个运行区间：
\[
\mathcal R_{\mathrm{safe}}
=
\{C<C_1\},
\]
\[
\mathcal R_{\mathrm{warning}}
=
\{C_1\le C<C_2\},
\]
\[
\mathcal R_{\mathrm{critical}}
=
\{C_2\le C<C_{\max}\}.
\]
其中：
\[
C_1<C_2<C_{\max}.
\]

如果再结合复杂度变化率，可以定义风险函数：
\[
R_C(t)
=
\alpha
\frac{C_{\mathrm{run}}}{C_{\max}}
+
\beta
\sigma(\dot C_{\mathrm{run}})
+
\gamma U_h
+
\delta X_h,
\]
其中 $\sigma$ 可以是只对正向增长敏感的非线性函数。

CCM 的目标由此不再只是：
\[
C_{\mathrm{run}}<C_{\max},
\]
而是：
\[
\boxed{
R_C(t)<R_{\mathrm{safe}}.
}
\]

我们还可以定义认知裕度：
\[
M_C
=
C_{\max}-C_{\mathrm{run}},
\]
和认知裕度变化：
\[
\dot M_C
=
-\dot C_{\mathrm{run}}.
\]
对于持续运行 Agent，$M_C$ 是非常重要的系统健康量。一个高性能但长期
\[
M_C\approx0
\]
的系统实际上处于脆弱状态，因为任何额外输入都会导致失稳。

CCM 与 SPC 在这里形成清楚的职责边界。SPC 负责更加广泛地估计：
\[
S_{\mathrm{self}}
=
[
C_{\mathrm{run}},
Phase,
Conflict,
Uncertainty,
Stability,\ldots
],
\]
而 CCM 专门针对其中的结构负载部分实施操作。因此可以写：
\[
\boxed{
SPC:\ WhatStateAmIIn?
}
\]
而：
\[
\boxed{
CCM:\ HowShouldTheActiveStructureBeReorganized?
}
\]

在理想实现中，SPC 与 CCM 共享部分观测变量，却不能合并成同一功能。否则系统会失去 observer 与 structure regulator
之间的模块化关系。

更进一步，运行复杂度估计应当记录其来源。我们可以写：
\[
C_{\mathrm{run}}
=
C_{\mathrm{goal}}
+
C_{\mathrm{world}}
+
C_{\mathrm{memory}}
+
C_{\mathrm{reason}}
+
C_{\mathrm{tool}}
+
C_{\mathrm{self}},
\]
分别表示目标、环境、记忆召回、推理、工具调用和自我监控产生的认知负载。
这种分解非常重要，因为降低不同来源的负载需要不同操作。若问题来自目标过多，应减少并发目标；
若来自记忆召回，应提高摘要层级；若来自推理支线，则应抑制分支；若来自自我监控，则可能需要降低 SPC 自反深度。

因此，运行态复杂度并不是一个单一数字，而应被理解成：
\[
\boxed{
\mathcal C(t)
=
[C_1(t),C_2(t),\ldots,C_m(t)]
}
\]
构成的动态负载场。CCM 真正治理的是这个多维状态，而总复杂度
\[
C_{\mathrm{run}}
\]
只是供上层控制和稳定性判断使用的聚合指标。


\section{HODog 式结构分解：从数量负载转向关系结构诊断}

在早期 CCM 讨论中，我们曾提出通过类似 HODog 的结构描述方法，不只统计工作记忆中存在多少内容，
而是识别当前认知图的高阶组织结构。本书在这里保留 ``HODog 式'' 这一历史术语，
但需要明确：它并不是引用某个成熟外部标准算法，而是指一种\textbf{层级化、有向化、对象--关系化的认知结构分解思想}。
其目的在于回答：
\begin{statementbox}
当前认知负荷究竟是由哪些结构形态造成的？
\end{statementbox}

设当前工作记忆可以表示为：
\[
\mathcal G_h
=
(V_h,E_h),
\]
其中节点 $V_h$ 为活跃 Agent-CSO，边 $E_h$ 表示当前必须显式维护的因果、约束、依赖、冲突和目标关系。
如果我们仅观察
\[
|V_h|,
\]
就无法区分链式问题与高度互连问题。例如两个认知图均有十个节点：

链式结构：
\[
v_1\rightarrow v_2\rightarrow\cdots\rightarrow v_{10},
\]
和近完全连接结构：
\[
v_i\leftrightarrow v_j,
\qquad
i\neq j.
\]
两者的节点数量相同，但显式协调负担显然完全不同。

因此 CCM 应提取一组结构指标，例如：
\[
\mathbf H_h
=
[
N_V,
N_E,
D,
B,
L,
K,
X,
R
],
\]
其中 $N_V$ 是节点数，$N_E$ 是边数，$D$ 是依赖深度，$B$ 是分支宽度，$L$ 是最长依赖链，
$K$ 是局部聚团程度，$X$ 是冲突边数量，$R$ 是重复结构比例。

在此基础上，我们可以进一步识别若干典型认知形态。

第一类是\textbf{长链型结构}。其特征是分支少但依赖深：
\[
B\approx1,
\qquad
D\gg1.
\]
这类问题的主要风险不是同时负载，而是前序结果长期占据工作记忆，导致错误累积。
CCM 应考虑中间结果压缩和阶段性固定。

第二类是\textbf{高分支型结构}：
\[
B\gg1.
\]
例如探索多个方案或者同时生成大量假设。此时主要风险是支线竞争与注意分散。
CCM 应采用支线抑制、排序或分页。

第三类是\textbf{高耦合型结构}：
\[
\frac{|E_h|}{|V_h|^2}
\gg0.
\]
每一个决策都影响大量其他变量。这类结构通常无法通过简单删除节点解决，
更需要改变表示形式，例如矩阵、约束系统或抽象变量。

第四类是\textbf{循环依赖型结构}。存在：
\[
v_i\leadsto v_j
\leadsto v_i.
\]
循环本身并不一定错误，但若系统在相同结构之间不断往返而没有状态收敛，就会形成认知空转。
因此需要区分功能闭环和无效循环。

第五类是\textbf{重复结构型}。多个节点实际上共享相同关系模式，只是在局部参数上不同。
如果系统把它们分别显式维护，复杂度会快速增长。CCM 应尝试提取共同模式：
\[
\{c_1,c_2,\ldots,c_n\}
\longrightarrow
(\mathrm{Template},\theta_1,\ldots,\theta_n).
\]

从这一角度看，所谓 HODog 式分析的核心并不是发明一个新的神秘复杂度指标，而是使 CCM 从：
\begin{statementbox}
``东西太多了''
\end{statementbox}
升级到：
\begin{statementbox}
``是哪种关系结构让系统变得难以维持？''
\end{statementbox}

我们可以将结构诊断表示为：
\[
z_h
=
\mathcal D_{\mathrm{struct}}(\mathcal G_h),
\]
并让 CCM 的控制策略依赖于：
\[
u_C
=
\pi_C(z_h).
\]
于是不同结构形态对应不同治理操作，而不再使用统一的 ``压缩''。

这一点非常重要，因为错误的复杂度治理可能本身造成信息损失。例如对长链型任务使用强支线删除并没有意义；
对高耦合问题使用简单分页又可能切断关键跨页关系。
因此：
\begin{statementbox}
CCM 必须先诊断结构，再选择治理算子。
\end{statementbox}

我们由此得到 CCM 的第二个基础原则：
\begin{proposition*}
复杂度管理不是减少信息量，而是改变导致当前认知负担的关系结构。
\end{proposition*}

这种思想与图论、网络科学、约束满足、层级分解等外部理论具有天然联系，但 CCM 的研究对象具有特殊性：
它关心的不是一个静态知识图的总体结构，而是当前被激活并必须由工作记忆同时维护的\textbf{动态认知子图}。
因此真正需要分析的是：
\[
\mathcal G_h(t),
\]
而不是完整的长期知识结构。


\section{分解：把不可同时维持的问题转换为可闭合的局部子问题}

分解是 CCM 最基础的结构操作之一，但 ``把大问题拆成小问题'' 这一日常表述远远不足以描述它。
一个有效分解必须满足至少三个条件：第一，子问题的运行复杂度下降；第二，子问题之间的接口足够简洁；
第三，局部求解以后能够重新构成原问题的有效解。

设原始问题的认知图为：
\[
\mathcal G
=
(V,E),
\]
CCM 希望构造：
\[
\mathcal G
\longrightarrow
\{\mathcal G_1,\ldots,\mathcal G_k\}
+
E_{\mathrm{interface}}.
\]
一个好的分解要求：
\[
C(\mathcal G_i)
<
C_{\max},
\qquad
\forall i,
\]
同时跨子图边数量尽可能小：
\[
|E_{\mathrm{interface}}|
\rightarrow
\min.
\]

这说明真正重要的不是 ``拆得越多越好''。如果一个问题被拆成一百个子问题，
但子问题之间仍然存在大量交叉依赖，那么总协调成本可能反而增加。
因此可以定义分解目标：
\[
J_{\mathrm{decomp}}
=
\sum_i
\phi(C_i)
+
\lambda
C_{\mathrm{interface}}
+
\mu
C_{\mathrm{recombine}},
\]
其中 $\phi(C_i)$ 对超过工作记忆安全区的子任务给予高惩罚，
$C_{\mathrm{interface}}$ 表示跨子任务关系成本，
$C_{\mathrm{recombine}}$ 则表示最终重新整合答案所需的认知成本。

理想分解满足：
\begin{statementbox}
局部内部强耦合，局部之间弱耦合。
\end{statementbox}
这与模块化系统的一般原则类似，但 CCM 中的模块并非永久软件模块，而是为了当前任务临时形成的认知闭包。

例如，如果一个任务包含：
\[
A\rightarrow B\rightarrow C\rightarrow D,
\]
那么可以按时间依赖分成多个阶段；
如果一个任务包含三个相互独立的方案：
\[
P_1,\ P_2,\ P_3,
\]
则可以按方案分解；
如果问题涉及成本、安全和性能三个相对独立的评价维度，
则可以按评价轴分解。

因此 CCM 需要多种分解基：
\[
\mathcal B_{\mathrm{decomp}}
=
\{
Temporal,
Functional,
Causal,
Goal,
Spatial,
Semantic,
Constraint
\}.
\]

成熟 CCM 不应机械固定一种分解方式，而应寻找使：
\[
\max_i C(\mathcal G_i)
\]
和
\[
C_{\mathrm{interface}}
\]
共同较低的划分。

分解以后，只有当前子问题：
\[
\mathcal G_j
\]
需要完整进入 h，其余子问题只保留：
\[
\mathrm{Index}
+
\mathrm{Status}
+
\mathrm{InterfaceConstraint}.
\]
于是原本可能需要：
\[
C(\mathcal G)>C_{\max}
\]
的问题被转化成：
\[
C(\mathcal G_j)<C_{\max}.
\]

这实际上是把空间上的同时复杂度转换成时间上的序列复杂度：
\[
\boxed{
SpatialComplexity
\longrightarrow
TemporalComplexity.
}
\]

这种转换构成持续智能能够解决远超瞬时容量问题的关键机制。一个有限工作记忆系统之所以能够处理大型工程，
不是因为它在某一时刻 ``装下了整个工程''，而是因为它能够保持宏观索引，然后在不同时间激活不同局部。

但分解也存在风险。最主要的是上下文丢失。如果每一个子问题完全独立运行，可能忽略全局约束。
因此我们需要一个最小全局状态：
\[
g_{\mathrm{global}}
=
[
Goal,
CriticalConstraints,
Progress,
Interfaces
].
\]
任一局部认知过程应满足：
\[
\mathcal G_i
\mid
g_{\mathrm{global}}.
\]
换句话说，分解不能删除整个问题的方向，只能删除暂时不需要显式展开的细节。

因此可以建立：
\begin{statementbox}
局部闭合--全局约束原则
\end{statementbox}
即：子任务应该尽可能局部闭合，但始终在一个稀疏全局约束面下运行。

这一原则后来会在更广泛的 AgentOS 多尺度体系中反复出现，但在 CCM 中，
我们第一次以纯工作记忆治理问题看到了它的必要性。


\section{合并：把分散的相关结构重新组织为更高阶认知单元}

如果说分解解决的是 ``一个结构过大''，那么合并解决的则是另一类问题：
工作记忆中存在大量彼此高度相关、却被系统当成独立对象维护的认知元素。
此时复杂度并不是因为问题真的包含如此多独立结构，而是因为当前表示层级过低。

设存在一组活跃 Agent-CSO：
\[
S
=
\{c_1,\ldots,c_m\},
\]
如果它们之间具有高度稳定的内部关系：
\[
R(c_i,c_j)
\approx
R^*_{ij},
\]
并且对当前目标而言可以通过一个高阶结构
\[
C^*
\]
描述其共同作用，那么 CCM 可以执行：
\[
\boxed{
\{c_1,\ldots,c_m\}
\longrightarrow
C^*.
}
\]

这种操作的本质不是删除细节，而是发生认知层级提升：
\[
LowLevelRelationSet
\longrightarrow
HigherOrderCSO.
\]

例如，一个初学者驾驶汽车时可能分别维护 ``方向盘角度''、``车身偏转''、``道路曲率''、``车道中心'' 等多个变量；
随着结构熟悉，这些变量可能被合并成一个 ``保持车道'' 的高阶控制对象。
在 AgentOS 中同样如此：如果多个变量长期形成稳定共变关系，就不需要始终在 h 中分别占据显式位置。

为了判断是否可以合并，可以定义内部耦合与外部耦合之比：
\[
Q(S)
=
\frac{
\sum_{i,j\in S}R_{ij}
}{
\sum_{i\in S,k\notin S}R_{ik}+\epsilon
}.
\]
当：
\[
Q(S)\gg1,
\]
说明该结构集合内部关系明显强于与其他当前结构的关系，它更适合作为一个整体单元处理。

但是合并必须满足信息充分性：
\[
I(C^*;G)
\ge
I_{\min}.
\]
如果高阶结构丢失了完成当前目标所需的信息，则不能仅为了降低认知复杂度而强行合并。

因此合并是一种有目标条件的结构压缩：
\[
\boxed{
C^*
=
\arg\min_{\widetilde C}
C(\widetilde C)
\quad
\mathrm{s.t.}
\quad
L_G(\widetilde C)\le\epsilon.
}
\]

这和统计学中的 sufficient statistic、信息瓶颈以及表示学习存在形式上的联系。
CCM 所追求的不是对世界建立最短描述，而是建立：
\begin{statementbox}
对当前目标充分、对工作记忆最省的表示。
\end{statementbox}

合并还具有一个重要的时间尺度意义。初次出现的结构通常需要在 h 中保持较多细节；
随着模式稳定，它们可以逐渐形成更高阶结构。这意味着 CCM 的即时合并操作与长期结构学习之间存在联系，
但两者不能混淆。CCM 的合并首先是运行时操作，它可以是临时的；长期结构是否真正固化，则需要更多经验支持。

例如：
\[
c_1+c_2+c_3
\overset{\mathrm{runtime}}{\longrightarrow}
C^*_{\mathrm{temporary}}.
\]
只有当这种合并在许多情境中重复成立时，才可能进一步成为长期稳定结构。

因此 CCM 应记录：
\[
N_{\mathrm{reuse}}(C^*),
\]
但不应自行决定所有长期结构固化。

合并同时也是形成抽象能力的微观来源之一。抽象并不是凭空 ``想得更高''，
而是系统发现一组低层关系在当前任务中可以被一个更稳定的高阶结构取代。
因此我们可以把运行时抽象写成：
\[
\boxed{
Abstraction_{\mathrm{runtime}}
=
StructuralMergeUnderGoalPreservation.
}
\]

这使 CCM 不再只是一个 ``清理内存'' 的组件，而成为有限认知系统中形成高阶操作单元的重要机制。


\section{去重：消除认知结构中的重复表达与等价状态}

工作记忆中的冗余并不总是表现为完全相同的文本。更常见的情况是，同一 CSO 或同一关系被不同路径、
不同语言、不同记忆来源重复激活。如果这些结构同时进入 h，系统会错误地把它们当成多个独立证据或多个不同问题，
导致认知容量被重复占用。

因此 CCM 的去重对象不是字符串，而是：
\[
\boxed{
Semantic/StructuralEquivalence.
}
\]

设：
\[
c_i,
c_j
\]
为两个活跃 Agent-CSO，如果存在映射：
\[
\phi(c_i)\approx\phi(c_j),
\]
并且对于当前目标 $G$：
\[
P(G\mid c_i,c_j)
\approx
P(G\mid c_i),
\]
那么二者在当前认知上下文中可能属于冗余结构。

可以定义近似等价关系：
\[
c_i
\sim_G
c_j
\]
表示两个结构在当前目标下具有足够相似的功能信息。

CCM 可以执行：
\[
c_i+c_j
\longrightarrow
(c^*,n=2,\mathrm{sources}),
\]
其中 $c^*$ 为统一结构，而来源和重复次数作为元数据保留。
这样既减少工作记忆占用，又避免把多个独立来源误认为只有一个来源。

这一点极为重要，因为：
\[
\boxed{
\text{表示去重}\neq\text{证据去重}.
}
\]
如果两个不同传感器独立报告相同事实，它们的语义内容可以合并，但证据独立性仍应保留。
否则系统可能错误丢失置信度信息。

因此 CCM 的去重结构可以写成：
\[
C^*
=
[
SemanticCore,
SourceSet,
ConfidenceStructure,
TemporalRange
].
\]

另一类重复来自推理过程本身。例如系统先得到：
\[
A\Rightarrow B,
\]
之后经过另一条路径再次推出 $B$。
如果工作记忆把两个 $B$ 同时保持为不同节点，就会增加无效结构。
CCM 应检测：
\[
Result(c_i)=Result(c_j)
\]
并将其合并到同一个结论节点，同时保留不同证明路径作为后台索引。

还存在循环性重复：
\[
A\to B\to C\to A.
\]
如果系统多次经过这一结构，却没有新的外部信息、状态变化或者置信度更新，那么这不是有效闭环，而是：
\begin{statementbox}
CognitiveLoopWithoutStateProgress.
\end{statementbox}
可以定义进展量：
\[
\Delta S_k
=
d(s_{k+1},s_k).
\]
若：
\[
\Delta S_k<\epsilon
\]
持续多个循环，则 CCM 可以判定当前认知进入重复空转。

去重因而不仅降低容量，也可以防止 ``思考次数'' 被误认为 ``获得了更多信息''。
这一问题在语言模型式 Agent 中尤其重要，因为同一结论可能被多种自然语言反复表达，
形成表面变化但结构不变的伪进展。

我们可以定义：
\[
R_{\mathrm{redundancy}}
=
1-
\frac{
|\mathcal C_{\mathrm{effective}}|
}{
|\mathcal C_{\mathrm{active}}|
}.
\]
当：
\[
R_{\mathrm{redundancy}}\uparrow,
\]
CCM 应增加语义归一化、结构合并和循环检测强度。

从更深层看，去重体现了一个重要认识：
\begin{statementbox}
智能容量应该由独立有效结构占用，而不是由表达次数占用。
\end{statementbox}

这使 AgentOS 能够在长期对话、反思和记忆召回过程中避免大量语义重复不断挤占显式认知面。
因此去重不仅是计算优化，也是保持长期主体认知清晰度的一项基础机制。


\section{折叠：用可恢复的高阶表示替代暂时不需要的低阶细节}

折叠（Fold）与合并相似，但二者并不相同。合并强调多个结构形成一个新的高阶语义单元；
折叠则强调暂时隐藏结构内部细节，只保留当前需要的接口，并保证未来必要时能够重新展开。

设一个认知子图：
\[
\mathcal G_s=(V_s,E_s)
\]
当前仍然与任务相关，但其内部细节已经暂时不需要显式参与推理。CCM 可以将其转换为：
\[
\boxed{
\mathcal G_s
\longrightarrow
F_s
=
[
Summary,
Interface,
State,
Pointer
].
}
\]

其中 Summary 是摘要，Interface 描述该子结构与当前认知图的关系，State 表示其求解状态，
Pointer 则提供未来恢复细节的索引。

折叠因此要求：
\begin{statementbox}
Recoverability.
\end{statementbox}
如果一个结构被 ``压缩'' 后无法恢复，而且未来可能需要其细节，那么这更接近不可逆遗忘，而不是 CCM Fold。

可以定义折叠操作：
\[
\mathcal F:
\mathcal G_s
\rightarrow
z_s,
\]
和展开操作：
\[
\mathcal F^{-1}:
z_s
\rightarrow
\widehat{\mathcal G}_s.
\]
理想情况下：
\[
d(
\widehat{\mathcal G}_s,
\mathcal G_s
)
<\epsilon_G
\]
对于未来可能需要的关键关系成立。

但实际系统不一定要求完整无损恢复。更合理的是任务条件下的可恢复性：
\[
I(
\widehat{\mathcal G}_s;
G_{\mathrm{future}}
)
\ge
I_{\min}.
\]

这使折叠成为一种介于 ``保持全部显式状态'' 和 ``完全删除'' 之间的中间状态。

一个典型例子是长时间任务中的已完成子任务。子任务内部可能经历了大量搜索、错误和中间状态，
但当前工作记忆只需要保持：
\[
[
Result,
Confidence,
Dependencies,
OpenIssues
].
\]
如果未来结果发生冲突，再通过 Pointer 恢复原始推理路径。

因此我们可以将工作记忆理解成具有多级可见性：
\[
Active
\supset
Folded
\supset
Indexed.
\]
而不是简单的：
\[
Present/Absent.
\]

这与软件 IDE 中折叠代码、操作系统虚拟内存、分层缓存等概念存在一定形式相似，
但认知折叠的对象是语义结构，而不是字节块。

CCM 决定折叠某结构时，需要考虑两个成本：
\[
J_{\mathrm{fold}}
=
C_{\mathrm{active}}
+
\lambda P_{\mathrm{reopen}}C_{\mathrm{unfold}},
\]
其中第一项是继续保持显式结构的成本，第二项是未来重新打开该结构的期望成本。
如果某结构很快又要被使用，则过早折叠可能造成频繁 Fold/Unfold 抖动。

因此需要迟滞：
\[
\theta_{\mathrm{fold}}
>
\theta_{\mathrm{unfold}}
\]
或者时间持续阈值，使系统不会因为瞬时注意变化而不断切换。

折叠进一步说明，有限工作记忆系统真正需要的不是不断 ``忘掉'' 东西，而是形成：
\begin{statementbox}
多层显式度结构。
\end{statementbox}
只有当前正在参与全局决策的结构保持完全展开；次重要结构保持摘要；远距离结构只保留索引。
这种分层恰恰使长期 Agent 可以维持极大知识和任务范围，而当前 h 仍然保持有限和清晰。


\section{支线抑制：控制搜索树宽度而不是禁止探索}

复杂认知最容易爆炸的情形之一，是开放问题同时产生大量可能方向：
\[
B_t
=
\{b_1,b_2,\ldots,b_n\}.
\]
如果系统将每个分支都保持在工作记忆中，那么认知复杂度通常随分支数快速增加：
\[
C_{\mathrm{branch}}
\propto
\sum_i C(b_i)
+
\sum_{i\neq j}R(b_i,b_j).
\]

因此 CCM 必须具有支线抑制机制。但 ``抑制'' 不能被理解成禁止探索。
真正目标是：
\begin{statementbox}
允许产生多个候选，但限制同时保持高激活的候选数量。
\end{statementbox}

设每个支线具有优先分数：
\[
s_i
=
\alpha V_i
+
\beta P_i
+
\gamma I_i
-
\delta C_i
-
\eta R_i,
\]
其中 $V_i$ 表示潜在价值，$P_i$ 表示成功概率，$I_i$ 表示信息增益，
$C_i$ 表示继续展开的认知成本，$R_i$ 表示风险。

CCM 不需要立即删除低分支，而可以调整激活权：
\[
a_i
=
\frac{
\exp(s_i/T_b)
}{
\sum_j\exp(s_j/T_b)
}.
\]
这里 $T_b$ 可以受到 TCE 的探索温度影响。
当 TCE 提高探索程度时，分支权重趋于平坦；当系统需要收敛时，CCM 则进一步集中激活。

因此 SPC、TCE 与 CCM 在支线管理中承担不同职责：
\[
SPC
\rightarrow
\text{观察当前分支数量和冲突};
\]
\[
TCE
\rightarrow
\text{决定整体探索--收敛状态};
\]
\[
CCM
\rightarrow
\text{实际改变哪些分支保持显式激活}.
\]

支线可以分成：
\[
Active,
Standby,
Archived,
Discarded.
\]
真正进入 h 的只有 Active 集合：
\[
B_{\mathrm{active}}
\subset B.
\]
且满足：
\[
C(B_{\mathrm{active}})
<
C_{\mathrm{safe}}.
\]

Standby 支线则保留最小状态：
\[
[
Hypothesis,
Reason,
LastState,
ResumeCondition
].
\]
这样如果当前主支线失败，可以快速恢复，而无需重新生成整个搜索空间。

这一设计避免了两种极端。第一种是：
\begin{statementbox}
过度发散
\end{statementbox}
即所有可能性同时存在，最终系统无法选择。第二种是：
\begin{statementbox}
过早收敛
\end{statementbox}
即第一个可行方案被立即锁定，导致系统失去更优可能。

CCM 因此必须维持一个：
\begin{statementbox}
ExplorationBandwidth
\end{statementbox}
即允许同时高激活的探索宽度。

可以定义：
\[
W_B
=
|B_{\mathrm{active}}|.
\]
根据当前认知裕度动态变化：
\[
W_B(t)
=
f(M_C,U,G,TCE).
\]
认知裕度高、环境不确定性高、任务价值高时，可以允许更多并行探索；
当系统接近工作记忆边界时，支线宽度应主动下降。

这意味着：
\begin{statementbox}
探索能力不是固定参数，而是认知容量条件下的动态资源。
\end{statementbox}

成熟 Agent 不是永远探索更多，而是能够知道 ``现在应该保留多少可能性''。
这一点使 CCM 从单纯的负载压缩器进一步成为认知搜索结构的治理者。


\section{暂停与恢复：把空间并发转换为时间多路复用}

当多个任务都具有价值，却无法同时维持时，最合理的方法通常不是删除其中一个，而是暂停。
暂停机制使有限工作记忆能够像有限 CPU 运行大量进程一样，通过时间复用服务多个长期认知线程。

设任务线程为：
\[
\mathcal T_i
=
[
G_i,
h_i,
Context_i,
Dependencies_i,
Progress_i
].
\]
如果所有线程同时进入全局工作记忆：
\[
h
=
\bigcup_i h_i,
\]
则很容易出现：
\[
C(h)>C_{\max}.
\]

CCM 因此需要将线程划分为：
\[
\mathcal T_{\mathrm{active}},
\qquad
\mathcal T_{\mathrm{suspended}}.
\]
对于被暂停的线程，不保留完整 $h_i$，而生成一个认知 checkpoint：
\[
\chi_i
=
[
Goal,
CurrentState,
KeyAssumptions,
OpenQuestions,
NextAction,
Pointers
].
\]

要求：
\[
C(\chi_i)
\ll
C(h_i).
\]
恢复时：
\[
\chi_i
+
E_i
+
\Theta
\longrightarrow
\widehat h_i.
\]

这里与传统计算机上下文切换存在重要区别。CPU 保存寄存器就可以准确恢复进程，
而认知状态具有语义性和生成性，因此无法保证逐比特恢复。
CCM 所追求的是：
\begin{statementbox}
FunctionalResume
\end{statementbox}
而不是：
\[
ExactStateRestore.
\]

也就是说，恢复以后只要 Agent 能够继续完成原目标、理解此前决定和开放问题，就已经满足认知连续性要求。

可以定义恢复损失：
\[
L_{\mathrm{resume}}
=
d_G(G_i,\widehat G_i)
+
\lambda d_S(S_i,\widehat S_i)
+
\mu d_C(C_i,\widehat C_i).
\]
CCM 需要设计 checkpoint，使：
\[
L_{\mathrm{resume}}
\]
足够低，同时 checkpoint 尽可能简洁。

暂停策略本身也是一个调度问题。一个任务是否应该暂停，可以根据：
\[
P_i
=
f(
Priority_i,
Deadline_i,
Progress_i,
Blocking_i,
C_i,
SwitchCost_i
).
\]

特别需要避免频繁切换。如果系统不断：
\[
T_1\rightarrow T_2\rightarrow T_1\rightarrow T_2,
\]
而每次都需要重新加载大量上下文，就会产生认知 thrashing。
定义切换成本：
\[
C_{\mathrm{switch}}
=
C_{\mathrm{fold}}
+
C_{\mathrm{reload}}
+
C_{\mathrm{reorientation}}.
\]
当：
\[
\sum C_{\mathrm{switch}}
\]
超过任务本身收益时，系统实际上已经进入失效的多任务状态。

因此 CCM 应建立最小执行时间或切换迟滞：
\[
T_{\mathrm{active}}
>
T_{\min},
\]
除非出现更高优先级事件。

暂停与恢复还解决了长期 Agent 的一个关键问题：一个主体可以有很多目标，
但不需要同时 ``想着'' 所有目标。真正维持身份连续的是目标和任务结构在长期系统中的持久存在，
而不是每个目标都持续占据 h。

因此：
\[
\boxed{
PersistentGoal
\neq
ContinuouslyActiveGoal.
}
\]

这一点极大扩展了有限工作记忆系统的长期能力。
Agent 可以同时拥有成百上千个潜在任务，而在任一时刻只激活极少数当前闭环。
从这一意义上说：
\begin{statementbox}
长期智能的规模来自时间复用，而不是无限扩大当前认知面。
\end{statementbox}


\section{表示重构：当问题太难时，首先改变问题的表达方式}

前述分解、合并、折叠等操作都在已有表示结构上工作。但有些问题之所以超出工作记忆容量，
并不是因为其本体结构必然如此复杂，而是因为当前表达方式制造了不必要的认知负担。
因此 CCM 必须具有更加高级的操作：
\begin{statementbox}
RepresentationReconstruction.
\end{statementbox}

设原始 Agent-CSO 表示为：
\[
R(C),
\]
系统可以寻找新的表示：
\[
R'(C)
=
\mathcal T_R(R(C)).
\]
要求语义目标保持：
\[
\mathrm{Sem}(R')
\approx
\mathrm{Sem}(R),
\]
同时认知成本下降：
\[
C(R')
<
C(R).
\]

例如，一组大量自然语言条件可能难以同时保持，但转成表格以后关系结构变得清晰；
一个空间问题可能通过坐标系转换大幅降低推理难度；
一个递归问题可以通过动态规划表达消除重复；
一个长期计划可以从事件列表重构为依赖图。

因此：
\begin{statementbox}
问题难度不仅取决于问题，还取决于表示。
\end{statementbox}

可以形式化为：
\[
C^*(C,G)
=
\min_{R\in\mathcal R(C)}
C(R\mid G),
\]
其中 $\mathcal R(C)$ 表示同一认知结构的可能表示集合。
智能的一项重要能力，就是搜索：
\[
R^*
=
\arg\min_R
C(R\mid G).
\]

这种表示优化与 CSO/Agent-CSO 区分直接相关。CSO 本体 $C$ 并没有改变，
改变的是：
\[
AgentCSO(C)
\]
中的 $R$ 分量：
\[
(C,R,F,\tau,B,S)
\longrightarrow
(C,R',F,\tau,B,S).
\]

因此本章可以看到，早期所谓 ``复杂度改变'' 实际上常常是：
\begin{statementbox}
同一 CSO 获得了更适合当前智能体的内部表示。
\end{statementbox}

表示重构可以分成不同层次。

第一类是语义重写，例如将自然语言条件转换成结构化约束。

第二类是坐标变换，例如把相对位置关系改写为绝对坐标，或者相反。

第三类是抽象层级改变，例如：
\[
\{c_1,c_2,c_3\}
\longrightarrow
C^*.
\]

第四类是计算形式改变，例如把搜索问题转换成优化问题。

第五类是时间表示改变，例如把 ``同时考虑全部步骤'' 转换成状态机或者阶段计划。

我们可以定义重构收益：
\[
B_R
=
C(R)-C(R')
-
C_{\mathrm{transform}}.
\]
只有：
\[
B_R>0
\]
时，重构才值得执行。

这一点说明 ``换一种思路'' 不是模糊的心理建议，而可以在 AgentOS 中成为一个明确的结构控制动作。
当 CCM 发现：
\[
C_{\mathrm{run}}\uparrow,
\qquad
Progress\approx0,
\]
且持续压缩和分解均无效时，可以尝试寻找新的表示空间。

更重要的是，表示重构能够突破单纯工作记忆容量的限制。
我们并不需要无限扩大：
\[
C_{\max},
\]
如果能够持续降低：
\[
C(R).
\]
因此，高级智能的重要标志可能不是 ``拥有无限大的工作记忆''，而是：
\begin{statementbox}
能够不断找到使有限工作记忆足以处理问题的新表示。
\end{statementbox}

这一判断把 CCM 从运行态资源管理推进到了真正的认知结构优化。


\section{微卸载：把暂时不需要全局处理的结构移出工作记忆}

即使经过分解、合并、去重、折叠和表示重构，某些结构仍然没有必要继续占据工作记忆。
此时 CCM 可以进行有限的微卸载：
\[
\boxed{
h
\longrightarrow
M_{\mathrm{aux}}.
}
\]

这里我们暂时不展开后续更加完整的认知卸载理论，只讨论 CCM 内部为了维持工作记忆稳定所执行的局部结构迁移。

设：
\[
c_i\in h.
\]
如果 $c_i$ 对当前决策的重要度下降：
\[
R_G(c_i)<\theta_R,
\]
但未来重新使用概率仍然较高：
\[
P_{\mathrm{reuse}}(c_i)>\theta_P,
\]
则删除并不合理，更适合将其转换成：
\[
[
Summary,
Pointer,
ReactivationCondition
].
\]

因此：
\[
c_i^{active}
\longrightarrow
c_i^{latent}.
\]

这种操作与 Fold 类似，但重点不同。Fold 通常针对一个复杂认知子图，将其内部细节隐藏；
微卸载则可以直接把整个当前结构从 h 中移出，只保留恢复入口。

设：
\[
A_t
\]
为当前活跃 CSO 集合，
\[
L_t
\]
为潜在结构集合，则：
\[
h(t)\approx A_t,
\]
而：
\[
A_t\cup L_t
\]
才更加接近当前任务完整认知状态。

微卸载的核心价值是释放：
\[
\Delta C
=
C_{\mathrm{before}}
-
C_{\mathrm{after}}.
\]

但卸载不是免费的。未来重新加载会产生：
\[
C_{\mathrm{reload}}.
\]
因此可以定义期望成本：
\[
J_{\mathrm{off}}
=
C_{\mathrm{keep}}
-
\left(
C_{\mathrm{offload}}
+
P_{\mathrm{reuse}}
C_{\mathrm{reload}}
\right).
\]
当：
\[
J_{\mathrm{off}}>0
\]
时才值得卸载。

更重要的是，CCM 不能卸载没有形成稳定恢复索引的结构。如果一个关键中间变量被移出以后无法重新定位，
就相当于信息丢失。因此微卸载必须满足：
\[
\boxed{
Indexability+Recoverability.
}
\]

对于长期任务，我们甚至可以维护：
\[
\mathcal I_{\mathrm{task}}
=
\{
pointer_i,
semantic_i,
priority_i,
resume_i
\},
\]
形成一个比完整工作记忆小得多的任务索引面。

这种结构再次证明：
\begin{statementbox}
当前认知状态不等于智能体拥有的全部认知状态。
\end{statementbox}
大多数结构应当处于低激活或者潜在状态，只有真正需要全局协调时才进入 h。

因此：
\[
MostAgentCSOs\notin h(t).
\]

从这一角度看，成熟智能的标志甚至不是工作记忆中 ``内容丰富''，而是：
\[
\boxed{
h(t)
\text{足够稀疏，却恰好包含当前决策所需结构。}
}
\]

CCM 的微卸载功能正是保证这种稀疏性的最后一道运行时机制。


\section{CCM 的统一控制模型：从结构操作集合到认知稳定闭环}

经过前面的讨论，我们现在可以把 CCM 从一组启发式操作正式提升为一个受约束控制问题。
设当前认知状态为：
\[
x_C(t)
=
[
C_{\mathrm{run}},
\dot C_{\mathrm{run}},
M_C,
B,
D,
U,
X,
R,
P
],
\]
分别描述当前负载、变化率、容量裕度、分支宽度、依赖深度、不确定性、冲突、冗余以及任务进展。

CCM 可选择的结构控制动作集合为：
\[
\mathcal U_C
=
\{
u_{\mathrm{decompose}},
u_{\mathrm{merge}},
u_{\mathrm{dedup}},
u_{\mathrm{fold}},
u_{\mathrm{suppress}},
u_{\mathrm{pause}},
u_{\mathrm{reconstruct}},
u_{\mathrm{microoffload}}
\}.
\]

于是：
\[
u_C(t)
=
\pi_C
\left(
x_C(t),
G_t,
S_{\mathrm{SPC}},
u_{\mathrm{TCE}}
\right).
\]

CCM 的目标函数不能只最小化复杂度，否则最简单的策略就是删除所有内容。
因此至少需要同时考虑任务损失、认知负载、结构切换成本和未来恢复成本：
\[
J_C
=
\int
\left[
\lambda_G L_G(t)
+
\lambda_C \phi(C_{\mathrm{run}})
+
\lambda_S C_{\mathrm{switch}}
+
\lambda_R C_{\mathrm{recovery}}
\right]
dt.
\]

其中：
\[
\phi(C)
\]
应当在接近容量边界时迅速增大，例如：
\[
\phi(C)
=
\frac{1}{
C_{\max}-C+\epsilon
}.
\]
这样系统不会把工作记忆长期维持在临界边缘。

约束条件至少包括：
\[
C_{\mathrm{run}}(t)
<
C_{\max},
\]
\[
L_G(t)
<
L_{\max},
\]
\[
I_{\mathrm{critical}}
\ge
I_{\min}.
\]

这里第三个约束非常关键：任何 CCM 操作都不能为了降低复杂度而删除当前安全、目标或关键现实判断所依赖的结构。

进一步地，CCM 应与 SPC 和 TCE 构成分工明确的闭环：
\[
\boxed{
SPC
\rightarrow
TCE
\rightarrow
CCM
\rightarrow
h
\rightarrow
SPC.
}
\]

其中 SPC 提供状态估计：
\[
\widehat x_C;
\]
TCE 提供宏观认知策略：
\[
u_T
=
[
Temperature,
Exploration,
Gain,
AttentionBreadth
];
\]
CCM 则负责实际改变：
\[
\mathcal G_h.
\]

因此可以写：
\[
\dot{\mathcal G}_h
=
F_h(
\mathcal G_h,
Input,
u_T,
u_C
).
\]

这里隐藏着一个非常重要的理论区别：
\[
\boxed{
TCE\text{主要改变认知动力学参数，CCM主要改变当前认知结构。}
}
\]

例如 TCE 可以降低探索温度，却不直接决定哪条支线被折叠；
CCM 可以暂停某支线，却不决定系统总体应该更探索还是更收敛。

这样的功能分离可以降低控制耦合。

我们还需要讨论 CCM 自身的稳定性。若 CCM 反应过强，可能出现：
\[
Structure
\rightarrow
Fold
\rightarrow
Unfold
\rightarrow
Fold
\rightarrow\cdots
\]
形成结构振荡。

因此 CCM 也需要迟滞：
\[
\theta_{\mathrm{on}}
>
\theta_{\mathrm{off}},
\]
并限制操作速率：
\[
\left\|
\frac{d u_C}{dt}
\right\|
<
\Gamma_C.
\]

复杂度治理应比瞬时 token 变化慢，却比长期记忆结构形成快：
\[
\tau_{\mathrm{token}}
<
\tau_{\mathrm{CCM}}
\ll
\tau_E,
\tau_\Theta.
\]

这使 CCM 成为真正意义上的运行态快速结构控制层。

在此基础上，我们可以提出本章的核心稳定性命题：

\begin{proposition*}
CCM 可运行性命题
\end{proposition*}

若对于任意有限时间内进入系统的任务结构，存在一组允许的 CCM 操作，使活跃认知图始终能够被转换为
\[
\mathcal G_h^*
\]
满足：
\[
C(\mathcal G_h^*)<C_{\max},
\]
并且：
\[
I(\mathcal G_h^*;G)
\ge I_{\min},
\]
同时恢复和切换成本有界，则该任务原则上可以在有限工作记忆系统中通过时间展开和结构治理持续处理，
而不要求工作记忆容量随完整任务规模同步增长。

这一命题并不证明所有复杂问题均可被有效解决，因为某些问题本身可能不存在低成本分解或充分压缩表示。
它说明的是另一个更基础的事实：
\begin{statementbox}
工作记忆有限并不必然意味着长期可解决问题的规模有限。
\end{statementbox}
限制的是：
\begin{statementbox}
同时显式处理的结构规模。
\end{statementbox}

这一区分构成 AgentOS 认知调度理论最关键的支点之一。


\section{CCM 的理论位置：从 ``有限容量'' 到 ``选择性显式认知''}

经过本章全部推导，我们现在可以重新理解工作记忆有限性的意义。有限工作记忆并不只是智能系统的缺陷。
恰恰因为全局显式认知是有限的，系统才必须发展出：
\[
\begin{gathered}
Decomposition,\ Abstraction,\ Compression,\\
Scheduling,\ SelectiveActivation,\ RepresentationChange.
\end{gathered}
\]
也就是说：
\begin{statementbox}
认知容量有限性本身，是高级认知组织结构产生的重要压力来源。
\end{statementbox}

如果一个系统拥有无限全局容量，它理论上可以把世界中的全部变量同时展开，而没有必要形成抽象、模块、
阶段计划和注意选择。但是现实智能始终处于有限资源条件下，因此必须不断把：
\[
LargeStructure
\]
转换成：
\[
SmallActiveStructure.
\]

CCM 正是这一转换在运行时层面的实现。

我们可以将一个成熟 Agent 的认知结构写成：
\[
\mathcal C_{\mathrm{agent}}
=
\mathcal C_{\mathrm{active}}
\cup
\mathcal C_{\mathrm{latent}}
\cup
\mathcal C_{\mathrm{external}},
\]
而工作记忆只对应其中：
\[
h(t)
\approx
\mathcal C_{\mathrm{active}}(t).
\]

因此：
\[
\boxed{
|\mathcal C_{\mathrm{active}}|
\ll
|\mathcal C_{\mathrm{agent}}|
}
\]
不仅是可能的，而且应当成为成熟智能的常态。

这导出一个非常重要的结论：
\[
\boxed{
MatureIntelligence
=
SelectiveExplicitCognition.
}
\]

成熟并不意味着任何事情都需要显式思考。恰恰相反，能力越成熟，越多结构可以以压缩、潜在、程序化、
结构化或外部形式存在，真正进入当前显式认知面的只剩下：
\begin{statementbox}
新颖的、冲突的、不确定的、跨模块的以及真正需要全局协调的结构。
\end{statementbox}

CCM 因此不能以 ``工作记忆内容越少越好'' 作为评价标准。真正需要优化的是：
\[
\boxed{
\frac{
\mathrm{TaskRelevantStructure}
}{
\mathrm{TotalActiveStructure}
}.
}
\]
可以定义认知有效率：
\[
\eta_C
=
\frac{
C_{\mathrm{relevant}}
}{
C_{\mathrm{run}}
}.
\]
成熟 CCM 应追求：
\[
\eta_C\uparrow
\]
而不仅是：
\[
C_{\mathrm{run}}\downarrow.
\]

如果复杂度很低，但系统忘记了关键目标，则 $\eta_C$ 可能并不高；
如果复杂度略高，但几乎所有活跃结构都直接参与当前决策，则系统仍然可能处于健康状态。

因此 CCM 最终面对的是一个比 ``内存清理'' 更深的问题：
\begin{statementbox}
什么值得在这一刻成为显式认知？
\end{statementbox}

这也解释了为什么 CCM 必须处于 SPC、TCE、工作记忆和长期结构之间的运行时交界位置。
它既不能独立决定价值，也不能取代推理，但它负责将有限认知资源转换成一个具有稳定结构的显式处理面。

最后，我们可以用一个完整关系概括本章：

\[
\boxed{
\begin{aligned}
&\text{有限工作记忆}
\\
&\Downarrow
\\
&\text{必须限制同时活跃的关系结构}
\\
&\Downarrow
\\
&\text{输入预测}
+
\text{运行监控}
+
\text{结构诊断}
\\
&\Downarrow
\\
&\text{分解、合并、去重、折叠、抑制、暂停、重构、微卸载}
\\
&\Downarrow
\\
&\mathcal G_h
\text{保持在可运行区域}
\\
&\Downarrow
\\
&\text{有限瞬时认知支持无限期持续任务}
\end{aligned}
}
\]

因此，本章最终给出 CCM 的正式定义：

\begin{definition*}
CCM 是 AgentOS 中面向有限工作记忆约束的运行态认知结构控制系统。
它通过持续估计活跃 Agent-CSO 及其关系网络所产生的认知负荷，
并在保持当前目标所需结构信息的前提下，对显式认知图实施分解、合并、
去重、折叠、支线抑制、暂停恢复、表示重构与局部卸载，
使任一时刻的全局认知结构保持在可稳定处理的有限区域内。
\end{definition*}

进一步用 CSO 本体语言表达：

\begin{statementbox}
CCM 并不管理一种名为 ``复杂度'' 的实体；
它管理的是哪些 Agent-CSO 在何种表示粒度、何种激活程度和何种关系结构下，
值得在当前时刻共同占据有限的显式认知面。
\end{statementbox}

这也是我们从早期 ``认知复杂度管理'' 走向成熟 AgentOS 理论以后，
对 CCM 最准确的定位。
