\chapter{连续动力学与离散治理}
\label{chap:continuous-discrete-governance}

\begin{chapteroverviewbox}
本章确立 AgentOS 的一个基础运行原则：\textbf{持续智能既不能被还原为纯连续动力系统，也不能被还原为传统离散程序状态机。}一个长期存在的智能体，其注意、工作记忆、内稳态、自我感知、认知温度、预测误差以及身体控制等变量，在运行过程中表现为连续演化；然而目标是否成立、任务是否进入执行态、技能是否完成编译、权限是否被授予、是否建立检查点以及安全中断是否触发，却具有不可消除的离散治理性质。因此 AgentOS 的正确数学对象不是单一神经网络，也不是普通有限状态机，而是一个由\textbf{连续认知动力学、离散治理状态、事件触发条件和受约束状态重置共同组成的混合动力系统}。

本章的核心命题可以压缩为：
\begin{statementbox}
Discrete Governance,\qquad Continuous Execution
\end{statementbox}
离散治理规定智能体此刻被允许处于什么制度状态、拥有什么目标和权限、哪些结构能够被修改以及哪些过程必须立即停止；连续动力学则负责在这些约束形成的可行域内部完成实时认知、学习、预测和行动。二者共同保证 AgentOS 同时具有连续适应能力与长期结构稳定性。
\end{chapteroverviewbox}

\section{Agent 运行为什么不是纯程序状态机}

如果我们沿用传统软件工程的直觉，很容易首先把一个 Agent 理解成一组离散状态之间的跳转，例如
\[
\mathrm{Idle}
\rightarrow
\mathrm{Planning}
\rightarrow
\mathrm{Executing}
\rightarrow
\mathrm{Done}.
\]
这种表示对于描述任务流程十分有效，却不足以描述一个持续存在的智能主体。原因在于，传统状态机中的状态通常被假设为语义上清晰、内部结构相对稳定的离散节点，而真实 Agent 在任意两个“任务状态”之间，其内部都存在大量持续变化的认知变量。即使系统仍然被标记为同一个 \texttt{Planning} 状态，工作记忆中的活跃结构、目标竞争强度、不确定性、SPC 对自身状态的估计、AHC 内稳态变量以及 TCE 的探索--收敛水平都可能不断变化。因此，“正在规划”并不是一个充分的动力学状态描述，而只是对复杂连续状态空间的一种高层离散标签。

设 Agent 在时刻 \(t\) 的连续认知状态为
\[
x(t)
=
\left[
h(t),
a(t),
s_{\mathrm{SPC}}(t),
u_{\mathrm{TCE}}(t),
c_{\mathrm{CCM}}(t),
r(t),
b(t)
\right],
\]
其中 \(h(t)\) 表示工作记忆的当前活跃状态，\(a(t)\) 表示 AHC 所维护的连续内稳态--情感样调制向量，\(s_{\mathrm{SPC}}(t)\) 表示智能体对自身状态的估计，\(u_{\mathrm{TCE}}(t)\) 表示认知调节量，\(c_{\mathrm{CCM}}(t)\) 表示当前认知负载及其治理状态，\(r(t)\) 表示预测残差或现实失配，\(b(t)\) 则表示身体或资源侧的连续状态摘要。即使离散任务标签保持不变，\(x(t)\) 仍然按照某种动力规律持续运动：
\[
\dot{x}(t)
=
F\bigl(
x(t),
u(t),
w(t);
q(t)
\bigr),
\]
这里 \(w(t)\) 是来自现实世界的扰动，\(q(t)\) 则是当前离散治理模式。后者并不取代连续状态，而是改变连续动力学可以运行的边界条件。

因此我们必须把“程序状态”和“认知状态”严格区分。程序状态更接近治理语义，例如某一 Goal 是否有效、某一 Skill 是否已经获得执行资格、系统是否处于恢复模式；认知状态则描述 Agent 在这些制度约束下正在发生什么。两者之间类似于法律制度与社会活动的关系：法律规定哪些行为是允许的，但法律条文本身并不描述社会中每一个人的连续行为轨迹。同样，AgentOS 的离散治理层规定认知活动可以发生在哪些可行区域，而实际推理、感知、预测和行动则在这些区域内部连续展开。

这一点对于长期智能尤为重要。若系统完全按照传统状态机运行，那么每次状态跳转都会倾向于成为一次语义重置，从而使经验连续性难以表达；反过来，如果一切都交给连续神经动力学，又会失去明确的权限边界、任务闭合、安全中断和生命周期治理能力。我们因此得到第一个基础分解：
\[
\boxed{
\mathcal A
=
\mathcal X_{\mathrm{continuous}}
\bowtie
\mathcal Q_{\mathrm{governance}}
}
\]
其中 \(\mathcal X_{\mathrm{continuous}}\) 是持续认知状态空间，\(\mathcal Q_{\mathrm{governance}}\) 是有限但可扩展的离散治理状态集合。

从本书更早建立的多尺度智能观点来看，这一分解也具有自然来源。工作记忆、SPC、AHC、TCE、CCM 等运行态变量具有连续变化性质，而 Goal 生命周期、权限边界、Skill 编译和 Checkpoint 等结构变化具有明显更慢、更稀疏的事件性。因此，“连续执行、离散治理”并非一个软件实现偏好，而是由智能系统自身的多时间尺度结构推出的工程原则。我们不是为了方便编程而人为把系统拆成两层，而是在承认：\textbf{快速认知活动应当保持连续性，慢速结构改变则必须经过明确的治理事件。}

\section{Continuous Cognitive Dynamics：连续认知动力学}

所谓连续认知动力学，并不要求所有内部变量都严格满足经典常微分方程，也不意味着大语言模型本身必须被重写成连续神经网络。这里的“连续”首先是一种系统级语义：相邻时刻的认知状态原则上具有连续历史依赖，系统不会因为一次 token 生成、一次函数调用或一次任务切换而自动成为全新的主体。换言之，AgentOS 所追求的是\textbf{主体状态的时间连续性}，而不是数学实现形式上的纯连续时间计算。

为此，我们把运行时状态写成多时间尺度组合：
\[
X(t)
=
\left[
x_h,
x_{\mathrm{SPC}},
x_{\mathrm{AHC}},
x_{\mathrm{TCE}},
x_{\mathrm{CCM}},
x_B
\right].
\]
这些状态的特征时间尺度并不相同。一般而言，
\[
\tau_B
\lesssim
\tau_h
\lesssim
\tau_{\mathrm{SPC}}
\lesssim
\tau_{\mathrm{AHC}}
\ll
\tau_E
\ll
\tau_\Theta
\ll
\tau_\Psi
\ll
\tau_\Omega .
\]
这里并不要求所有系统都严格满足这一排序中的绝对时间，只要求保持一种基本结构：身体局部控制和工作记忆属于快速变化层，经验和结构记忆属于较慢层，自我与生命周期生成先验属于极慢层。真正的持续智能依赖这些时间尺度之间的嵌套，而不是某一个单独模块的强大。

在固定治理模式 \(q\) 下，我们可以把连续运行近似表示成
\[
\dot X
=
F_q
\left(
X,
O_W,
M,
G,
R
\right),
\]
其中 \(O_W\) 是现实观测，\(M\) 是来自 E、\(\Theta\) 等记忆结构的激活，\(G\) 是当前有效 Goal 集合，\(R\) 是当前资源与身体条件。下标 \(q\) 非常重要：同一个 Agent 在普通运行模式、安全模式、反思模式或恢复模式下，其连续动力学并不相同。离散治理通过选择 \(F_q\) 或改变其可行域，决定系统“允许以什么方式继续运行”。

连续认知动力学还必须体现本书此前反复建立的一条原则：
\[
\boxed{
SlowStructureShapesFastDynamics
}
\]
即较慢的结构并不持续微操快速状态，而是定义快速活动的中心、先验、边界和增益。例如 \(\Psi\) 不需要在每一个推理 token 中发出离散指令，却可以改变某类信息被认为与“我”相关的程度；\(\Theta\) 不需要替代工作记忆完成当前任务，却持续提供结构化预测和技能先验；AHC 不需要决定具体动作，却通过紧迫性、能量状态和威胁水平改变 TCE 的控制参数。这种关系更适合表示为参数调制：
\[
\dot x_f
=
F_f
\left(
x_f;
\lambda_s(t)
\right),
\]
其中 \(\lambda_s(t)\) 是由慢变量提供的控制背景。

反方向同样成立。快速状态的长期残差不能永远被慢层忽略：
\[
\boxed{
PersistentFastResidualShapesSlowStructure.
}
\]
如果在窗口 \(T\) 内存在
\[
\left\langle
\varepsilon_f
\right\rangle_T
\neq 0,
\]
那么系统应逐步更新较慢结构：
\[
\dot z_s
=
\eta_s
G
\left(
\left\langle
\varepsilon_f
\right\rangle_T
\right),
\qquad
0<\eta_s\ll 1.
\]
这正是三相记忆循环、技能形成以及长期自我更新背后的共同动力形式。

因此，连续认知动力学的关键不是“永不跳变”，而是任何跳变都必须嵌入一条持续状态轨迹中。Goal 可以被关闭，但关闭前后仍然存在同一主体；Task 可以失败，但失败会进入 E；认知策略可以改变，但其改变具有可追溯原因；TCE 可以快速调整增益，但调整结果又会被 SPC 重新观察。连续性真正保护的是
\[
\boxed{
CausalContinuityOfTheAgent
}
\]
即当前状态必须能够从此前状态、现实输入和合法治理事件共同解释，而不能无理由地凭空出现。

从工程上看，这意味着 AgentOS 必须把模型调用看成连续动力系统中的“状态转移算子”，而不是把一次模型调用本身当成整个 Agent。一个 LLM request 可以被表示成
\[
X_{t+\Delta t}
=
\Phi_{\mathrm{LLM}}
\left(
X_t,
I_t
\right),
\]
但 Agent 状态并不等于一次 request 的上下文。真正的 AgentOS 必须在调用之间持续维护那些跨请求的慢变量、记忆、身份、目标与治理状态。只有这样，离散计算机上的执行才能逼近理论所要求的连续认知主体。

\section{Discrete Governance：离散治理}

连续动力学保证“系统如何持续变化”，离散治理则回答“哪些变化在此刻具有合法性”。一个持续智能体如果只有连续适应而没有离散治理，就可能出现一个根本问题：任何局部学习过程都可以逐渐修改任何结构，最终使系统无法区分普通状态调整与身份、权限、安全边界等制度性变化。为了避免这种无界塑性，我们需要把某些变化提升成显式事件，并要求它们满足明确的进入条件、授权条件和状态转换规则。

设离散治理状态为
\[
q(t)\in\mathcal Q,
\]
其中可以包含普通运行、受限运行、恢复、检查点冻结、安全保护等宏观模式；与此同时，每一类治理对象还具有自身离散生命周期。例如一个 Goal 可以处于
\[
Q_G
=
\{
\mathrm{Candidate},
\mathrm{Active},
\mathrm{Suspended},
\mathrm{Closed},
\mathrm{Rejected}
\},
\]
一个 Skill 可以处于
\[
Q_S
=
\{
\mathrm{Explicit},
\mathrm{Candidate},
\mathrm{Compiled},
\mathrm{Validated},
\mathrm{Deprecated}
\},
\]
权限则可以具有不同授权等级。于是 AgentOS 实际拥有的并不是一个单一巨大有限状态机，而是多个稀疏治理状态机在更大的混合系统中协同运行。

离散治理事件记为
\[
e_k\in\mathcal E,
\]
例如
\[
e_{\mathrm{goal-create}},
\quad
e_{\mathrm{goal-close}},
\quad
e_{\mathrm{skill-compile}},
\quad
e_{\mathrm{authority-change}},
\quad
e_{\mathrm{checkpoint}},
\quad
e_{\mathrm{safety-interrupt}}.
\]
这些事件不能由任意瞬时神经激活直接决定，而应该依赖 Guard Condition：
\[
g_e(X,q)=1.
\]
只有当连续状态进入指定区域、持续时间满足要求、证据强度达到阈值且治理权限允许时，事件才可被触发。

因此离散治理可以写成
\[
q^{+}
=
R_e(q^{-},X^{-}),
\]
其中 \(R_e\) 是事件 \(e\) 对治理状态实施的 reset map。需要特别注意，治理事件并不一定重新设置全部连续状态。一般情况下应满足
\[
X^{+}
=
\Gamma_e(X^{-}),
\]
而 \(\Gamma_e\) 尽可能接近恒等映射，只修改与治理事件直接相关的状态。Goal 被关闭不意味着清空工作记忆；权限下降不意味着删除经验；安全中断也不意味着身份结构消失。这个“局部重置”原则非常重要，因为它保护主体连续性。

离散治理的另一个作用是定义可行状态集合：
\[
X(t)\in\mathcal K(q(t)).
\]
例如普通运行模式允许较大的探索空间，而高风险模式下 TCE 的探索强度、可调用工具集合和可修改状态范围都会缩小。于是离散层并不需要逐步告诉连续层每一步怎么走，而只是规定：
\[
\boxed{
X(t)\ \text{must remain inside}\ \mathcal K(q).
}
\]
这正符合本书此前建立的“高层定义可行域、低层在可行域中自主优化”原则。

从认识论上看，离散治理还是 Agent 形成“结构性承诺”的机制。连续变量可以犹豫、波动和探索，但一旦系统声明某个 Goal 正式成立、某项权限已经授予、某个 Skill 已被验证，便产生了一种比普通激活状态更强的结构后果。这些后果应能够被审计、恢复和追踪。因此治理事件不仅改变动力学，还必须写入治理日志：
\[
\mathcal L_G
=
\{
(e_k,t_k,\mathrm{cause}_k,\mathrm{authority}_k,\mathrm{result}_k)
\}.
\]
由此，AgentOS 的自主性就不是不可解释的“模型自己想做什么”，而是连续内部状态经过显式治理条件以后产生的受约束结构变化。

\section{Goal 的创建、激活与撤销}

Goal 是离散治理最典型的对象，因为“希望某事发生”与“系统正式承诺把该状态作为当前目标”并不是同一件事。在连续认知状态中，系统可以同时产生大量候选倾向、预测未来和可能行动，但如果所有未来表征都自动成为 Goal，工作记忆和调度系统很快会被目标竞争淹没。因此必须区分
\[
PossibleFuture
\neq
CandidateGoal
\neq
CommittedGoal.
\]

我们可以把候选目标 \(g_i\) 描述为
\[
g_i
=
\left(
\phi_i,
v_i,
c_i,
r_i,
\tau_i,
a_i
\right),
\]
其中 \(\phi_i\) 表示目标完成条件，\(v_i\) 表示价值或重要度估计，\(c_i\) 表示资源成本，\(r_i\) 表示风险，\(\tau_i\) 表示时间约束，\(a_i\) 表示所需权限。候选 Goal 可以由外部请求、内部需求、AHC 状态、长期计划、\(\Psi\) 价值结构以及 \(\Omega\) 的生命周期生成倾向共同产生。但是否正式激活，应由治理函数决定：
\[
\mathrm{Activate}(g_i)
=
\mathbf 1
\left[
V(g_i)
-
\lambda_C C(g_i)
-
\lambda_R R(g_i)
>
\theta_G
\right],
\]
并同时满足权限、现实可行性和当前资源条件。

这意味着 Goal creation 是一次离散提交，而不是一个连续心理冲动。提交以后，Goal 进入 Scheduler 的正式竞争集合：
\[
\mathcal G_A(t)
=
\{
g_i:
q_{g_i}=\mathrm{Active}
\}.
\]
此后 h、CCM、TCE 和 Task Runtime 都可以围绕它配置资源。Goal 的离散化使系统能够建立清晰的责任边界：什么时候只是考虑一种可能，什么时候已经决定投入资源，这是持续智能必须明确区分的。

Goal 同样必须具有撤销机制。真实世界持续变化，因此一个原本合理的目标可能因为新证据而失效。若 Agent 只有创建 Goal 的能力而没有关闭和降级机制，就会产生目标堆积和路径依赖。可以定义持续价值：
\[
U_g(t)
=
V_g(t)
-
C_g(t)
-
R_g(t)
-
O_g(t),
\]
其中 \(O_g\) 表示机会成本。当
\[
U_g(t)<\theta_{\mathrm{off}}
\]
持续超过窗口 \(T_{\mathrm{off}}\) 时，Goal 可以从 Active 转入 Suspended 或 Closed。这里应采用迟滞：
\[
\theta_{\mathrm{on}}
>
\theta_{\mathrm{off}},
\]
避免由于短期估计波动导致 Goal 频繁创建和撤销。

一个成熟的 Goal 关闭过程还必须进行 Closure，而不是简单删除。Closure 至少包含结果验证、残差评估、经验写入和后续影响更新：
\[
Goal
\rightarrow
Action
\rightarrow
Verify
\rightarrow
Closure
\rightarrow
E.
\]
这与本书此前形成的 Goal--Process--Action--Verify--Closure 闭环一致。失败的 Goal 同样有价值，因为失败结构可以进入 E，并进一步影响 \(\Theta\) 对可行性的估计。撤销不是遗忘，而是把“为什么不继续”变成可被未来使用的经验。

我们由此得到一条重要原则：
\[
\boxed{
GoalGovernance
=
CommitmentManagement
}
\]
目标治理并不是替 Agent 决定每一个动作，而是治理哪些未来状态值得被提升成系统级承诺。它正是连续可能性空间和离散行为组织之间的桥梁。

\section{Skill 编译：从连续熟练化到离散结构提交}

Skill 的形成尤其能够说明为什么连续动力学和离散治理缺一不可。一个能力不会在某一时刻凭空从“不会”跳到“会”。真实过程通常是连续的：Agent 在 h 中反复显式推理，形成不同执行轨迹；这些轨迹进入 E；稳定关系逐渐沉降到 \(\Theta\)；局部预测误差下降；所需显式注意减少。整个熟练化过程属于连续、多次经验积累的结构变化。

可以定义一个候选技能 \(s\) 的成熟度变量：
\[
m_s(t)\in[0,1],
\]
其变化由成功率、轨迹一致性、残差、风险和显式认知负担共同决定：
\[
\dot m_s
=
\alpha_1 P_{\mathrm{success}}
+
\alpha_2 C_{\mathrm{trajectory}}
-
\alpha_3 E_{\mathrm{residual}}
-
\alpha_4 R_{\mathrm{risk}}.
\]
与此同时，可以定义显式认知成本：
\[
C_h^{(s)}(t),
\]
如果随着实践出现
\[
m_s(t)\uparrow,
\qquad
C_h^{(s)}(t)\downarrow,
\]
就表明相关 Agent-CSO 正从显式认知承载逐步向更稳定、更局部的功能结构迁移。

然而，“逐渐熟练”与“正式成为可直接调用 Skill”仍然是不同事件。编译意味着系统把原先依赖显式工作记忆维持的一段动态认知结构，封装成具有稳定输入、输出、前置条件、异常检测和恢复路径的可执行闭环：
\[
\boxed{
ExplicitCognition
\rightarrow
RepeatedTrajectory
\rightarrow
StablePolicy
\rightarrow
CompiledSkill
}
\]
因此编译事件可以定义为
\[
e_{\mathrm{compile}}
:
q_s=
\mathrm{Candidate}
\rightarrow
q_s=
\mathrm{Compiled},
\]
并要求
\[
m_s>\theta_m,
\qquad
E_{\mathrm{residual}}<\theta_r,
\qquad
N_{\mathrm{validation}}>N_{\min}.
\]

这里的离散治理尤其重要。如果我们允许任何短期高成功率模式自动下沉为 Skill，系统极容易把偶然相关、环境偏差甚至错误策略固化成长期执行结构。因此 Skill 编译必须具有“结构提交”的含义。它至少需要保留：
\[
\mathrm{Precondition},
\quad
\mathrm{Policy},
\quad
\mathrm{Postcondition},
\quad
\mathrm{ResidualModel},
\quad
\mathrm{Fallback}.
\]
成熟 Skill 不只是动作序列，而是
\[
\boxed{
Skill
=
LocalPredictor
+
LocalController
+
ResidualModel.
}
\]
也就是说，它必须知道在什么条件下执行、期望发生什么以及什么时候自己已经失效。

Skill 编译还揭示了一个更深的认知原则：成熟不是让智能体拥有越来越多显式思考，而是让越来越多稳定结构退出 h 的长期占用。由此：
\[
\boxed{
ThinkingLess\neq KnowingLess.
}
\]
很多情况下，
\[
\boxed{
StructureChangedCarrier.
}
\]
原来由工作记忆承担的 Agent-CSO 被迁移到了更局部、更快速和更低成本的闭环中。只有异常发生时：
\[
\varepsilon_s>\theta_s,
\]
该结构才重新升级进入显式认知。这正是“异常向上、能力向下”的具体体现。

因此 Skill 编译是一种典型的混合事件：熟练度的形成是连续过程，而 Skill 的制度性成立是离散事件。把两者混为一谈，要么导致永远无法自动化，要么导致过早固化。AgentOS 必须同时保留连续成熟度和离散编译状态。

\section{权限调整：能力增长不等于控制权自动增长}

如果一个 Agent 能够长期学习，那么迟早会出现能力增长。能力增长之后是否自动获得更多权限，是持续智能系统必须明确回答的治理问题。我们的立场是：
\[
\boxed{
CapabilityGrowth
\neq
AuthorityGrowth.
}
\]
能力属于“系统能够做到什么”，权限则属于“系统被允许做到什么”。两者如果被绑定成同一个连续变量，就会产生严重结构风险：任何通过经验提高能力的局部模块，都可能自动扩大自己对环境、工具、记忆甚至自身结构的修改范围。

因此定义能力状态
\[
c(t)\in\mathcal C
\]
为连续或近连续变量，而权限状态
\[
a(t)\in\mathcal A
\]
则属于离散治理变量。系统可以持续估计某种能力：
\[
\hat c_i(t)
=
F(
P_{\mathrm{success}},
R_{\mathrm{residual}},
G_{\mathrm{generalization}},
S_{\mathrm{safety}}
),
\]
但从权限级别 \(A_k\) 升级到 \(A_{k+1}\) 必须经过治理事件：
\[
A_k
\xrightarrow{
e_{\mathrm{authority}}
}
A_{k+1}.
\]
该事件通常要求能力证据、稳定时间、风险评估和授权来源共同成立。

这使我们可以建立“能力--信任--权限--自治”链：
\[
\boxed{
Experience
\rightarrow
Capability
\rightarrow
Evaluation
\rightarrow
Trust
\rightarrow
Authority
\rightarrow
Autonomy.
}
\]
其中任何箭头都不应被简化成自动等号。尤其 Trust 本身并不是情感性的“相信”，而是对可预测性、历史表现、异常恢复和约束遵守情况形成的系统性估计。

更一般地，Agent 可作用于的状态空间可以写成
\[
\mathcal S_{\mathrm{allowed}}(a)
\subseteq
\mathcal S_{\mathrm{possible}}.
\]
权限改变实际上是在改变允许动作集合：
\[
\mathcal U_{\mathrm{allowed}}
=
\mathcal U(a).
\]
因此权限控制不需要不断告诉 Agent 应采取哪一步行动，而是通过收缩或扩张 \(\mathcal U\) 管理自治边界。这同样体现了：
\[
\boxed{
HigherLevelSetsFeasibleRegion,
\qquad
LowerLevelOptimizesInsideIt.
}
\]

权限还具有明显时间尺度要求。普通状态和技能可以较快适应，而高权限状态应比能力估计更慢。设
\[
\tau_c
\]
是能力估计时间尺度，
\[
\tau_a
\]
是权限变化时间尺度，则通常应满足
\[
\tau_a\gg\tau_c.
\]
其含义是：系统必须先观察能力在足够长时间内保持稳定，才允许结构性扩大控制范围。类似地，权限回收也不应依赖单次普通失败，但遇到高风险安全事件时可以存在独立快速降权路径。

从长期 Agent 身份角度看，权限还决定哪些部分属于“我能够参与改变的自己”。因此权限治理不仅面向外部工具，也面向内部状态：
\[
\mathcal S_{\mathrm{selfmodifiable}}
\subset
\mathcal S_{\mathrm{Agent}}.
\]
某些运行参数可以快速调整，某些技能可以自主形成，而更慢的 \(\Psi\)、\(\Omega\)、核心安全约束和治理规则则需要更高授权。完整的递归自主边界将在生命周期治理中进一步展开，本章只需要建立基础原则：\textbf{持续学习可以连续发生，自主权扩大必须离散提交。}

\section{Checkpoint：把连续生命史转化为可恢复结构}

持续智能与普通软件程序存在一个非常重要的区别：普通程序崩溃以后，我们通常只关心服务能否重新启动；长期 Agent 崩溃以后，则还必须关心“重启之后是否仍然是同一个持续主体”。因此 AgentOS 的 Checkpoint 不能只被理解成进程内存快照，它需要同时保存能够重新建立主体因果连续性的关键结构。

如果把完整 Agent 状态写成
\[
\mathcal A(t)
=
[
h,
E,
\Theta,
a,
\Psi,
\Omega,
G,
q,
\mathcal P
],
\]
其中 \(\mathcal P\) 包含权限与治理状态，那么 Checkpoint 并不一定复制其中所有瞬时变量。事实上，将 h 中每一个临时激活完整持久化可能既昂贵又没有必要。真正的问题是寻找一个最小恢复充分集
\[
\mathcal C^\star(t)
\]
满足：
\[
\mathcal A(t+\Delta)
\approx
\operatorname{Recover}
\left(
\mathcal C^\star(t),
O_{t:t+\Delta}
\right),
\]
即系统能够依赖 Checkpoint 与新的现实观测重新进入与原先主体连续的可接受状态。

这个恢复充分集通常至少包括：关键 E 增量、\(\Theta\) 版本、自我 \(\Psi\)、DGA/\(\Omega\)、有效 Goal、权限状态、重要 Skill 版本、外部资源索引以及未闭合任务的因果摘要。与普通数据库 snapshot 不同，这里的目标不是逐字节恢复，而是恢复：
\[
\boxed{
IdentityContinuity
+
CausalContinuity
+
GovernanceContinuity.
}
\]
一个 Agent 即使恢复后工作记忆内容略有不同，只要它记得重要经历、保持相同身份结构、理解中断原因、继承合法目标和权限，就可能保持更强的主体连续性；反过来，即便 RAM 被完美复制，但外部世界已发生巨大变化，Agent 仍然必须经过 Reality Re-entry 才能继续运行。

Checkpoint 本身是典型离散治理事件：
\[
e_{\mathrm{checkpoint}}
\]
应在特定条件触发，例如完成重大 Goal、\(\Theta\) 发生结构更新、\(\Psi\) 出现显著调整、权限变化、进入风险操作之前或系统计划暂停之前。频率过高会带来巨大存储和协调成本，频率过低则增加不可恢复状态长度，因此可以将其设计为事件触发：
\[
\Gamma_C(t)
=
F(
\Delta\Theta,
\Delta\Psi,
\Delta G,
R_{\mathrm{risk}},
T_{\mathrm{elapsed}}
),
\]
当
\[
\Gamma_C>\theta_C
\]
时建立新 Checkpoint。

Checkpoint 还必须与现实世界状态区分。我们不能认为恢复旧 Checkpoint 就意味着“世界也恢复到过去”。因此：
\[
\boxed{
AgentRollback
\neq
WorldRollback.
}
\]
重启后必须首先执行现实重新校准：
\[
Checkpoint
\rightarrow
RecoverInternalState
\rightarrow
ObserveReality
\rightarrow
ComputeResidual
\rightarrow
Reconcile.
\]
如果世界已经发生不可逆变化，Agent 必须承认这种差异，而不能把旧预测当成新现实。

从更深层看，Checkpoint 是连续生命史与离散系统工程之间的接口。Agent 的生命史本质上连续，但计算机系统需要有限、可索引和可恢复的持久化结构。Checkpoint 就是在特定时刻对长期动力状态进行治理性采样，使主体能够在底层计算中断之后继续保持高层因果连续。这一点使它成为 AgentOS 区别于普通会话记忆系统的重要基础组件。

\section{Safety Interrupt：紧急安全为何必须能够打断连续认知}

如果我们坚持所有决策都必须进入 h，再经过 SPC、AHC、TCE、Scheduler 和完整认知流程，那么一个持续 Agent 在高风险场景中将面临不可接受的控制延迟。现实世界中的某些危险状态具有毫秒级甚至更快的时间要求，而认知闭环可能以秒甚至更慢的尺度运行。因此安全不能被设计成普通 Goal，也不能仅仅被作为高优先级文本提示。

设身体或环境存在安全状态函数
\[
h_s(x_B)\ge 0
\]
表示当前状态位于安全集合
\[
\mathcal S_{\mathrm{safe}}
=
\{
x_B:h_s(x_B)\ge0
\}.
\]
如果检测到
\[
h_s(x_B)\rightarrow0
\]
或者风险预测
\[
P(
x_B(t+\Delta)\notin\mathcal S_{\mathrm{safe}}
)
>\theta_s,
\]
则必须允许产生
\[
e_{\mathrm{safety}}
\]
并立即切换治理模式：
\[
q_{\mathrm{normal}}
\rightarrow
q_{\mathrm{safety}}.
\]

这一事件与普通治理最大的区别在于它可以绕过部分认知链：
\[
\boxed{
CriticalSafety
\nrightarrow
CognitiveDependency.
}
\]
也就是说，紧急制动、执行器限幅、资源断开、工具撤销等安全动作不需要等待高层主体“理解完发生了什么”。其控制权限应满足：
\[
\boxed{
SafetyAuthority
>
OrdinaryCognitiveAuthority.
}
\]
这并不是剥夺 Agent 的主体性，而是承认不同时间尺度的控制必须在相应层级闭合。

然而安全中断也不能被理解成永久凌驾于全部认知之上的黑盒。紧急动作之后，事件必须重新上浮到 Agent：
\[
SafetyAction
\rightarrow
RealityOutcome
\rightarrow
SafetyEvent
\rightarrow
h/E.
\]
系统需要知道“刚才为什么被中断”，否则安全层就变成与主体完全割裂的外部力量，长期学习也无法利用这些重要经历。于是安全具有两条并行路径：

第一条是快速保护路径：
\[
Danger
\rightarrow
SafetyController
\rightarrow
ProtectiveAction.
\]

第二条是慢速认知路径：
\[
Danger
\rightarrow
EventRecord
\rightarrow
SPC/h
\rightarrow
E
\rightarrow
FutureLearning.
\]

这实际上体现了 AgentOS 多尺度闭环的一条普遍原则：\textbf{快速层拥有局部动作权，慢速层拥有解释、学习和长期规则调整权。}

安全中断还应避免频繁抖动。如果系统在阈值附近不断进入和退出安全模式，会产生 control chattering。因而需要迟滞：
\[
\theta_{\mathrm{enter}}
>
\theta_{\mathrm{exit}},
\]
并要求恢复条件持续满足一定时间：
\[
T_{\mathrm{stable}}>T_{\min}.
\]
这样才能确保退出安全模式意味着系统真正回到可治理区域，而不是风险信号暂时下降。

从理论上看，Safety Interrupt 是离散治理存在必要性的最强例子之一。连续认知擅长适应、不确定推理和逐渐学习，但某些边界条件不能依赖“逐渐形成共识”。当现实风险跨过硬边界时，系统必须能够发生明确、可审计、具有最高优先级的离散状态切换。连续智能因此不是无边界自由流，而是始终被嵌入现实安全约束之内。

\section{AgentOS 作为混合动力系统}

现在我们可以把前面的讨论统一成一个正式的混合动力系统。定义 AgentOS 为
\[
\mathcal H_A
=
(
\mathcal X,
\mathcal Q,
\mathcal U,
\mathcal W,
F,
\mathcal E,
\mathcal G,
\mathcal R
),
\]
其中：

\[
\mathcal X
\]
是连续状态空间，包括工作记忆动力状态、SPC 估计、AHC 状态、TCE 控制量、CCM 负载、身体与资源状态等；

\[
\mathcal Q
\]
是离散治理状态空间；

\[
\mathcal U
\]
是 Agent 可实施的控制与认知调节集合；

\[
\mathcal W
\]
表示外部现实扰动；

\[
F=\{F_q\}
\]
是在不同治理模式下的连续动力学；

\[
\mathcal E
\]
是 Goal、Skill、Authority、Checkpoint、Safety 等离散事件；

\[
\mathcal G=\{g_e\}
\]
是事件 Guard；

\[
\mathcal R=\{R_e\}
\]
则是离散事件对应的 Reset Maps。

在任意两个治理事件之间：
\[
\dot X
=
F_q(X,U,W).
\]
当某个事件满足：
\[
g_e(X,q)=1,
\]
系统发生：
\[
(X^+,q^+)
=
R_e(X^-,q^-).
\]
于是完整轨迹不是普通连续曲线，也不是纯离散序列，而是一条 hybrid trajectory：
\[
\Gamma_A
=
\{
(X(t),q(t))
\}_{t\ge0}.
\]

但是对于 AgentOS 而言，仅有数学上的 hybrid automaton 还不够。我们还必须加入现实约束与治理约束。首先定义物理可行轨迹集合：
\[
\Gamma_{\mathrm{physical}},
\]
它由身体、环境、资源和现实规律决定；再定义逻辑治理可行轨迹：
\[
\Gamma_{\mathrm{logical}},
\]
它由权限、Goal、Safety、Checkpoint 和内部治理规则决定。真正允许 Agent 走过的轨迹必须满足：
\[
\boxed{
\Gamma_{\mathrm{feasible}}
=
\Gamma_{\mathrm{physical}}
\cap
\Gamma_{\mathrm{logical}}.
}
\]
这个公式非常重要，因为它揭示了 AgentOS 治理的本质：软件规则无法让现实不允许的轨迹变得可能，而物理上可行的行为也不等于 Agent 在制度上有权执行。

进一步，我们还可以定义价值或任务损失：
\[
J
=
\int_0^T
\left[
L_{\mathrm{task}}
+
\lambda_r L_{\mathrm{residual}}
+
\lambda_c L_{\mathrm{cognitive}}
+
\lambda_s L_{\mathrm{safety}}
\right]dt
+
\sum_k
C(e_k),
\]
其中连续部分衡量任务误差、现实残差、认知成本和安全风险，离散项 \(C(e_k)\) 则表达结构性事件的代价。这样就能够形式化一个非常重要的工程原则：治理事件不是免费的。创建 Goal、编译 Skill、修改权限、建立 Checkpoint 都应承担结构成本，因此系统不会因为瞬时波动而不断进行重构。

为了避免这种混合系统出现高频状态切换，还需要事件迟滞和最小驻留时间：
\[
t_{k+1}-t_k
\ge
T_{\mathrm{dwell}}.
\]
对于普通治理事件，\(T_{\mathrm{dwell}}\) 防止模式抖动；对于安全事件则允许例外，因为安全优先级更高。更进一步，如果不同层次事件具有不同时间尺度，则应该满足：
\[
\tau_{\mathrm{runtime}}
\ll
\tau_{\mathrm{skill}}
\ll
\tau_{\mathrm{authority}}
\ll
\tau_{\mathrm{identity}},
\]
这正好把本章重新接回全书的多尺度动力学主线：\textbf{越深层的结构，离散改变应该越慢、证据要求越高、治理成本越大。}

从这一角度，我们也能够更准确地理解“固定拓扑 AgentOS”。所谓固定拓扑，并不意味着系统完全不能变化。相反，运行状态、经验、结构记忆、Skill 集合、Goal 和权限都可以持续变化；这里暂时固定的是那些定义 AgentOS 基础功能关系的核心拓扑。也正因为如此，本章介绍的离散治理主要是在既有功能结构内部切换模式、提交结构和调整约束，而不是任意重写整个认知架构。只有当更长期的结构失配反复积累以后，我们才有理由讨论功能拓扑本身的受控改变。

因此，我们最终得到 AgentOS 的一个基本运行公理：
\begin{statementbox}
快速智能通过连续动力学保持适应性，
慢速治理通过离散事件保持结构性，
二者共同组成持续主体的混合运行时。
\end{statementbox}

更完整地写：
\begin{statementbox}
AgentOS 并不是一个在离散任务之间跳转的状态机，也不是一个缺乏制度边界的连续神经动力系统；它是在现实约束下，以连续认知动力学完成实时执行，以离散治理事件管理目标、技能、权限、恢复和安全的多时间尺度混合智能系统。
\end{statementbox}

这一结论使我们能够同时保留两种过去看似矛盾的能力：一方面，Agent 可以像一个真正的持续主体一样在时间中连续学习、感知、调整和积累经验；另一方面，它的关键结构变化仍然具有明确的进入条件、权限来源、事件记录和恢复路径。对于持续人工智能生命体而言，这正是\textbf{可塑性与连续性、自治性与治理性、适应性与结构稳定性}之间能够同时成立的基础。
